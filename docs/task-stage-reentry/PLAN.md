# 阶段重新进入实施计划

## 1. 实施模式

- 模式：STRICT。
- 风险级别：高。
- 目标：统一修复设计、制作、安装三个阶段的明细重入逻辑。
- 现阶段：代码实施已完成，本地验证已通过，待提交并部署。

## 2. 实施约束

- 后端状态机和明细关联是唯一事实来源，前端不自行推断下一阶段。
- 任何自动进入只针对触发完成事件的订单明细，不按整张任务卡重置。
- `rolled_back` 是可重开的阶段退出记录；`cancelled` 是历史取消，不自动复活。
- 不使用整卡 `reset_existing` 重置阶段重入，必须增加逐项重置边界。
- 不增加新的业务权限码；继续使用对应阶段的状态变更权限和现有任务可见范围。
- 生产环境不执行未经干跑和授权的数据迁移。
- 每个计划项对应一个主验收项，见 `ACCEPTANCE.md`。

## 3. 计划项

### SR-P01：冻结三阶段状态和关联分类

工作内容：

- 固化设计、制作、安装的执行中、完成、`rolled_back`、`cancelled` 状态集合。
- 明确定义“有效关联”“可重开关联”“历史取消关联”。
- 确认设计→制作、制作→安装、安装退回→制作→安装的状态矩阵。
- 明确任务卡整体状态不得替代明细关联状态。

输出：状态分类常量、状态矩阵、兼容边界。

### SR-P02：实现统一的有效明细关联查询

工作内容：

- 扩展关联查询能力，支持按 `item_status` 排除 `rolled_back` 和 `cancelled`。
- 默认查询保持现有历史兼容，只有阶段自动进入明确使用“有效关联”模式。
- 保留任务卡中的历史关联，避免通过删除关联掩盖历史。
- 增加唯一性和并发查询约束说明。

输出：统一有效关联查询函数及单元测试。

### SR-P03：实现逐项阶段重入服务

工作内容：

- 建立统一的“完成当前明细后进入下一阶段”服务。
- 先查有效关联，再查 `rolled_back` 可重开关联，最后复用开放卡或创建新卡。
- 增加 `reopen_item_ids` 或等价的逐项重置参数。
- 只重置当前明细的状态、进度、完成时间和执行人。
- 对 `cancelled` 关联不自动复活。
- 保证事务失败整体回滚，重复请求不产生重复卡或重复关联。

输出：统一阶段进入服务、幂等策略和事务测试。

### SR-P04：修复设计→制作

工作内容：

- 设计明细完成时调用统一阶段进入服务。
- 制作卡内同一明细为 `rolled_back` 时恢复为 `pending`。
- 制作卡内已有有效关联时直接幂等返回。
- 制作卡内只有 `cancelled` 历史关联时不自动复活。
- 保持同卡其他明细和设计任务进度不变。

输出：设计到制作的服务接入和回归测试。

### SR-P05：修复制作→安装

工作内容：

- 制作明细完成时调用统一阶段进入服务。
- 安装卡内同一明细为 `rolled_back` 时恢复为 `pending`。
- 已有有效安装关联时不重复创建。
- 安装任务进度和订单阶段只按有效明细重新计算。
- 保持外协进行中时不能绕过完成阻塞。

输出：制作到安装的服务接入和回归测试。

### SR-P06：校准安装退回制作后的闭环

工作内容：

- 安装退回制作时只把选中的安装明细标记为 `rolled_back`。
- 制作目标明细只恢复为 `pending`，不重置制作卡其他明细。
- 制作再次完成后，安装侧 `rolled_back` 关联能够重新打开。
- 设计退回制作、制作退回设计的行为与上述规则保持一致。
- 验证同一订单多明细跨不同阶段时不会互相覆盖。

输出：回退→重入闭环测试矩阵。

### SR-P07：修复任务汇总、看板和订单阶段计算

工作内容：

- 任务进度分子、分母排除历史退出关联。
- 只有 `rolled_back`/`cancelled` 的任务卡不显示为可执行未完成任务。
- 目标卡重入一条明细时只影响目标卡的当前汇总。
- 订单阶段按照每条有效订单明细的最高阶段计算。
- 防止历史 100% 进度导致任务卡或订单误完成。

输出：汇总计算回归测试和看板数据契约。

### SR-P08：历史异常数据盘点与可选定向修复

工作内容：

- 先只读盘点“来源阶段已完成、目标阶段为 `rolled_back`”的记录。
- 生成干跑清单，显示订单、明细、来源任务、目标任务和前后拟变更状态。
- 生产修复前备份数据库和上传目录元数据，确认恢复方式。
- 仅在管理员明确授权后逐条或小批量修复，不处理普通历史 `cancelled`。
- 修复操作写入审计日志，可重复执行而不重复建卡。

输出：盘点报告、干跑证据、定向修复方案和回滚/恢复步骤。

### SR-P09：权限、接口和页面契约校准

工作内容：

- 设计、制作、安装仍只能操作本岗位流程。
- 自动重入由后端完成，不增加前端绕过入口。
- 历史取消恢复按钮与普通阶段重入区分展示。
- `rolled_back` 明确显示“已退回设计/已退回制作”；重入后显示待处理。
- 操作失败使用大白话提示，不能显示状态码或英文异常。

输出：接口契约、前端动作契约和页面检查清单。

### SR-P10：完整验证、提交和部署

工作内容：

- 后端状态机、权限、事务、幂等和数据汇总测试。
- 前端动作、单项 ID、按钮文案和进度显示测试。
- 执行类型检查、lint、构建、差异检查和安全检查。
- 发布前检查分支、提交、服务器工作区和备份状态。
- 部署后验证健康接口、设计→制作、制作→安装、安装回退闭环和关键页面。
- 异常时优先回退代码版本，不用危险 SQL 反向修复业务数据。

输出：测试报告、Git 提交、部署证据和剩余风险。
