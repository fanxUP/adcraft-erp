# 阶段重新进入验收标准

每个验收项对应 `PLAN.md` 中一个主计划项，验收以实际测试结果和部署后证据为准。

## A-SR-01：三阶段状态和关联分类

对应：SR-P01

- [ ] 设计、制作、安装的执行中、完成、`rolled_back`、`cancelled` 状态集合有统一定义。
- [ ] 能明确区分当前有效关联、系统回退可重开关联和历史取消关联。
- [ ] 设计→制作、制作→安装、安装退回→制作→安装的状态矩阵已固化。
- [ ] 任务卡整体状态不再被用来替代订单明细关联状态。

## A-SR-02：有效明细关联查询

对应：SR-P02

- [ ] 阶段自动进入查询时，`rolled_back` 关联不再被判定为当前有效关联。
- [ ] 阶段自动进入查询时，历史 `cancelled` 关联不被普通推进自动复活。
- [ ] 历史关联仍然保留，查询和页面可以解释其历史状态。
- [ ] 同一任务、同一订单明细不会产生重复有效关联。

## A-SR-03：逐项重入服务

对应：SR-P03

- [ ] 重入只处理触发本次完成事件的明细 ID。
- [ ] `rolled_back` 目标关联重入后为 `pending`、进度为 0、完成时间为空、执行人为空。
- [ ] 同一任务卡中其他明细的状态、进度、执行人和附件关联不变。
- [ ] 重复请求不会重复创建任务卡、关联或重复执行整卡重置。
- [ ] 服务中途失败时，来源状态和目标状态不会留下半成功结果。

## A-SR-04：设计→制作

对应：SR-P04

- [ ] 设计明细完成后，明细进入制作任务并显示为待制作。
- [ ] 制作侧已有 `rolled_back` 关联时，系统重开原关联，不新增重复任务卡。
- [ ] 制作侧已有有效关联时，重复完成设计不会重复关联。
- [ ] 制作侧只有历史 `cancelled` 关联时，普通设计完成不会自动复活该历史记录。
- [ ] 设计和制作任务中的其他明细保持原有状态。

## A-SR-05：制作→安装

对应：SR-P05

- [ ] 制作明细完成后，明细进入安装任务并显示为待安装/待分配。
- [ ] 安装侧已有 `rolled_back` 关联时，系统重开原关联，不新增重复任务卡。
- [ ] 安装侧已有有效关联时，重复完成制作不会重复关联。
- [ ] 有进行中的外协任务时，制作完成仍被阻塞，不能通过重入绕过。
- [ ] 制作和安装任务中的其他明细保持原有状态。

## A-SR-06：回退与再次重入闭环

对应：SR-P06

- [ ] 安装明细退回制作后，只有当前明细在安装侧变为 `rolled_back`。
- [ ] 该明细在制作侧恢复为待制作，制作卡其他明细不被重置。
- [ ] 该明细再次完成制作后，安装侧能够重新恢复为待处理。
- [ ] 制作退回设计后，设计再次完成能够重新进入制作。
- [ ] 同一订单多个明细分处设计、制作、安装时，任一明细回退或重入不覆盖其他明细。

## A-SR-07：任务、看板和订单汇总

对应：SR-P07

- [ ] `rolled_back` 和 `cancelled` 不计入当前阶段完成数量。
- [ ] 历史 100% 进度不会单独把任务卡推到 100%。
- [ ] 任务卡只剩历史退出明细时，不显示为可执行未完成任务。
- [ ] 重入一条明细后，目标卡按全部有效明细重新计算进度。
- [ ] 订单阶段按每条有效订单明细的实际阶段计算，不因任务卡整体状态误推进或误完成。

## A-SR-08：历史异常数据门禁

对应：SR-P08

- [ ] 发布前能生成只读盘点，列出来源已完成、目标为 `rolled_back` 的异常记录。
- [ ] 干跑结果包含订单、明细、来源任务、目标任务和拟变更字段。
- [ ] 生产定向修复前已完成数据库/上传目录元数据备份，并验证备份可恢复或有明确恢复路径。
- [ ] 未经管理员授权不执行生产数据修复。
- [ ] 修复只处理明确范围，不批量恢复历史 `cancelled`，并写入审计记录。

## A-SR-09：权限、接口和页面契约

对应：SR-P09

- [ ] 设计、制作、安装人员仍只能变更自己岗位的流程。
- [ ] 无对应权限的账号不能通过接口执行阶段重入。
- [ ] `rolled_back` 显示为“已退回设计/已退回制作”，重入后显示待处理。
- [ ] 历史取消恢复与普通阶段重入动作在页面上有清晰区别。
- [ ] 错误提示使用业务人员能理解的中文，不显示英文异常或内部状态码。

## A-SR-10：验证与发布

对应：SR-P10

- [ ] 后端测试覆盖三阶段正向进入、回退重入、混合进度、权限、外协和幂等。
- [ ] 前端测试覆盖单项明细 ID、动作显示、提示文案和状态刷新。
- [ ] 类型检查、lint、生产构建和差异检查全部通过。
- [ ] GitHub 目标分支、部署提交和服务器 HEAD 一致。
- [ ] 部署后应用、数据库、Nginx 和关键任务接口健康。
- [ ] 出现异常时可以恢复到上一个已验证代码提交，不通过危险 SQL 反向改业务数据。
