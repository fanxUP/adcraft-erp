# 人事模块优化

用户已同意按评估建议开始实施。本次为涉及工资历史、考勤、权限与财务的多阶段变更，不自动修改生产数据，不推测历史付款日期或重建已丢失的工资标准。

## 实施顺序与验收

1. 考勤和工资共用后端统计：缺卡、明确未出勤、请假、未登记分别统计；半天同时检查签到/签退；只统计已到日期和任职期间，采用部门考勤工作日。缺卡旧码 `missed` 保留为缺卡，已有公式不自动改写。请假生效以审批记录为准，不覆盖原始打卡。
2. 保留历史工资：当月已有记录的离职/软删除员工继续展示；按任职日期选取计算员工；工资记录保存人员、工资规则、指标、参数和计算值快照。历史无快照如实使用现存数据，不能声称恢复了原始历史。
3. 已发工资保护：所有计算、手改单元格、旧 CRUD 和支付状态入口执行一致校验，并按员工锁串行写入。批量计算跳过锁定行，手工操作整体预检。工资标准按生效日期新增版本，已被核算使用的版本不能原地改删。重复历史记录在迁移前阻断，禁止静默合并或删除。
4. 页面和主数据：使用部门管理数据；缩减员工默认列；考勤/工资内提供规则、请假、报表/打印等入口，保留旧 URL。私密字段按权限返回。
5. 权限：员工、考勤、请假审批、工资读取/核算/发放、部门维护分别授权；前后端一致。既有超级管理员保留能力，不自动扩大普通角色权限。
6. 付款与交接：工资发放登记实际日期/账户/金额并进入现有支出，分次付款复用现有有效付款口径，历史已发工资不自动生成支出；离职提示未完成任务及未发工资并自动记履历，既有禁用账号逻辑保留。

## 验证与迁移

- 专项回归覆盖：离职历史、半天/缺卡/未来/请假/不同工作日、已发锁定所有入口、规则版本、越权、工资付款去重。
- PostgreSQL 使用显式测试连接与随机 schema，升级前后核对记录数、金额和历史值；生成检查迁移 SQL；执行前设置短锁超时，遇重复阻断不清洗。
- 前端执行类型检查、相关测试、Lint、构建，并在模拟 API 下检查界面。
- 生产发布另行记录备份、只读预检、迁移干跑、应用提交与回滚；应用回退保留新增数据结构，不回滚真实工资/付款事实。
- 为完整回归同步修正旧编号测试的业务时区断言及 Vitest 自动组件样式配置（仅测试模式禁用 CSS 自动导入），不改变生产编号或构建样式。
- 不引入依赖，不重构订单/任务状态机或现有支出统计，不自动回填历史付款。
