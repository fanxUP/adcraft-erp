## 历史数据及实现边界

- 原来被覆盖的工资标准、已经丢失的人员历史属性无法从当前记录还原；旧记录不伪造快照。保存新快照后才具备完整的新核算追溯信息。
- `missed` 保留原存储码，在本次统一口径中表示缺卡；原签到页面曾显示为“旷工”，工资公式又曾使用该码。发布前应核对旧数据含义和既有自定义公式，不自动把旧记录重新分类或重算已发工资。
- 只将明确登记的 `absent` 计作未出勤；未登记和缺卡不会自动升级为旷工。请假与正常打卡冲突单独提示，不覆盖原打卡。
- 工资标准仍按月末前最新生效版本核算；跨月中途调薪不自动分段计价。打卡异常以登记状态为准，不新增考勤机/自动判迟到；现有工资固定加班费率口径保留。
- 已建立快照的月份沿用原指标。已发金额不能通过重算更正，实际补发通过独立支出登记，不能修改原发放事实。
- 旧已发工资与此前人工登记的工资支出不自动匹配、不重新生成；不得把登记时间猜作付款日期。本次请求防重覆盖工资发放入口，不会猜测并合并其他独立人工支出。
- 私密资料的 API 字段、列表和上传/删除入口已细分授权；已有上传文件仍沿用项目既有静态 URL 存储方式。文件级私密存储与历史文件迁移应作为独立安全改造处理，不应把字段隐藏等同于历史文件 URL 已失效。
