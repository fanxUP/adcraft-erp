# 验收标准

## A1：合同是新收款的必需依据

- 应收页面登记收款时必须选择合同。
- 旧客户端只提交 order_id 时，系统能解析唯一合同；订单未关联合同时返回清晰错误。
- 客户与合同不一致时拒绝写入。

## A2：收款分配正确且不重复

- 不指定订单时，收款按合同关联订单顺序分配，超出订单合计的部分保留合同级分配。
- 指定订单时只能分配到该合同关联订单。
- 一笔收款的分配合计不超过收款金额，合同已收不超过合同总额。

## A3：余额和作废可重算

- 合同已收、合同未收、订单已收、订单未收均与有效分配一致。
- 收款作废后，收款记录仍可查询，合同和订单余额恢复正确。
- 历史收款没有分配时仍可查询，并不会被静默删除或重复计算。

## A4：框架合同和订单编辑兼容

- 框架合同仍能按其项目/订单看到正确收款汇总。
- 订单明细编辑的关联检查仍能识别实际关联订单的收款。
- 设计、制作、安装任务状态和权限不受收款改造影响。

## A5：权限和金额隔离

- 未持有 payment:create 的用户不能登记收款。
- 未持有 payment:void 的用户不能作废收款。
- 任务执行角色不因任务权限获得合同或收款金额。

## A6：发布质量

- 后端既有测试和新增回归测试全部通过。
- Alembic 在线检查无未登记模型变化，迁移可重复执行且不删除业务数据。
- 前端类型检查、Lint、构建和 AI 页面契约检查通过。
