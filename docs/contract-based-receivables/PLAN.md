# 实施计划

## P1：建立收款分配模型

新增 PaymentAllocation ORM 和加法迁移；将 Payment.document_id 调整为可空以支持合同级收款，保留历史订单字段兼容。

## P2：改造收款服务

登记收款先锁定并校验合同，再按指定订单或合同关联订单自动生成分配；合同余额、订单余额和作废重算统一使用分配事实。

## P3：统一合同与报表计算

合同列表、合同详情、客户欠款总览和框架合同项目统计改为读取 allocation 汇总，避免合同关联变化导致历史收款漂移。

## P4：改造应收页面

登记收款对话框改为先选合同，显示合同余额和关联订单，可指定订单或使用自动分配；收款记录展示合同编号、分配状态和分配明细。

## P5：历史兼容与迁移检查

迁移只自动回填订单明确对应唯一合同的历史收款；没有合同或存在多合同关系的历史记录不猜测、不删除，并输出待核对范围。

## P6：回归验证

覆盖合同收款、订单自动分配、指定订单、部分收款、超收拦截、作废恢复、框架合同、权限和现有订单编辑关联检查。

## 依赖

```text
P1 → P2 → P3 → P4
       └────→ P5 → P6
```
