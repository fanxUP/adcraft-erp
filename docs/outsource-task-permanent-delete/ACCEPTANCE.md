# 外协任务永久删除验收标准

## A01：软删除和恢复保留付款事实（对应 P01）

- 将含付款流水的任务移入回收站后，`outsource_payments` 记录和金额保持不变。
- 恢复任务后，付款明细、已付/未付金额与删除前一致；不会因付款行缺失而把历史非零已付静默改成 0。
- 对旧回收站记录不自动生成付款流水或付款日期。

## A02：资格条件由后端强制（对应 P02）

- 未软删除、非取消、已完成/已结算、非零已付、存在任一付款行、存在任一付款日期核对记录、费用重叠审查记录，或旧版日志证明曾清除付款流水时，永久删除均被拒绝并返回明确原因。
- 前端资格结果过期或并发状态变化时，后端最终复核仍能拒绝删除。
- 符合条件的单条任务可进入删除流程；不提供批量或强制覆盖路径。

## A03：权限、事务、审计和关联完整性（对应 P03）

- 只有具有 `outsource_task:permanent_delete` 且满足依赖权限的用户可调用 API；仅有普通外协删除权限的用户得到 403。
- 删除仅针对回收站任务，服务端在事务中锁定并重查资格。
- 删除和永久删除审计日志原子提交；日志包含操作者、原因、时间、IP、任务编号和必要业务快照。
- 日志写入失败时任务仍存在；任务删除不会级联删除付款、核对、费用审查、订单/报价、订单明细或内部任务。

## A04：回收站交互明确且不可误触（对应 P04）

- 无权限用户不看到永久删除入口，也不能通过直接调用 API 绕过权限。
- 有权限用户能看到每条记录是否符合条件和具体阻止原因。
- 确认窗要求准确输入任务编号及删除原因，并清晰说明不可恢复及关联影响。
- 成功后列表刷新；取消确认不发送删除请求；重复提交不会删除其他对象。

## A05：财务口径和发布安全（对应 P05）

- 非零已付历史任务即使没有付款明细，也不能永久删除；其支出台账金额和待核实提示不因本功能被抹除。
- 旧版日志标记曾被清除付款明细的任务，即使当前已付汇总为 0，仍被阻止永久删除。
- 具备付款行或财务引用的任务在测试中全部被拒绝，费用/付款汇总保持一致。
- 后端测试、权限测试、前端测试、类型检查、Lint、构建和差异检查通过。
- 生产数据副本上的干跑覆盖允许/拒绝场景；生产备份和恢复流程有证据，生产验证不包含试删真实记录。
