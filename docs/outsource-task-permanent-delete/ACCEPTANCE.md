# 外协任务永久删除验收标准

> A06–A08 是 2026-10 当前修订并覆盖 A02–A05 中与付款/财务引用阻止删除、保留所有财务关联、输入完整任务编号确认相冲突的条款；A01 软删除/恢复保全行为仍有效。

## A01：软删除和恢复保留付款事实（对应 P01）

- 将含付款流水的任务移入回收站后，`outsource_payments` 记录和金额保持不变。
- 恢复任务后，付款明细、已付/未付金额与删除前一致；不会因付款行缺失而把历史非零已付静默改成 0。
- 对旧回收站记录不自动生成付款流水或付款日期。

## A02：资格条件由后端强制（对应 P02，按 A06 修订）

- 不在回收站或状态不是已取消时，永久删除被拒绝并返回明确原因。
- 付款行、付款日期核对、费用重叠审查及非零历史已付金额不是阻止条件；这些范围内的直接关联财务行随任务一起清理。
- 前端资格结果过期或并发状态变化时，后端最终复核仍会拒绝不符合回收站/取消状态的任务。
- 只允许单条任务操作；不提供批量或强制覆盖路径。

## A03：权限、事务、审计和关联完整性（对应 P03）

- 只有具有 `outsource_task:permanent_delete` 且满足依赖权限的用户可调用 API；仅有普通外协删除权限的用户得到 403。
- 删除仅针对回收站任务，服务端在事务中锁定并重查资格。
- 删除和永久删除审计日志原子提交；日志包含操作者、原因、时间、IP、任务编号和必要业务快照。
- 日志写入失败时任务及财务记录仍存在；已授权的直接财务清理、任务删除和永久删除审计日志处于同一事务。
- 项目成本、订单/报价、订单明细、内部任务和操作日志均保留。

## A04：回收站交互明确且不可误触（对应 P04）

- 无权限用户不看到永久删除入口，也不能通过直接调用 API 绕过权限。
- 有权限用户能看到每条记录是否符合条件和具体阻止原因。
- 确认窗展示关联项、财务清理范围和保留范围；无需重复输入任务编号，但删除原因必填 5–500 字。
- 成功后列表刷新；取消确认不发送删除请求；重复提交不会删除其他对象。

## A05：财务口径和发布安全（对应 P05）

- 删除审计快照记录任务原始金额及被删除的付款/日期核对金额摘要；旧版“曾清除付款行”日志仍保留并记录到本次审计快照。
- 删除后外协付款来源不再进入支出台账；项目成本及其独立付款/核对数据仍按原口径统计。
- 有付款行或财务引用的已取消回收站任务，在确认后可清理；不符合回收站或取消条件的任务仍被拒绝。
- 后端测试、权限测试、前端测试、类型检查、Lint、构建和差异检查通过。
- 生产数据副本上的干跑覆盖允许/拒绝场景；生产备份和恢复流程有证据，生产验证不包含试删真实记录。

## A06：直接关联财务数据原子清理（对应 P06）

- 仅回收站且已取消的任务可永久删除；非取消任务仍被拒绝。
- 删除会清理该任务的付款行、指向任务或其付款行的所有付款日期核对（包括已撤销），以及指向该任务的费用重叠审查。
- 财务清理、外协任务删除和永久删除审计日志在同一事务完成；任一步骤失败则全部回滚。
- 项目成本及其独立付款日期核对、订单/报价、订单明细、来源设计/制作/安装任务和操作审计历史均保留。
- 审计快照记录被清理的记录数量、金额摘要和关联项目成本 ID；财务支出台账不再把已删除的外协付款来源计入期间实际付款，独立项目成本仍正常统计。

## A07：关联清单与简化确认（对应 P07）

- 永久删除确认不再要求输入完整任务编号；删除原因仍需填写 5–500 字。
- 弹窗展示关联内部任务、订单/明细和将删除的财务记录数量/金额，并明确哪些数据保留。
- 取消不发送删除请求；提交时按钮进入 loading/disabled；成功提示并刷新列表，失败保留弹窗和错误原因。

## A08：质量与安全验证（对应 P08）

- 服务层测试证明财务删除及保留边界正确，路由测试证明权限/审计原子性，前端测试证明无需任务编号且展示关联清单。
- 聚焦后端与前端测试、类型检查、Lint、构建、权限审查及差异预算通过。
- 不对生产数据执行删除；发布仅按 A09 的明确授权和门禁执行。

## A09：受控提交、推送与生产部署（对应 P09）

- 变更以普通提交推送至功能分支，并经 PR 合入受保护的 `master`；无强推、历史改写或跳过失败检查。
- 发布前确认服务器工作区干净、回滚基线可用、服务当前健康；本次没有数据库迁移或生产数据修改。
- 通过项目 `deploy.sh` 发布 GitHub `master` 的指定完整提交。
- 发布后 `adcraft-backend` 运行中，健康响应包含 `database: ok`，且服务器 HEAD 与 `.deployed-commit` 和目标提交一致。
- 检查服务日志无启动错误；失败时停止后续操作并按记录的回滚基线恢复。
