# 外协任务永久删除设计

> 当前行为以 2026-10 修订为准：仅删除任务直接关联的外协付款、任务/付款日期核对与费用重叠审查；项目成本、订单、明细、内部任务和操作审计保留。原始“财务关联阻止删除”规则仅记录初版设计，已由本修订取代。

## 2026-10 修订：关联财务数据和确认交互

- 范围仍为单条、回收站中、已取消的外协任务；权限校验、行锁和事务审计保留。
- 删除事务按依赖顺序移除：指向任务或其付款行的付款日期核对（含已撤销）、外协付款行、指向任务的费用重叠审查、外协任务。
- 项目成本以及项目成本自身的付款日期核对不属于外协任务的直接数据，不删除；操作日志也保留。
- 来源设计/制作/安装任务、订单及订单明细仅解除外协任务引用，不删除这些业务实体。
- 确认弹窗列出来源任务、订单/明细、外协付款/核对/审查数量及金额，标明保留项；不要求重复输入任务编号，仍需填写删除原因。
- 财务关联和历史已付汇总不再阻止取消任务删除，因为用户已明确授权清理这些直接关联财务记录；它们仍作为审计快照与删除影响展示。非取消状态仍被拒绝。
- 对关联成本审查记录删除后，其项目成本仍留在支出台账，仍可能影响项目实际支出；审计记录说明审查行已删除及其关联成本 ID。

## 初版背景与当前规则

- 类型：外协任务不可逆删除与财务数据保全。
- 风险：高；采用 STRICT 模式。永久删除不能靠页面确认框替代后端约束。
- 目标：有权限的人员可永久删除回收站中状态为“已取消”的单条外协任务，并按本设计清理其直接关联财务记录。
- 当前资格：任务必须仍在回收站且状态为已取消。付款行、任务/付款日期核对、费用重叠审查及非零历史已付不再阻止删除，因为这些直接关联项会一并删除。
- 当前删除范围：外协付款；来源为 `outsource_task` 或关联外协付款 ID 的所有付款日期核对（包括已撤销）；指向该任务的费用重叠审查；外协任务本身。
- 明确保留：项目成本及其 `project_cost` 日期核对、订单/报价、订单明细、来源设计/制作/安装任务、供应商和所有操作日志。

## 当前行为与设计约束

- 回收站目前只有恢复操作，没有永久删除入口。
- 现有任务删除接口将任务软删除，但同时物理删除关联的 `outsource_payments`；恢复时按仍存在的付款行重算金额。付款行一旦被删，恢复可能无法还原原付款明细和金额口径。
- 财务费用重叠审查通过 `ON DELETE RESTRICT` 外键引用外协任务；当前流程在删任务前显式删除该任务的审查行，不依赖数据库级联。
- 付款日期核对记录通过 `source_type/source_id` 多态关联，数据库没有外键保护；当前流程按任务及其付款行 ID 显式查询、锁定并删除对应核对行。
- 操作日志可保留删除对象 ID 和 JSON 快照，可用于记录永久删除事件；日志不能替代财务流水。
- 旧版软删除日志会记录被清除的付款行数量；永久删除时保留这些日志，并把其历史数量纳入当前删除审计快照。

因此，永久删除功能的前置条件是先修正软删除：移入回收站不得删除付款行，恢复不得把只有历史已付汇总、但没有付款明细的任务静默改成已付 0。已有回收站数据不自动补造付款明细或付款日期。

## 当前事务与审计规则

1. 后端校验独立永久删除权限、任务仍处于回收站、状态为已取消，并在同一请求事务中锁定任务后复核。
2. 按依赖顺序清理任务/付款日期核对、费用重叠审查及外协付款，再物理删除外协任务；任何一步失败或审计写入失败，整个事务回滚。
3. 服务层将最小必要任务快照和直接财务删除摘要交给 API；摘要包含付款/核对数量与金额、审查数量及其关联项目成本 ID。操作日志保留，历史日志不会被级联删除。
4. 旧版软删除日志中“曾清除付款行”的记录只作为审计快照信息，不会被删除，也不再阻止当前已取消任务的永久删除。
5. `FinancePaymentDateReconciliation` 是多态来源引用，没有数据库外键；财务核对创建流程会锁定对应任务或付款行，永久删除流程也锁定这些来源行后再清理，避免并发产生孤儿核对。
6. 未付款余额属于已取消任务的历史计划摘要；删除后任务计划不再存在，实际已记录的外协付款来源不再进入支出台账。项目成本仍独立统计。

## 交互与接口

1. 回收站显示“永久删除”操作，并先展示服务端计算的资格与阻止原因。
2. 对符合条件的记录，确认弹窗显示任务编号、来源内部任务/单据/明细、外协付款与日期核对数量及金额、费用审查数量、不可恢复提示和明确保留项；只要求填写删除原因（5–500 字），不重复输入任务编号。
3. 前端按钮状态仅作提示。后端独立校验权限、回收站状态和取消状态，并在事务中锁定任务后复查。
4. 使用独立的永久删除 API，例如 `DELETE /outsource/tasks/recycle/{task_id}`；不复用现有软删除路由。
5. 单事务内写入永久删除审计日志（操作者、时间、IP、原因、任务编号及最小必要快照），再物理删除任务。审计日志失败则整个事务回滚。
6. 只删除明示的直接关联财务记录；不删除项目成本、其独立日期核对或其他业务记录。日志保留每次永久删除及其财务摘要。

## 权限

- 新增独立权限 `outsource_task:permanent_delete`，与 `outsource_task:delete`（软删除/回收站管理）分离。
- 默认只授予系统管理员；其他角色必须在角色管理中显式授权。
- 权限依赖外协中心和任务读取权限，并在权限目录中标记为高风险敏感操作；API 必须服务端校验，不能只隐藏前端按钮。

## 全局影响

- 财务支出台账：直接关联外协付款及日期核对删除后不再作为该外协任务来源统计；独立项目成本及其付款信息仍留在台账。
- 外协付款：普通软删除和恢复保留原付款行；只有用户主动确认永久删除已取消回收站任务时，相关付款行才一并删除。
- 订单明细、内部设计/制作/安装任务：被删任务不再出现在关联统计中；永久删除审计快照保留原关联信息。相关业务实体本身不删除。
- 成本重叠审查和任务/付款日期核对：直接关联行随该任务删除；项目成本自身的日期核对及所有操作日志保留。
- 供应商历史与外协计划统计：永久删除会移除该任务的历史计划行；确认弹窗和审计快照应明确展示。

## 数据库、恢复与发布

- 预计无需新增业务表或 Alembic 迁移；权限目录/角色种子版本需要更新，操作日志复用现有 JSON 字段。若实现审计快照需要独立表，再单独评估迁移。
- 永久删除本身没有应用内撤销；误删恢复依赖备份恢复或人工重建。当前请求仅实现并测试代码，不执行生产数据试删或发布。
- 现有软删除已经物理删除过的付款明细不能通过新逻辑自动恢复；不得根据 `paid_amount` 合成带日期的付款记录。需要从可靠备份/凭证恢复时，应作为单独财务数据修复流程处理。
- 不对生产数据执行试删。上线前确认最近备份有效、恢复流程可用；上线后只做健康检查和非破坏性页面/API 校验。
