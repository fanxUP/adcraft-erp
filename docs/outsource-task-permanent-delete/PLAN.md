# 外协任务永久删除实施计划

## 模式与范围

- 模式：STRICT。
- 风险：高；涉及不可逆数据删除、付款流水、角色授权与跨模块财务统计。
- 有界目标：为回收站增加受限的单条永久删除能力，并确保软删除/恢复不会继续丢失付款明细。
- 不做：生产数据清理、批量删除、强制绕过财务阻止、删除付款/核对/审查记录、为旧数据补造付款日期。
- 预计不新增数据库表；需要新增权限码并提升权限种子版本。只有审计要求超出既有操作日志能力时才另行提出迁移。

## 执行项

### P01：保全软删除与恢复中的付款事实

- 调整软删除流程：只把任务移入回收站，不物理删除 `outsource_payments`。
- 调整恢复流程：保留可验证的付款明细和金额；没有付款明细但任务保留非零历史已付汇总时，不得静默重置为 0。
- 增加回归测试；不尝试自动恢复已被旧逻辑删除的付款行。
- 主验收：A01。

### P02：建立永久删除资格检查

- 在服务层形成统一资格检查，返回可删除标记及阻止原因。
- 检查任务是否已删除且已取消、非零已付、付款行、所有日期核对记录、费用重叠审查记录、旧版曾清除付款行的操作日志及完成/结算状态。
- 在删除事务中重新检查，避免仅依赖前端预检结果。
- 主验收：A02。

### P03：实现独立权限、事务删除与审计

- 新增 `outsource_task:permanent_delete` 权限、依赖和角色种子版本；默认仅系统管理员获权。
- 新增独立回收站永久删除 API；服务端锁定任务并执行资格复核。
- 将最小必要任务快照、操作者、原因、时间、IP 写入现有操作日志；日志与删除同事务提交。
- 禁止级联删除付款、财务核对、费用审查和业务主记录；任何遗留引用都拒绝操作。
- 主验收：A03。

### P04：回收站资格提示和双重确认

- 为有权限用户展示永久删除入口及资格状态；阻止时显示可理解原因。
- 确认窗展示金额、关联数据、不可恢复说明；要求输入任务编号和删除原因。
- 删除成功后刷新回收站；失败时保留上下文并显示后端阻止原因。
- 主验收：A04。

### P05：严格验证与发布门禁

- 覆盖服务、API 权限、并发/事务、历史付款清除审计识别、前端确认和财务汇总测试；更新原“删除时级联删除付款”的测试预期。
- 在生产数据副本上演练：符合条件的模拟任务可删，不符合条件的付款/财务任务必须被拒绝；不对真实业务记录试删。
- 生产上线前确认备份及恢复证据；部署后只做健康检查和只读功能核验。
- 主验收：A05。

## 关键决策

- 永久删除仅处理“已取消且无实际财务痕迹”的回收站任务；非零已付、付款流水、核对记录或成本审查关联均不可绕过。
- 对“已取消但仍有未付余额”的业务口径，实施前由业务确认：本计划暂将其视作取消后的计划余额并在审计快照中保留；如果它仍代表真实应付，应改为阻止删除并先设计核销流程。
- 对当前已付金额非零、但付款明细缺失的旧任务，保留记录并继续核实；不得用永久删除来消除未核实金额。
