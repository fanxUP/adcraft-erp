# 银行台账建设方案

## 目标与范围

在「财务中心 → 公司账户」增加「银行台账」入口，复用现有账户档案。每个银行账户能独立看余额、查收支、导入对账单和处理差异。员工仍在应收、支出、外协付款等原页面登记，选择实际使用的账户和日期即可，财务不需要把同一笔款再录一次。

首期覆盖人民币银行账户，先选 1–2 个有完整对账单的常用账户试点。现金、微信、支付宝继续使用现有账户类型，后续按需接入；车辆等独立登记模块先按实际凭证核对，确认是否已经走支出付款后再接入。首期不接网银、不发起真实转账、不替代会计总账。本文是设计和实施计划，无生产数据操作。

## 现有模块如何接入

| 现有业务 | 银行台账的处理规则 |
| --- | --- |
| 公司账户 | 继续用原账户 ID、开户信息、尾号及启停状态。补充开户主体或归属公司的筛选、币种和各账户台账启用日。账户别名可调整；有台账记录后不得把旧账户改成另一张卡或物理删除，销户用停用保留历史。 |
| 客户收款 | 现有合同收款有付款方式和日期字段，新增「收款账户」并要求新登记的银行收款填实际到账日期。一次收款按收款单进入账户一次；分配到多个订单仍是一笔银行入账。向客户退回货款等实际退款按业务规则登记并关联原收款，按实际出款账户和日期记反方向流水；误录作废走更正。 |
| 支出和项目成本 | 登记时已付部分按实际付款入账，分批付款按每一笔的金额、账户、日期分别入账；项目成本总额、欠款、累计已付汇总和最后付款日期不作为银行流水。沿用现在的规则：登记时已付，选的日期就是这笔付款日期。 |
| 外协付款 | 按外协付款记录接入；不从外协任务总额、已付汇总或项目成本再生成同一笔付款。对疑似在项目成本和外协重复登记的款列差异，由财务核实。 |
| 工资 | 已通过「支出 → 应付付款」发放的工资随该付款进入台账，工资模块不再生成第二笔。独立历史标记不补造付款。台账能看资金流向，员工工资细节继续受人事权限约束。 |
| 财务总览、合同、订单、项目利润 | 继续按原业务记录计算。银行台账用于查资金和核对，不将导入的流水叠加到现有营收、收款或支出汇总中。只改变核对关系时，合同已收、订单未收、项目成本不变。 |

## 页面和日常操作

- **账户总览**：显示账户别名、开户主体、开户行、尾号、账面余额、银行对账单余额及截至日期、同日差额、待对账笔数。支持按主体、银行、账户状态搜索和筛选。总计按同主体、同币种和同一截至日汇总；缺少期初或对账单的账户注明状态，不默认为零。不同截至日的对账单余额不直接加成一个余额。
- **账户明细**：一张收支表，列日期、摘要、对方、收入、支出、账面余额、来源、对账状态。支持日期、类别、对账状态筛选及跳转到有权查看的合同、支出或外协记录。银行记账日期、银行流水号在详情中显示。列表余额以账户的完整流水顺序计算，不会因筛选某类收支而改变。
- **对账工作台**：先选账户并导入对账单，系统预览行数、收支合计、时间范围、错误及疑似重复；确认后保存。左边是银行流水，右边是 ERP 待对账记录。优先推荐同账户、同方向、同金额且银行参考号明确的记录；日期、对方和摘要仅作辅助。同日同金额有多笔时由财务选择，首期匹配均由人确认。
- **内部转账**：使用一个入口选转出和转入账户，统一转账编号。各账户按自己的实际发生日期记一条转出或转入；扣款后未到账时显示「在途」，确认到账后补齐转入侧，不假定当天到款。纳入同一主体统计的账户互转不增加经营收入或支出；单独扣收的手续费按独立支出登记，不能混入转账本金。不同主体之间的往来单列，不能当作同主体内部转账直接抵销。

## 余额、差额和异常处理

账面余额＝启用日之前的期初余额＋启用日起已入账收入－启用日起已入账支出（含内部转入和转出，以及明确的更正）。银行对账单余额取银行提供的截至日结余，保留来源和截至日；只导入交易明细却没有结余时，显示「未提供银行余额」。账户总览可同时看最新账面余额和最近银行余额，差额只比较同一账户同一截至日的两项余额。

银行和 ERP 各留自己的日期：ERP 用实际收付款日期，银行侧用银行记账日期。比如账上 10 日已付、银行 11 日才扣款，经凭证确认后可以跨日对账；10 日仍可查看该日期的时间差。银行有、ERP 没有的款，由财务在原业务入口补录；银行利息等没有现成来源的交易使用受控的银行收支登记。ERP 有、银行没有的款保持未匹配，核查是否为在途、选错账户或误录。银行流水导入只保存证据，不生成业务付款或另一笔账面流水。金额不符、账户不明、凭证不全进入待核实，不通过改期初或填一笔无来源差额强行对平。

首期支持一对一匹配和整笔撤销匹配；代发工资、批量付款、拆分到账、净额扣手续费等复杂流水保留待处理，明确提示当前能力。第二期实现一对多和多对一金额分配：同账户、同币种、同方向，双方金额分配不得超出原额；足额才标记已对账。若银行只提供扣费后的净额，在明确规则和凭证下单独登记手续费并核对净额，不能擅自改客户已付金额或用金额容差销账。余额相等时仍显示未匹配笔数，避免正负差异碰巧抵消。

## 数据与权限约定

- 业务收付款、ERP 账户流水、银行对账单原始流水是三类记录。业务付款更新原业务和账户流水应在同一事务完成；以业务来源类型、来源 ID 和记账动作建立唯一标识。请求重试不能重复入账，同一天同金额的两笔真实付款仍可分别记录。账户余额可由期初和流水重算，不能直接编辑余额覆盖差异。
- 建议数据结构：账户启用记录（起始日、期初、币种、凭证）、账户流水（账户、实际日期、收支方向、金额、业务来源和更正关联）、内部转账（两端及在途状态）、对账单导入批次及银行流水、对账匹配及分配明细。金额按分精确计算。启用、入账、更正、确认匹配和撤销都记录操作者、时间与原因。
- 对账单首期支持通用 CSV/Excel 格式及字段映射。批次保留文件摘要、账号归属、日期范围和预览结果；确认时校验账户，复查文件重复、期间缺口或重叠。优先按账户和银行提供的稳定唯一流水号去重；无稳定编号时用字段组合提示疑似重复，由财务确认，不能把同日同额的真实交易直接吞掉。导入按批次提交，失败可重试。银行原件通过现有鉴权附件方式读取。
- 将账户档案管理、按账户查看余额/流水、导入、确认或撤销对账、导出分开授权。普通业务人员继续只按权限选账户，不能因为能选账户就查看余额、原件或完整账号；默认显示尾号。导出和来源跳转也执行服务端权限校验。试点由经办导入、财务复核确认。
- 误录、选错账户或错误删除要保留原流水及更正记录。更正未核对交易通过冲销和重记完成；已有匹配先按权限撤销匹配并说明原因，银行原始流水保留并重新进入待对账。真实退款/退票另登记反向交易，不用作废抹掉实际流水。已核对或已锁期的付款不得随业务单据的删除被级联移除；现有外协任务永久删除须在预览中列出银行台账影响，误录按更正处理，真实付款事实及银行证据继续保留。只改订单明细、任务归属、说明等内容，不重记银行流水。

## 上线步骤与验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| P1：准备期初 | 盘点开户主体、账户类型、日常付款入口，挑 1–2 个对账单齐全的账户；选月初为启用日，核实前一日银行对账单结余和跨期未达款。新增表和可空的收款账户字段。 | A1：试点账户期初与证据相符，跨期未达能逐笔说明；每账户可单独启用，未启用账户显示「未建账」；迁移不改历史金额和日期。 |
| P2：跑通资金账 | 上线账户总览、单账户明细和来源跳转；接入合同收款、登记时已付、应付分批、外协付款和经应付发放的工资；支持内部转账、实际退款、常用手续费和更正。 | A2：一笔收款分给多个订单只增加一次余额；一张支出单由两张卡分批付款，分别扣各自余额；工资只计一次；跨日转账在途可见，互转不增加经营收支；退款保留原记录；重复提交、修改、作废和回滚时余额可复算。 |
| P3：试点对账 | 导入试点银行对账单并人工确认一对一匹配；列出时间差、金额差、缺记录、疑似重复和覆盖缺口。试跑一个完整账期后再逐户推广。 | A3：同文件重试不重复入账，同日同额的真实交易能并存；导入与撤销匹配不改业务金额；同一截至日余额与未达明细可解释，部分文件不能标成全期已核完；普通角色和越权账户无法看余额、附件或导出。 |
| P4：扩展 | 按试点真实例子增加合并/拆分对账、银行格式模板、月末结账与锁期、导出和需要接入的其他账户或费用来源。 | A4：批量或拆分匹配不会超分配；历史月已锁时阻止直接回改，授权更正可审计；真实退款、回收站永久删除和对账撤销都能保留资金链。 |

依赖：P1 → P2 → P3 → P4。P2 和 P3 达成后完成首期试点；未达款或复杂批付未解决的账户，不能以“完全对平”作为结论。

### 历史数据切换规则

以账户为单位确定启用日，启用日前两边都已记账的款包含在期初，不再重放。若两边都对齐，账面期初直接等于前一日银行结余；若启用日前 ERP 已入账、银行尚未记账，按凭证把未达款计入账面期初并逐笔保留待匹配明细。银行日后补记时只核对，不再增加或扣减同一笔账面金额。若启用前银行已记账而 ERP 未登记，先查证并明确由期初承接还是在原业务补登，不能既包含在账面期初又计入启用后流水。试点若无法确认跨期差异，先换对账材料完整的日期或账户。启用日及之后发生的收付款，只有经财务确认账户、日期和金额才逐笔接入；已有流水按来源标识防重。缺账户、日期或真实凭据的老记录保留为待核实，不填默认账户、不推测日期、不修改原业务记录。

发布前在隔离数据库验证迁移和数据保留，用脱敏对账单演练重复导入、跨日到账、两卡分付、客户退款、外协误录和权限隔离。上线以账户单独开关；需要暂停时停止新增台账接入并保留已记录的流水与核对历史，继续通过原业务页面登记，恢复前核查停用期间的流水缺口。

## 推荐的试点准备

由财务选一个经常收款、一个经常付款的账户，准备账户尾号、启用日前一日对账单余额和启用后一个完整账期的对账单（CSV/Excel）；确认两户是否同属一个主体，并选一笔内部转账、一笔分批付款和一笔疑似重复记录作样例。账户众多时，先把这两户跑通再分批开通，比全量整理多年旧账更容易定位余额差异。
