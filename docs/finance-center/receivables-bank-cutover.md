# 银行台账与应收管理切换

银行台账中的「主营业务收入」流水直接出现在应收管理的「收款记录」。关联后才生成合同收款分配。解除关联撤销该笔分配，原资金流水仍计入账户余额。财务中心的实际收款包含授权可见的银行到账，经营报告的业务回款以已确认的合同和订单收款为准。

## 切换前核对

1. 记录切换时间，并用项目的备份脚本生成新的数据库和附件备份。核对归档和校验值，恢复到隔离数据库。
2. 在隔离库应用结构迁移 `receivables_bank_01`。该迁移为收款增加银行来源和归档批次，活动收款的银行来源有唯一索引。结构迁移只处理表结构，旧数据由下面的归档命令处理。
3. 在后端目录用项目 Python 环境预览。切换时间取计划中的业务时点并写上时区。预览在只读事务中运行。

```bash
python -m scripts.archive_legacy_receipts \
  --actor '管理员登录名' --cutoff '带时区的切换时间' > receipts-preview.json
```

预览按旧收款列出可能重复的银行流水、调整记录、账户余额及合同和订单的已收、待收变化。核对文件以旧收款 ID 为键，按凭证填写下列处理方式。

| 处理方式 | 用途 | 字段 |
| --- | --- | --- |
| `match` | 已确认台账有对应的实际到账或退款 | `entry_id`、`evidence` |
| `preserve` | 保留为一条独立的历史资金流水 | `evidence`，原账户或日期缺失时补充已核实的 `account_id`、`entry_date`。确认是主营业务收入时可填 `category` |
| `archive_only` | 经核对只保留历史凭据 | `evidence` |

银行台账中原本已有的独立到账，在没有同日同额记录、退款和预收转分配时，默认保留为「历史客户收款」。已作废的记录仅归档。核对后的结果保存在访问受控的目录。

## 执行和验收

在隔离库完成一次执行和验收。正式操作安排在财务暂停登记的时段，应用结构迁移后，用生产目标重新生成预览。以下两条命令使用相同的切换时间和核对文件。

```bash
python -m scripts.archive_legacy_receipts \
  --actor '管理员登录名' --cutoff '带时区的切换时间' \
  --decisions receipts-decisions.json > receipts-preview.json

python -m scripts.archive_legacy_receipts \
  --actor '管理员登录名' --cutoff '带时区的切换时间' \
  --decisions receipts-decisions.json \
  --apply --expect-plan '预览中的 plan_sha256' > receipts-applied.json
```

执行会先锁定相关业务表并重新计算预览。等待锁超过 5 秒、预览变化、存在待核对项或执行结果与预览不一致时，事务将回滚。保存输出中的批次号。逐账户检查收支和余额，逐合同和订单检查已收和待收。检查主营业务收入笔数、历史归档、原凭证、已确认对账单和草稿对账单，再验证关联及解除关联。

若切换后发现差异，先暂停相关写入。在正式恢复登记前，可用切换前备份恢复。恢复登记后用归档批次和操作日志定位差异并逐笔更正，以保留切换后的新流水和关联。
