# CPB-P01 实施计划

## 范围

### 本期做

- 完成订单项目的服务端分页查询和只读详情查询。
- 复用现有明细完成事件、订单任务可见范围、阶段读取权限和价格字段权限。
- 独立项目看板和工作台项目看板增加“完成”列。
- 普通员工按自己的明细完成归属查看，管理员/全员查看者查看权限范围内的全部项目和明细。
- 补充后端权限/数据隔离测试、前端契约测试和构建检查。

### 本期不做

- 不修改订单、任务、外协、明细状态机。
- 不把完成任务重新放回活跃任务队列。
- 不新增表、迁移、依赖或完成项目的编辑/恢复操作。
- 不改变价格、成本、利润、外协现有权限。
- 不把“完成项目”误解为当前登录员工独立完成整单；员工口径是完成过该项目的至少一条明细工作单元。

## 执行顺序

1. 先写服务层纯函数和边界测试，验证员工/管理员范围、阶段读取权限、最新状态和返工回退规则。
2. 增加完成项目服务、响应模型与 API，跑后端测试。
3. 增加完成卡片、只读详情抽屉和项目看板列，跑前端类型检查与 Vitest。
4. 将同一接口接入工作台，验证独立看板与工作台完成列使用同一数据源。
5. 运行 scope check、后端相关测试、前端测试/typecheck/build、security review；本轮不提交 Git、不部署。

## 风险控制

- 查询层不接收员工 ID 作为普通员工的可选参数，避免通过 URL 扩大范围。
- 所有金额字段在后端白名单中按 `order:view_price` 决定是否加入响应；员工端不依赖前端隐藏作为安全措施。
- 所有明细查询必须再次执行项目可见范围和阶段读取权限校验，不能只依赖列表页已加载的卡片。
- 新完成列单独捕获请求失败，保证现有活跃任务看板的故障隔离。

## 当前实施结果

- 后端完成项目服务、只读列表/详情接口和非财务响应模型已完成。
- 独立项目看板、工作台项目看板已接入“完成”列和只读详情抽屉。
- 本地后端全量测试 1124 项通过（新增 CPB 测试 6 项），前端 Vitest 169 项通过，typecheck、lint、build 通过。
- 尚未提交 Git、尚未部署服务器；上线前仍需在真实账号与真实完成订单上核对一次员工/管理员权限矩阵。
