# CPB-P01 / CPB-P02 实施计划

## 范围

### 本期做

- 完成订单项目的服务端分页查询和只读详情查询。
- 复用现有明细完成事件、订单任务可见范围、阶段读取权限和价格字段权限。
- 独立项目看板和工作台项目看板增加“完成”列。
- 普通员工按自己的明细完成归属查看，管理员/全员查看者查看权限范围内的全部项目和明细。
- 补充后端权限/数据隔离测试、前端契约测试和构建检查。

### 本期不做

- 不修改订单、任务、外协、明细状态机。
- 不把完成任务重新放回活跃任务队列。
- 不新增表、迁移、依赖或完成项目的编辑/恢复操作。
- 不改变价格、成本、利润、外协现有权限。
- 不把“完成项目”误解为当前登录员工独立完成整单；员工口径是完成过该项目的至少一条明细工作单元。

## 执行顺序

1. 先写服务层纯函数和边界测试，验证员工/管理员范围、阶段读取权限、最新状态和返工回退规则。
2. 增加完成项目服务、响应模型与 API，跑后端测试。
3. 增加完成卡片、只读详情抽屉和项目看板列，跑前端类型检查与 Vitest。
4. 将同一接口接入工作台，验证独立看板与工作台完成列使用同一数据源。
5. 运行 scope check、后端相关测试、前端测试/typecheck/build、security review；本轮不提交 Git、不部署。

## 风险控制

- 查询层不接收员工 ID 作为普通员工的可选参数，避免通过 URL 扩大范围。
- 所有金额字段在后端白名单中按 `order:view_price` 决定是否加入响应；员工端不依赖前端隐藏作为安全措施。
- 所有明细查询必须再次执行项目可见范围和阶段读取权限校验，不能只依赖列表页已加载的卡片。
- 新完成列单独捕获请求失败，保证现有活跃任务看板的故障隔离。

## 当前实施结果

- 后端完成项目服务、只读列表/详情接口和非财务响应模型已完成。
- 独立项目看板、工作台项目看板已接入“完成”列和只读详情入口（CPB-P01 历史基线）。
- 本地后端全量测试 1124 项通过（新增 CPB 测试 6 项），前端 Vitest 169 项通过，typecheck、lint、build 通过。
- 尚未提交 Git、尚未部署服务器；上线前仍需在真实账号与真实完成订单上核对一次员工/管理员权限矩阵。

## CPB-P03：完成项目详情按明细重排与任务资料区

### 本期做

- 将完成详情的主表改为“一条有效订单明细一行”，字段固定为：项目内容、产品/材质/工艺、规格、数量、设计、制作、安装。
- 每个阶段单元格固定显示三行：完成状态、执行人、完成日期；只使用对应“阶段 + 订单明细”的最新有效完成事件，不能使用整张任务的负责人兜底覆盖其他明细。
- 复用 `BusinessDocumentItem` 的有效明细、排序、材质工艺、尺寸和数量字段；不返回单价、小计、成本、利润等价格参数。
- 在表格下方增加设计任务附件、制作任务附件、安装任务现场照片与视频三个只读资料模块；按任务编号分组，复用现有附件类型判断和预览/下载能力。
- 任务资料继续执行阶段读取权限和订单任务可见范围裁剪；无权限阶段不返回任务编号、执行人、完成时间或附件地址。

### 本期不做

- 不修改订单、任务、明细状态机、完成事件写入、负责人分配、外协和成本规则。
- 不新增数据库表、迁移、依赖、上传/删除操作或新的菜单入口。
- 不改变完成看板卡片的列表口径、员工/管理员项目范围和金额字段权限。

### 执行顺序

1. 先新增 item-centric 响应与权限/去重/阶段隔离测试，确认旧的“事件一行”契约被安全替换。
2. 批量加载有效订单明细、最新阶段完成事件、可见任务和附件，避免逐条查询。
3. 更新独立完成详情页主表和三类资料区，保持只读、页面级滚动和响应式换行。
4. 执行后端相关测试、前端契约测试、类型检查、Lint、构建、scope/budget/security/quality gate。

### CPB-P03 实施结果

- 已完成完成项目详情的明细化重构：主表改为一条有效订单明细一行，固定展示项目内容、产品/材质/工艺、规格、数量、设计、制作、安装；阶段单元格按状态、执行人、完成日期展示，且不同阶段不会串用负责人。
- 已完成设计任务附件、制作任务附件、安装任务现场照片与视频三个只读资料模块，按任务编号分组；图片支持缩略图/放大，视频支持播放，其他文件显示文件名、类型、大小、上传时间并提供预览或下载。
- 已在服务端复用现有项目、任务、阶段读取权限和员工数据范围；员工只返回本人可见的完成阶段与资料，管理员按权限查看全部；响应不增加价格、成本、利润或外协字段。
- 未新增数据库表、迁移、依赖、上传/删除操作或路由；资源查询采用批量加载，避免按明细逐条查询。
- 本地后端全量测试 1127 项通过，前端 Vitest 172 项通过，lint、typecheck、build 和 bundle-size 检查通过；自动 Vibe 门禁脚本在当前环境不存在，因此以等价的差异范围、敏感信息、编译和测试检查完成本地验证。
- 尚未提交 Git、尚未部署服务器。

## CPB-P02：完成明细独立页面

### 本期做

- 删除工作台完成统计区内的“按项目/按明细”明细表、筛选器和分页请求；保留汇总 KPI、阶段数量和管理员员工统计。
- 新增独立完成项目详情页，复用现有 `GET /task-queue/completed-projects/{project_id}` 只读接口。
- 工作台和独立项目看板的完成卡片统一跳转到同一个详情路由，不再打开抽屉。
- 为详情路由增加 `task_completion:read` 页面能力映射，并同步前端契约测试。
- 删除不再被引用的完成详情抽屉组件，避免留下死功能代码。

### 本期不做

- 不修改完成项目后端查询口径、订单/任务状态、员工归属、价格脱敏和数据权限。
- 不增加菜单入口、详情编辑、恢复、删除、导出或新的数据库/依赖。

### 执行顺序

1. 先更新路由、页面跳转和抽屉下线的前端契约测试，形成失败用例。
2. 增加独立详情页面并接入详情接口，完成权限守卫和返回路径。
3. 清理工作台明细表及其专用请求状态，只保留完成统计摘要。
4. 删除抽屉组件，执行 scope check、前端测试、typecheck、lint 和 build。

### 验收要点

- 两处完成列卡片点击后都进入同一个 `/projects/completed/:projectId` 页面。
- 工作台源码不再请求 `/reports/task-completion/details`，且页面不渲染完成明细表。
- 详情页只读展示，后端接口失败或越权时显示大白话错误，不显示空白或旧数据。
- 没有 `task_completion:read` 的账号不能通过直接 URL 进入详情页；有权限的员工仍只能看到后端返回的个人范围。

### CPB-P02 实施结果

- 已完成独立完成项目详情页、统一路由跳转、路由权限映射和返回看板入口。
- 已移除工作台完成明细表、筛选/分页状态及其前端报表接口和类型；完成统计摘要仍保留。
- 已删除旧完成详情抽屉组件，前端运行时代码不再引用抽屉或旧完成明细报表接口。
- 本地前端全量测试 172 项通过，typecheck、lint、build 通过；尚未提交 Git、尚未部署服务器。
