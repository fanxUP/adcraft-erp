# 订单级三阶段资料源验收标准

## A-OSA-01：业务归属与权限契约

- [ ] 订单详情可以在没有设计、制作或安装任务时分别进入三个阶段资料区。
- [ ] 上传订单阶段资料只需要 `order_id + stage + file`，不要求 `task_id`。
- [ ] 删除任务、完成任务、取消任务、任务合并或重新生成，不会让订单阶段资料丢失或变成不可管理的孤儿资料。
- [ ] 同一个订单、同一个阶段只有一份资料集合；同一资料不会因为存在多张任务而重复展示。
- [ ] `order:read` 用户在订单入口可以查看、上传、下载、删除三个阶段资料。
- [ ] 设计、制作、安装任务入口只能读取对应阶段；上传和删除使用对应阶段的任务更新权限。
- [ ] 没有对应订单或阶段权限的账号不能通过修改 URL、阶段参数或附件 ID访问资料。

## A-OSA-02：数据模型、接口和文件安全

- [ ] `attachments` 表存在可空 `order_id`、`stage` 字段、阶段校验和查询索引。
- [ ] 新订单资料以 `order_id + stage` 为权威归属，服务端不通过任务存在性判断能否上传、下载或删除。
- [ ] 规范接口提供订单级列表、上传、受保护文件读取和删除能力，上传接口不把任务 ID作为必填字段。
- [ ] 下载/预览前服务端精确校验 `order_id + attachment_id` 的归属，跨订单附件 ID 返回无权/不存在。
- [ ] JSON 响应不返回物理 `file_path`、绝对路径或可绕过鉴权的公开文件地址。
- [ ] 继续执行 MIME、扩展名、文件大小和 magic-byte 校验；不支持的文件被拒绝。
- [ ] 文件名不会参与服务器路径拼接，文件路径经过 `confined_path` 校验，操作日志记录订单、阶段、附件和操作人。
- [ ] 订单资料响应不带订单金额、单价、小计、成本、利润等价格字段，除非调用方已有明确价格权限且该接口确实需要。

## A-OSA-03：历史迁移与兼容

- [ ] dry-run 能统计设计、制作、安装旧任务附件的可映射数量和孤儿数量。
- [ ] 可映射历史附件补齐正确 `order_id` 和 `stage` 后，在订单阶段资料区可见。
- [ ] 迁移不复制、不移动、不重命名、不删除物理文件；迁移前后附件文件数量和文件路径保持一致。
- [ ] 迁移重复执行不会重复创建附件或改变已确认的归属。
- [ ] 订单明细、车辆、报价和其他模块附件不受影响。
- [ ] 过渡期旧订单任务资料接口和旧任务上传接口转调同一订单资料服务，不再产生新的非订单级三阶段资料。
- [ ] 无法映射的历史孤儿资料有报告且保留，不能静默删除。

## A-OSA-04：前端三个入口一致性

- [ ] 订单详情固定显示设计、制作、安装三个阶段资料区，即使对应阶段没有任务也可以上传。
- [ ] 设计任务详情调用订单级设计资料接口，制作任务详情调用订单级制作资料接口，安装任务详情调用订单级安装资料接口。
- [ ] 任务详情页不再把当前任务 ID作为附件所有权或上传必填参数；若传入，仅作为可见性校验上下文。
- [ ] 完成项目详情按订单阶段各显示一个只读资料区，不按任务数量重复显示安装资料。
- [ ] 图片显示缩略图并可点击放大；视频显示缩略图并可打开播放器；非图片文件不强制生成缩略图。
- [ ] 非图片文件显示文件名、类型、大小、上传时间，并提供可用的预览或下载操作。
- [ ] 拖拽、点击选择、批量上传、失败重试、删除确认和上传/删除后刷新均可用。
- [ ] 一个入口新增或删除资料后，其他入口刷新能看到同一结果，不产生重复记录。
- [ ] 无任务状态不显示“没有任务所以不能上传”的误导提示；完成或取消任务不锁住订单级资料。

## A-OSA-05：安全、越权和生命周期回归

- [ ] 员工不能通过订单附件接口读取自己没有订单范围的资料。
- [ ] 设计人员不能通过 `stage=production` 或 `stage=installation` 读取、上传或删除其他阶段资料。
- [ ] 删除任务后仍能从订单详情下载、删除该阶段资料；新建同阶段任务后能看到原有资料。
- [ ] 订单软删除时资料不被物理删除且不可访问；订单恢复后按原权限恢复可见。
- [ ] 任务详情和工作台仍不泄露价格字段；附件接口不成为价格绕过入口。
- [ ] 直接访问旧公开 `/uploads` 路径不会绕过新订单接口的权限设计；若现有公共路径无法立即收口，必须记录为发布阻断项或后置安全任务。
- [ ] 最近的服务日志不出现认证令牌、Cookie 或完整敏感查询参数。

## A-OSA-06：质量门禁与发布

- [ ] Alembic 升级、dry-run、回填数量核对和兼容测试通过。
- [ ] 后端目标测试和全量测试通过。
- [ ] 前端目标测试、全量 Vitest、typecheck、lint 和生产构建通过。
- [ ] `git diff --check`、接口路由唯一性检查和安全扫描通过。
- [ ] 数据库、服务、Nginx/API 健康检查通过；上传、预览、下载、删除至少各有一个真实或集成验证证据。
- [ ] 发布记录包含当前版本、迁移结果、旧接口调用观察窗口、回滚版本和未处理孤儿资料清单。
