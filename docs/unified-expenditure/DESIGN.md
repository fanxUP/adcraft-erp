# 统一支出查看设计

任务类型：功能实现；财务金额及权限风险：STRICT。授权范围为开发和验证，未授权提交或部署。

## 边界

保留 expenses、project_costs、outsource_tasks/payments、payable_payments 为唯一来源，不复制业务记录，不更改成本/应付计算或付款登记流程。不合并历史疑似重复记录，不推测付款日期，不扩展车辆、工资、采购等尚无统一关联的模块；此页面明确不是全公司完整现金流量表。

## 数据视图

- GET /expenses/ledger：经营支出、实际登记项目费用（含报价阶段真实费用）、已完成/结算外协或有付款的外协任务、未关联任务的外协付款。按业务日期筛选，累计已付不按业务日期截断；库存领用及报价预计 cost_amount 不参与。被取消/软删但仍有外协付款的任务保留财务事实并标明状态，剩余待付为零。
- GET /expenses/disbursements：有效应付付款、外协真实付款、原记录推算的登记已付/历史结清。真实流水使用 paid_at；缺日期及推算金额均单独标明待核实，不使用 created_at、cost_date、expense_date 补造日期。
- SQL UNION ALL 后统一过滤、稳定排序、分页；全量摘要由同一筛选集合后端计算，不从当前页相加。页面记录、全量摘要和未核实摘要在单条 SQL 的同一快照中读取，避免并发付款造成列表与汇总错位。相同业务只出现一次，付款拆分不重复添加业务总额。
- 日期筛选采用上海自然日，现有应付付款的 naive UTC 字段按上海转换；外协历史 paid_at 延续原 API 的本地无时区日期口径。无日期流水在日期筛选下不出现在列表；在同一非日期筛选范围下单独报告未核实金额，不能作为该期间支出。
- 项目成本旧 is_settled 且不存在任何付款历史时兼容未知日期结清；有作废历史不回退为已付。外协 paid_amount 大于实际流水汇总时差额作为待核实，不伪造逐笔记录。

## 权限与交互

入口和经营/项目数据沿用 expense:read。外协数据附加 outsource_center:read、outsource_task:read、outsource_payment:read 和 finance:view_cost，未授权数据不查询、不统计。DTO 只读；不返回银行信息。来源跳转沿用原页面入口权限，不能扩大写权限。

支出管理默认统一台账，第二标签为付款流水，保留经营支出标签及原登记/附件/编辑/删除。新视图只提供查看来源，不提供第二套修改入口。来源详情在只读抽屉中展示字段；经营记录可切换原维护标签，项目跳转原项目成本详情，外协跳转原任务/付款页面。

沿用已有主题 tokens（品牌 #2563eb、正文 #1f2937、次级 #6b7280、背景 #f5f7fa、表面 #ffffff、边框 #e5e7eb）及现有字体。主要表达是对齐金额的财务表格，口径提示紧邻汇总，不新增营销装饰或动画。筛选可换行、可键盘操作，加载/错误/空状态独立，过期响应不能覆盖新筛选结果。

## 兼容和历史风险

无 schema 迁移、无数据回填，原接口和 CRUD 保持兼容。没有实际付款日期的历史记录保留未知状态；即使新登记记录也不能把业务日期猜成实际付款日期。人工重复录入仍可能重复，需后续人工核对而非按金额自动去重。将来可另行授权显式登记首付款日期/流水。
