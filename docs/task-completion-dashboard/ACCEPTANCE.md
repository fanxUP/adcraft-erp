# TCD-P01 验收标准

## A01 统计口径和时间范围

- [ ] 员工主指标明确显示“我完成过的项目”和“我完成的明细”，不冒充整单交付。
- [ ] 管理员能区分“整单完成项目”“最终交付明细”和“完成工作明细”。
- [ ] 全部不限制时间；当月使用 `Asia/Shanghai` 的 `[月初, 下月月初)`。
- [ ] 订单完成只认当前仍为 `completed` 的最后一次完成事件；返工/退回后不残留错误完成数。
- [ ] 明细完成以 `(阶段, 订单明细)` 为工作单元，最终交付明细按明细去重。

## A02 明细完成事件和历史边界

- [ ] 每次勾选明细的状态变更为每条明细写入一条状态事件。
- [ ] 事件包含阶段、任务、订单、明细、变更前后状态、负责人快照、操作人和事件时间。
- [ ] 状态更新与事件写入同事务；任一失败都不会产生半成功状态。
- [ ] 迁移回填可识别的历史完成快照，并标记 `source=backfill`；不修改任务状态/进度。
- [ ] 没有可靠完成时间的历史记录不被伪造为当月完成，发布说明记录数据起点。

## A03 权限和员工数据隔离

- [ ] `task_completion:read` 只能查看本人范围；`task_completion:view_all` 依赖前者。
- [ ] 管理员可查看组织总计、员工分组和指定员工明细。
- [ ] 普通员工传入其他 `employee_id` 时后端返回 403，不能通过接口绕过前端限制。
- [ ] 统计范围与既有订单任务可见范围取交集；不可见订单的任务/明细不出现在统计中。
- [ ] 未绑定员工账号返回稳定空数据和大白话提示，不泄露全员统计。
- [ ] 离职员工历史数据保留原归属并显示离职标识。

## A04 API 和响应安全

- [ ] 汇总接口和分页明细接口独立，统计接口失败不影响原驾驶舱其他卡片。
- [ ] 明细接口支持全部/当月、项目/明细、阶段、员工和分页参数。
- [ ] 普通员工只能获取自己的项目/明细；管理员按员工筛选结果正确。
- [ ] 完成统计响应不包含订单总额、明细单价、小计、成本、利润等价格字段。
- [ ] 401、403、422、空数据、无绑定员工和数据库异常均有契约化处理。

## A05 员工驾驶舱体验

- [ ] 设计、制作、安装员工能在工作台切换全部/当月并看到自己的两个主指标。
- [ ] 员工明细包含项目、订单明细、阶段、任务编号、负责人和完成时间。
- [ ] 员工看不到员工分组表、其他人员筛选器和其他人的明细。
- [ ] 阶段分布能解释同一明细跨阶段分别计数的原因。
- [ ] 加载、空数据、错误重试和 390/1024/1440 宽度布局正常。

## A06 管理员驾驶舱体验

- [ ] 管理员看到组织总计和员工分组统计。
- [ ] 员工行点击后通过服务端分页查看该员工个人项目/明细，不在前端拿全量数据过滤。
- [ ] 可返回“全部人员”视图，员工筛选切换不会污染下一次全部/当月查询。
- [ ] 组织总计与员工分组、未分配桶可以核对，允许历史回填边界被明确标识。

## A07 回归和代码质量

- [ ] 后端专项测试覆盖权限、月份边界、状态回退、多选明细、换负责人、外协阻断和 legacy 任务。
- [ ] 前端全量 Vitest、Lint、TypeScript、生产构建和权限/AI 契约检查通过。
- [ ] 后端全量 pytest 通过；迁移在隔离数据库完成 upgrade/downgrade 演练。
- [ ] `git diff --check`、敏感信息扫描、依赖数量和范围检查通过。
- [ ] 真实浏览器使用管理员、设计、制作、安装和无员工绑定账号完成主流程验收。

## A08 发布与回滚安全

- [ ] 发布前完成数据库备份并记录当前代码提交、Alembic 版本和服务状态。
- [ ] 先迁移/回填，再发布后端和前端；回填结果抽样与任务详情数据核对。
- [ ] 发布后验证组织统计、本人统计、他人 403、价格字段不泄露和服务健康状态。
- [ ] 失败时可回退应用；数据库回退只删除本期新增事件表，不删除业务任务/订单数据。
