# 项目看板与项目成本部门/科室展示验收标准

## A01：字段来源、权限和队列口径冻结

- [ ] 订单和报价的部门/科室统一来源为 `business_documents.department`。
- [ ] 部门/科室为空时所有相关页面均显示 `-`，不从员工部门、客户名称或其他字段猜测。
- [ ] 项目队列只包含订单状态 `pending_confirm`、`confirmed`，不会把同一订单的设计/制作/安装任务卡误当成项目队列卡。
- [ ] 项目看板的订单队列请求继续经过后端订单读取权限；无 `order:read + order:view_price` 能力的员工不会因为本次需求获得项目队列及订单金额。
- [ ] 任务队列仍按订单任务可见范围、阶段读取权限和终态隐藏规则返回；本次不改变任务明细可见范围。

## A02：管理员项目看板显示项目队列

- [ ] 管理员进入 `/projects/board` 可以看到“项目队列”列，并位于设计、制作、安装之前。
- [ ] 项目队列卡片至少显示：订单编号、项目名称、客户名称、部门/科室；有价格权限时显示订单金额。
- [ ] 工作台和独立项目看板使用同一项目队列加载方法、同一状态口径和同一 `ProjectQueueCard`，相同数据下卡片数量与字段一致。
- [ ] 项目队列卡片点击或键盘 Enter/空格进入对应订单详情；设计、制作、安装卡片仍进入对应任务详情。
- [ ] 同一订单不会因同时存在多个阶段任务而在项目队列中重复显示；阶段卡仍可按阶段分别存在。
- [ ] 项目队列请求失败时，设计、制作、安装和完成列仍可正常加载或显示各自空态，不被队列请求拖垮。

## A03：项目成本列表显示部门/科室

- [ ] `/project-costs` 列表出现“部门/科室”列，位置在客户列之后。
- [ ] 订单来源行显示订单的 `department`，报价来源行显示报价的 `department`。
- [ ] 部门名称较长时可省略并通过 tooltip 查看，空值显示 `-`。
- [ ] 增加列不改变来源筛选、关键词筛选、状态筛选、分页、项目金额、项目成本金额和进入详情行为。
- [ ] `QuoteCostResponse` 前端类型声明 `department`，真实报价成本接口响应与类型一致。

## A04：项目成本详情显示部门/科室

- [ ] `/project-costs/:orderId` 顶部信息卡显示“部门/科室”。
- [ ] `/quote-costs/:quoteId` 使用相同位置和相同文案显示报价的部门/科室。
- [ ] 详情页直接使用已加载单据详情的部门字段，不新增逐条请求；刷新、返回、自动刷新后字段不丢失。
- [ ] 窄屏下信息卡能够换行，部门/科室不会覆盖状态、项目名称或项目成本合计。
- [ ] 空部门显示 `-`，不把成本归属的订单明细或员工部门显示成部门/科室。

## A05：权限、回归和发布前质量

- [ ] 管理员可以看到其权限范围内的项目队列、部门/科室和成本详情。
- [ ] 财务用户只按现有项目成本/财务权限访问成本页；增加部门列不扩大其订单编辑、任务处理或其他模块权限。
- [ ] 设计、制作、安装用户仍不因本次需求看到订单金额、明细单价、小计、项目成本或利润；其原有工作台/任务详情范围不变。
- [ ] 直接输入无权项目看板、订单或项目成本地址时，前端路由守卫和后端 API 均不绕过权限；不通过隐藏菜单作为唯一证据。
- [ ] 后端定向及全量测试、前端 Vitest、typecheck、lint、生产构建和差异/敏感信息检查通过。
- [ ] 本期无数据库迁移、无数据批量修改、无新依赖、无新权限码；Git 提交和服务器部署前形成可追溯验证记录。
