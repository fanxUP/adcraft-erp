# 项目看板与项目成本部门/科室展示实施计划

## 1. 范围与执行原则

本计划只处理项目队列和项目成本页面的部门/科室展示及项目看板入口一致性。项目队列卡片使用已有订单主数据；设计、制作、安装任务仍使用已有任务队列和阶段权限；项目成本计算与金额权限不变。

本任务为 `STRICT`：先建立契约测试，再实施页面改动，最后执行权限、构建和回归。本轮已完成本地业务代码实现及自动化验证；Git 提交、真实账号验收和服务器部署仍待单独执行。

当前实现状态：

- `P01` 至 `P04`：已完成本地实现。
- `P05`：已完成本地自动化验证；管理员、财务、设计、制作、安装账号的线上验收尚未执行。

## 2. 实施项

### P01：基线契约与权限边界冻结

工作内容：

- 固化当前项目看板、工作台、订单列表、报价成本列表、项目成本详情的字段来源和角色矩阵。
- 确认管理员通过现有订单队列能力查看项目队列；无订单价格查看能力的员工不请求、不显示项目队列。
- 增加或先行设计后端/前端契约测试：订单和报价均有 `department` 时能传到页面；字段为空时显示 `-`；价格、任务可见范围和成本权限没有被放宽。
- 将订单状态 `pending_confirm`、`confirmed` 作为项目队列口径，防止队列和阶段任务重复。

对应验收：`A01`。

### P02：独立项目看板增加项目队列并共用项目队列卡片

工作内容：

- 抽取共享 `ProjectQueueCard`，统一工作台和独立项目看板的订单号、项目名称、客户名称、部门/科室、订单金额和点击行为。
- 增加可复用的项目队列订单加载方法，并行取得 `pending_confirm`、`confirmed` 两类订单，按 ID 去重、按创建时间排序。
- 在 `ProductionTaskBoard.vue` 增加“项目队列”列，管理员/具备订单队列能力的账号可见；其余阶段列与完成列沿用原有权限和数据源。
- 保持项目队列卡点击订单详情，设计/制作/安装卡点击任务详情；不合并卡片实体。
- 确保项目队列请求失败不阻塞阶段任务列和完成列。

对应验收：`A02`。

### P03：项目成本统一列表增加部门/科室列

工作内容：

- 在 `ProjectCostList.vue` 的订单/报价统一表格中增加“部门/科室”列，位置放在客户之后。
- 为前端 `QuoteCostResponse` 补齐 `department` 类型；订单继续使用已有 `OrderListResponse.department`。
- 订单和报价行统一显示 `row.department || '-'`，保留 tooltip 和响应式表格行为。
- 不修改成本金额、项目成本汇总、状态筛选、来源筛选和进入详情的逻辑。

对应验收：`A03`。

### P04：项目成本详情增加部门/科室信息

工作内容：

- 在 `ProjectCostDetail.vue` 顶部订单/报价信息卡增加“部门/科室”。
- 直接使用已加载的 `OrderDetailResponse.department` 或 `QuoteDetailResponse.department`，不增加额外请求。
- 调整信息卡的换行和间距，确保桌面端、窄屏端不挤压状态和项目成本合计。
- 空部门显示 `-`；不显示员工部门，不把部门字段与成本归属混淆。

对应验收：`A04`。

### P05：全链路验证与发布前检查

工作内容：

- 执行后端契约/权限回归、前端组件/源码契约测试、typecheck、lint、生产构建和 Git 差异检查。
- 使用管理员、财务、设计、制作、安装账号验证项目队列列、部门/科室列和详情头部。
- 验证无价格权限的员工不看到项目队列订单金额；不因部门展示看到订单明细价格、成本或利润。
- 验证订单和报价部门为空、中文长文本、直接 URL、刷新和接口局部失败等场景。
- 本阶段只形成验证证据；Git 提交和服务器部署需用户另行授权。

对应验收：`A05`。
