# 用户个人设置验收标准

每个计划项对应一个主验收项。重点验证“只能改自己”“偏好跨设备持久化”“密码安全边界”和“不会影响现有业务权限”。

## A-USER-PREF-01 对应 USER-PREF-P01：入口和职责边界冻结

- [ ] 桌面端所有已登录角色都能从用户菜单进入个人中心。
- [ ] 移动端“我的”页面有个人设置入口。
- [ ] 个人中心明确区分账号信息、我的设置和修改密码。
- [ ] 管理员系统设置不再提供会被误认为全局生效的主题、字号、字重重复控件。
- [ ] 个人设置只影响当前用户，不新增角色权限，不改变业务数据范围。
- [ ] 主题、字号、字重的选项与现有系统常量一致，安全默认值为 `light-blue / 14 / 400`。

证据：页面结构检查、桌面端与移动端截图、路由/访问规则检查。

## A-USER-PREF-02 对应 USER-PREF-P02：偏好持久化和接口安全

- [ ] 数据库存在一对一 `user_preferences` 表，`user_id` 唯一且关联 `users.id`。
- [ ] 现有用户迁移后都有默认偏好记录，迁移不删除订单、任务、权限和用户数据。
- [ ] `/auth/me` 返回当前用户的完整 `preferences`，不返回密码、令牌或其他用户偏好。
- [ ] `PATCH /auth/preferences` 只能修改当前 Bearer 会话对应的用户。
- [ ] 请求中的主题、字号、字重只接受白名单值，任意 CSS 字符串和越界字号被拒绝。
- [ ] 偏好保存成功返回完整值，部分更新不会把未提交字段重置为默认值。
- [ ] 同一用户不存在重复偏好记录，重复创建采用安全的获取或更新逻辑。

证据：Alembic 迁移检查、后端 API/service 测试、越权和非法输入测试。

## A-USER-PREF-03 对应 USER-PREF-P03：密码修改和重置安全

- [ ] 用户不提供正确原密码时不能修改密码。
- [ ] 用户不能通过请求体、路径或查询参数指定其他用户作为密码修改目标。
- [ ] 新密码空值、过短、超长或与原密码相同时被服务端拒绝。
- [ ] 密码响应、操作日志、前端状态和错误日志中不出现原密码或新密码。
- [ ] 普通修改密码成功后，当前账号可以使用新密码登录，旧密码不能登录。
- [ ] 修改密码成功后清除 `must_change_password`，现有首次登录强制改密弹窗能正常结束。
- [ ] 管理员重置密码后，目标账号下次登录被要求修改初始密码。
- [ ] 设计、制作、安装、销售、财务等角色的业务权限不因修改密码而改变。

证据：认证服务/API 测试、管理员重置密码测试、敏感信息扫描。

## A-USER-PREF-04 对应 USER-PREF-P04：加载、应用和账号隔离

- [ ] 登录后主题、字号、字重按服务端个人偏好应用。
- [ ] 刷新桌面端页面后个人偏好保持不变。
- [ ] 从桌面端切到移动端或反向进入时使用同一份个人偏好。
- [ ] 用户 A 退出后，用户 B 登录不会继承用户 A 的主题或字号。
- [ ] 浏览器缓存按用户 ID 隔离，不再把未命名旧缓存作为最终数据源。
- [ ] 服务端偏好与旧缓存冲突时，以服务端偏好为准。
- [ ] 偏好加载或保存失败时，页面仍可使用安全默认/最近一次服务端值，不出现半套样式状态。
- [ ] 字号变更至少影响正文、表单、菜单、表格、标签、分页和公共页面组件的基础字号。

证据：前端 store/API 测试、登录切换测试、桌面/移动端手工验证、样式变量检查。

## A-USER-PREF-05 对应 USER-PREF-P05：设置界面和交互完成

- [ ] 桌面端提供主题预览卡、字号选择、示例文字、保存和恢复默认。
- [ ] 移动端提供可用的纵向设置面板，不要求用户必须切换桌面端。
- [ ] 选择主题或字号后能在当前页面预览，点击保存后才持久化。
- [ ] 保存中按钮禁用并有 loading，保存成功清除未保存状态。
- [ ] 保存失败时恢复最近一次服务端值，并显示用户可理解的错误提示。
- [ ] 有未保存变更离开页面时有确认提示，恢复默认不会绕过保存确认。
- [ ] 修改密码表单继续支持显示/隐藏密码、原密码校验、确认密码一致性和成功反馈。
- [ ] 深色主题下设置卡片、表单、提示、按钮和示例文字均可读，窄屏不溢出。

证据：桌面端/移动端截图、交互操作记录、前端组件契约测试。

## A-USER-PREF-06 对应 USER-PREF-P06：质量门禁和发布边界

- [ ] 后端相关测试通过，包含迁移、认证、越权和非法偏好值回归。
- [ ] 前端相关测试通过，包含 app/auth store 和个人中心/移动端设置契约。
- [ ] `npm test` 通过。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run lint` 通过。
- [ ] `npm run build` 通过。
- [ ] `git diff --check` 通过，修改文件无密码、令牌、任意 CSS 注入或危险调试代码。
- [ ] 现有价格可见性、角色权限、订单/任务数据隔离测试没有回归。
- [ ] 本阶段未未经授权执行 Git 推送或服务器部署。

证据：命令输出、差异审查、测试报告和未部署声明。
