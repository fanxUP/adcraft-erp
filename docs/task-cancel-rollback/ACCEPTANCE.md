# 任务取消改为跨阶段回退：验收标准

每项验收标准只对应 `PLAN.md` 中的一个主计划项。

## A-TRB-01：业务规则与兼容边界

对应：TRB-P01

- [ ] 能明确说明设计、制作、安装三类任务的明细操作矩阵。
- [ ] 能明确区分订单“已确认”和任务首阶段“设计”。
- [ ] 订单级“取消订单”仍可用且不被误当成明细回退。
- [ ] 历史 `cancelled` 数据不被批量改写；设计历史取消仍只读，制作/安装历史取消可由有权限用户单条恢复。

## A-TRB-02：新工作流和旧取消请求防护

对应：TRB-P02

- [ ] 新的设计明细动作中不存在“取消设计”。
- [ ] 新的制作/安装明细动作分别提供“退回设计/退回制作”，而不是取消动作。
- [ ] 旧客户端发送设计、制作、安装明细取消请求时，后端拒绝并返回大白话提示。
- [ ] 非法跨阶段状态仍然被后端拒绝，不会只依赖前端禁用按钮。
- [ ] 回退只使用对应阶段的 `change_status` 权限；没有该权限的用户不能通过接口执行回退。
- [ ] `rolled_back` 不会参与完成数量、100% 进度或下游任务自动创建。

## A-TRB-03：明细级回退事务

对应：TRB-P03

- [ ] 制作任务单击一条未完成明细“退回设计”后，只有该明细回到设计任务。
- [ ] 安装任务单击一条未完成明细“退回制作”后，只有该明细回到制作任务。
- [ ] 同一订单中其他明细的状态、执行人、进度、附件关联不发生变化。
- [ ] 目标阶段不会产生重复任务卡或重复明细关联。
- [ ] 外协进行中的明细不能回退，并显示明确阻塞原因。
- [ ] 普通员工不能回退已完成明细；高权限未开放时同样被拒绝。
- [ ] 重复提交同一个回退请求具有幂等性，不重复创建关联和日志。
- [ ] 中途失败时源阶段和目标阶段同时回滚，不留下半成功数据。

## A-TRB-04：整卡删除和设计起始规则

对应：TRB-P04

- [ ] 设计任务明细没有单独取消/删除入口。
- [ ] 无 `design_task:delete` 权限的用户看不到或不能调用设计任务删除。
- [ ] 有权限删除设计任务后，订单回到“已确认”，而不是被误改成已完成或订单级已取消。
- [ ] 删除设计任务不会把无关订单明细的下游状态重置。
- [ ] 订单确认后，设计任务是项目看板展示的首个执行阶段。
- [ ] 任务自动创建/复用不因删除或回退产生重复设计、制作、安装任务。

## A-TRB-05：详情页和列表交互

对应：TRB-P05

- [ ] 设计详情页不显示明细取消/回退按钮。
- [ ] 制作明细按钮文案为“退回设计”，安装明细按钮文案为“退回制作”。
- [ ] 单项点击只发送当前明细 ID，不会把未点击明细一起变更。
- [ ] 回退前确认框明确说明目标阶段和“其他明细不受影响”。
- [ ] 设计历史取消明细保持只读；制作/安装历史取消明细显示单条“恢复到设计/恢复到制作”入口，`rolled_back` 明细显示回退状态、目标阶段和时间。
- [ ] 权限、外协、完成限制的提示不再出现技术英文或状态码。

## A-TRB-06：回归测试与质量门禁

对应：TRB-P06

- [ ] 后端测试覆盖状态机、权限、回退事务、幂等、混合进度和历史兼容。
- [ ] 前端测试覆盖动作显示、确认操作、错误提示和单项 ID 传递。
- [ ] 通过项目现有 lint、类型检查、构建和测试命令。
- [ ] 通过差异检查，没有未授权的依赖、迁移或上传目录改动。
- [ ] 生成测试报告并记录未纳入本轮的风险。

## A-TRB-07：发布和恢复门禁

对应：TRB-P07

- [ ] 发布前有可验证的数据库/数据备份，不修改业务数据内容。
- [ ] 发布前确认历史取消数据数量和状态未被转换。
- [ ] 部署后健康检查、登录、任务列表和三类任务详情均可访问。
- [ ] 部署后至少验证制作→设计、安装→制作和设计整卡删除三条主路径。
- [ ] 发现异常时有明确的代码恢复路径，且不通过危险 SQL 逆向修复业务数据。
