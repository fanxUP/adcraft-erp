# 任务取消改为跨阶段回退：实施计划

## 1. 实施模式

- 模式：STRICT
- 风险级别：高
- 原因：涉及状态机、明细级任务链、权限、订单汇总、历史数据兼容和下游任务自动创建。
- 本计划只覆盖设计/制作/安装任务的取消替代和逐级回退；订单级取消不纳入改造。

## 2. 约束

- 不修改、不删除历史业务数据。
- 不把回退实现为普通 `change_status` 的待分配状态。
- 所有回退都以明细 ID 为边界，禁止整卡隐式全量重置。
- 后端是唯一状态规则来源，前端只负责展示可执行动作。
- 第一版回退沿用对应阶段的 `change_status` 权限，不新增回退权限码；是否允许回退仍由后端按明细、执行人、外协和完成状态校验。
- 每个计划项对应一个验收项，见 `ACCEPTANCE.md`。

## 3. 分阶段任务

### TRB-P01：冻结业务规则与兼容边界

工作内容：

- 固化设计不可取消、制作退回设计、安装退回制作的状态矩阵。
- 明确订单前置“已确认”和任务首阶段“设计”的边界。
- 盘点历史 `cancelled` 记录、订单级取消和任务级取消调用方。
- 确定历史取消不批量迁移，设计历史取消只读，制作/安装历史取消支持有权限用户逐条恢复；订单级取消保留，已完成回退默认需要高权限。

输出：业务规则常量、兼容说明、受影响接口清单。

### TRB-P02：重构工作流与服务端动作契约

工作内容：

- 从设计/制作/安装的新动作集合中移除新的明细取消动作。
- 增加服务端回退动作类型和统一错误码/大白话提示。
- 后端拒绝旧客户端对这三类任务发送新的明细取消请求。
- 将 `rolled_back` 定义为历史退出当前阶段的非执行状态，不参与完成汇总。
- 保证非法跨阶段流转仍被状态机阻断。

输出：工作流注册表、服务端动作生成器、动作 API 契约更新。

### TRB-P03：实现明细级跨阶段回退事务

工作内容：

- 增加制作→设计、安装→制作的明细回退服务和接口。
- 校验权限、可见范围、明细归属、执行人、外协阻塞和已完成限制。
- 源阶段只标记选中的明细为 `rolled_back`，目标阶段只恢复选中的明细。
- 复用或创建目标任务时避免重复任务卡和重复关联。
- 重算源任务、目标任务和订单状态/进度。
- 写入操作人、时间、原因、源任务、目标任务和明细 ID。

输出：原子事务、幂等策略、回退日志。

### TRB-P04：收敛整张任务删除和设计起始规则

工作内容：

- 设计任务只保留有权限用户的整卡删除，移除设计明细取消入口。
- 删除设计任务后回到“已确认”，清理/恢复受影响下游任务，不影响无关明细。
- 校准制作/安装整卡删除的上一阶段回退语义和权限。
- 确认订单确认后自动进入设计任务，项目看板从设计开始展示。
- 检查自动创建、复用任务、整单完成和回收站恢复逻辑的兼容性。

输出：整卡删除规则、订单状态规则、回归数据处理说明。

### TRB-P05：调整三个任务详情页和明细列表

工作内容：

- 设计明细隐藏取消/回退操作，只保留设计流程动作。
- 制作明细显示“退回设计”，安装明细显示“退回制作”。
- 操作按钮只能针对当前点击的单条明细，不读取未点击行作为批量范围。
- 回退前显示影响范围和确认提示；外协、完成、权限阻塞显示明确原因。
- 历史 `cancelled` 行默认保留历史语义；制作/安装任务对有权限用户显示“恢复到设计/恢复到制作”，只恢复当前明细，不做自动批量迁移。
- 对 `rolled_back` 行显示回退目标和时间，避免误认为已完成。

输出：设计、制作、安装详情页 UI 和动作调用调整。

### TRB-P06：建立回退与混合进度回归验证

工作内容：

- 覆盖后端状态机、权限、事务、幂等和任务汇总测试。
- 覆盖“一个订单多个明细分别处于设计/制作/安装”的混合场景。
- 覆盖已完成明细、外协进行中、历史取消、下游任务存在和重复提交。
- 覆盖前端动作显示、错误提示、确认弹窗和明细单项操作。
- 执行 lint、类型检查、构建、后端测试、前端测试和差异检查。

输出：测试报告、场景矩阵、剩余风险列表。

### TRB-P07：发布前数据与回滚门禁

工作内容：

- 实施前备份数据库和上传目录元数据，确认备份可用。
- 只读盘点现有任务状态，确认不会自动转换历史取消数据。
- 检查变更文件、依赖、迁移、权限和 API 范围符合预算。
- 先本地验证，再部署到服务器；部署后验证健康检查、接口和关键页面。
- 如出现状态异常，优先恢复代码版本，不逆向修改业务数据。

输出：发布检查单、部署证据、恢复预案。

## 4. 建议执行顺序

```text
TRB-P01
   |
   v
TRB-P02 ---> TRB-P04
   |           |
   v           v
TRB-P03 ---> TRB-P05
       \      /
        v    v
        TRB-P06
           |
           v
        TRB-P07
```

TRB-P02 和 TRB-P04 可以在规则冻结后并行分析，但服务端回退契约先于前端调整；TRB-P06 必须等待服务端和前端都完成；TRB-P07 是发布门禁，不能跳过。

## 5. 不纳入本轮的后续项

- 已完成明细的经理强制回退独立审批流。
- 回退操作的撤销/反向恢复按钮。
- 跨订单批量回退。
- 历史 `cancelled` 数据的业务迁移。
- 统一事件中心、短信、邮件、飞书通知。

上述内容进入后续 backlog，不在本次变更中顺手扩大范围。
