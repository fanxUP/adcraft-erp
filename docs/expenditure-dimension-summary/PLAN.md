# 支出总览维度汇总实施计划

## 1. 执行约束

本计划对应 `docs/expenditure-dimension-summary/DESIGN.md`。这是财务统计功能，后续实现按 `STRICT` 执行：先测试并冻结数据口径，再实现接口和页面；未经用户明确授权，不提交、推送或部署。

范围限制：只读汇总、筛选和下钻；保留现有数据来源、付款/成本写入流程及权限。不新增数据库迁移、依赖、权限码或业务数据写操作。

## 2. 实施项

### P01：维度与口径契约测试

- 定义四维分组键与展示名：项目、部门/科室、供应商/自由文本收款方、分类+来源类别。
- 定义付款日期、上海日期边界、真实付款额、付款笔数、涉及业务数、未知日期金额的口径。
- 先增加失败测试，覆盖无关联项目/供应商、空部门、同名不同 ID、相同类别跨来源、分批付款、无日期历史付款、潜在重叠不自动去重等情况。

对应验收：A01。

### P02：只读分组接口与权限

- 新增 `/expenses/summary` 查询，服务端完成授权来源裁剪、组合过滤、分组、全量汇总及分页。
- 补充部门过滤和供应商自由文本收款方过滤；定义稳定分组键以便下钻。
- 分组金额严格只合计所选期间中有实际付款日期的付款记录；分组和明细复用同一权限及日期过滤逻辑。
- 保持已有台账/付款记录接口响应兼容，不触碰来源表写流程。

对应验收：A02。

### P03：维度汇总界面与明细下钻

- 在支出总览加入“维度汇总”视图，提供付款日期、来源、关键词和折叠的四维筛选。
- 增加项目/部门/供应商收款方/分类分组切换，显示期间金额、付款笔数、业务数和比例。
- 点击分组加载匹配付款明细，可打开来源；筛选变化同步刷新全量汇总与下钻明细。
- 保留原有台账列、付款记录列、经营支出登记入口和权限控制。
- 实现空、加载、错误、移动端及键盘访问状态。

对应验收：A03。

### P04：金额守恒、权限和回归验证

- 用真实 PostgreSQL 测试聚合 SQL、跨页统计、维度下钻一致性和上海自然日边界。
- 验证用户无外协完整权限时，外协数据不会影响摘要、分组数、笔数、比例或明细。
- 执行后端/前端定向及全量测试、前端 lint/typecheck/build、差异与敏感信息检查。
- 不修改生产业务数据、不执行数据库迁移；部署需单独获得用户明确授权并执行发布预检。

对应验收：A04。

## 4. 完成状态

当前状态：P01–P04 已完成。本地实现新增只读 `/expenses/summary` 和“维度汇总”界面，支持项目、部门/科室、供应商/收款方、来源内分类分组，按真实付款日期统计并下钻查看付款记录。

- 数据口径：只计入有实际付款日期的确认付款；摘要由完整筛选集计算，不随分页变化；下钻复用相同日期、来源和维度键。
- 维度边界：未关联项目、未填写部门/收款方有明确分组；部门值键与未填写哨兵不冲突；供应商按 ID、自由文本收款方按去首尾空格后的名称分组；分类键包含来源类别。
- 安全与范围：沿用现有支出权限和外协权限裁剪；没有数据库迁移、依赖、权限码或来源写入。
- 测试证据：后端 `pytest -q` 1422 passed、3 skipped；发布前后端定向回归 5 passed；前端 Vitest 225 passed，`npm run lint`、`npm run typecheck`、`npm run build` 均通过；本地 PostgreSQL 集成测试使用临时 schema 并自动清理。
- 发布证据以 GitHub 发布提交和服务器的 `.deployed-commit` 为准；本计划不把部署前的本地状态当成发布完成证据。
