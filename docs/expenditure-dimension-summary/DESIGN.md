# 支出总览维度汇总设计

## 1. 任务类型、风险与模式

- 任务类型：现有支出总览的增量统计与交互设计。
- 风险：STRICT。汇总涉及实际付款、业务总额、权限裁剪及潜在重复成本；错误口径会影响财务判断。
- 本文保留需求与数据口径基线；实施状态和发布证据见本目录的 `PLAN.md`、`ACCEPTANCE.md`。
- 后续实现模式：STRICT，先冻结金额口径和维度键，再做后端汇总、界面和独立验证。

## 2. 当前基线

- `frontend/src/views/payments/ExpenseList.vue` 的“支出总览”目前有“支出台账”和“付款记录”两个视图；经营支出登记维护仍在原入口。
- `frontend/src/components/payments/ExpenditureTable.vue` 已展示项目、部门/科室、供应商/收款方和分类；前端现有筛选主要是来源、关键词和付款日期。
- 后端 `/expenses/ledger` 与 `/expenses/disbursements` 已支持部分来源、分类、供应商、单据和日期过滤，但部门过滤尚未建立；部分已支持筛选参数也未由当前组件统一传递。
- 台账的每行代表一项来源业务，业务总额、累计已付和剩余待付是当前状态快照；付款记录每行代表一笔付款/历史付款事实。
- 台账日期按来源的最后付款日期筛选，但金额仍是当前业务汇总；付款记录的日期筛选才适合表达期间现金支出。页面现有说明已提示两种口径不同。
- 项目和部门来自关联的 `BusinessDocument`；经营支出可保存自由文本收款方；供应商可通过统一供应商档案关联；项目成本分类与外协任务类型不是同一套主数据。
- 外协只在账号同时拥有外协中心、任务、付款和成本查看权限时进入支出总览。

## 3. 目标、假设与非目标

### 3.1 本期目标

在“支出总览”增加“维度汇总”视图，允许用户按项目、部门/科室、供应商/收款方、分类查看所选期间的实际付款汇总，并从汇总项下钻到对应付款记录。提供四个维度筛选，支持组合筛选与查看匹配付款明细。

### 3.2 默认业务假设

本方案将“支出汇总”解释为帮助用户回答“所选期间的支出分别花在什么项目、部门、收款方和分类上”。因此汇总金额以已确认付款日期的真实付款记录为准；不把当前业务总额、未付余额、业务日期或台账最后付款日期混作期间付款额。台账继续提供当前业务总额、累计已付和剩余待付。

如果用户还要按这些维度统计“当前业务总额/累计已付/剩余待付”，可在后续另做明确标注的“当前应付快照”，不要与期间现金支出合并成一个数字。

### 3.3 非目标

- 不修改付款登记、成本登记、删除、回收站或原始业务数据。
- 不新增付款、不回填或推测历史付款日期，不把业务日期当成付款日期。
- 不自动合并同名供应商/收款方，不按金额或项目自动去重潜在重复成本。
- 不纳入没有统一关联和权限契约的库存领用、工资、车辆等模块；不宣称是公司完整现金流量表。
- 不新增数据库字段/迁移、依赖、权限码或新的财务写入口；不在本期做导出、预算、利润或跨期同比分析。

## 4. 推荐信息架构

### 4.1 视图与筛选

在支出总览现有标签后增加第三个标签：

`支出台账 | 付款记录 | 维度汇总`

维度汇总顶部使用一行主筛选：付款日期范围、支出来源、关键词；默认日期范围为本月截至今日，并明确展示起止日期。高级筛选折叠呈现：项目、部门/科室、供应商/收款方、分类。每次筛选变更重置分页，并同步刷新汇总和明细，避免两个区域口径不一致。提供一键重置。

初始默认选中“项目”维度。维度切换为：

`项目 | 部门/科室 | 供应商/收款方 | 分类`

一次展示一个分组维度，避免四张大表同时堆叠。用户可先组合过滤，再选择按哪个维度分组。

### 4.2 汇总卡片与分组表

页面顶部汇总卡片：

- 期间实际付款金额
- 付款笔数
- 涉及业务数

分组表列：维度名称、期间实际付款、付款笔数、涉及业务数、占当前筛选付款金额比例。默认期间实际付款倒序，支持分页；金额右对齐并使用现有财务数字格式。页面标题/说明始终标明“按付款日期统计”。

分组名称规则：

- 项目：优先显示“单据编号 + 项目名称”；无关联单据显示“未关联项目”。同名项目以单据 ID 区分，避免把不同业务单据误并。
- 部门/科室：读取关联单据原值；空值为“未填写”。仅清理首尾空白，不猜测、不从员工或客户字段补部门。
- 供应商/收款方：有供应商 ID 时按 ID 分组；无 ID 时按原始收款方文本分组。相同显示名但不同供应商 ID 不自动合并。
- 分类：沿用现有显示映射；为避免经营支出、项目成本、外协任务的同名类别被误认为统一分类，分组键包含来源类别，必要时显示来源副标签。

### 4.3 下钻明细

点击汇总行后，在当前页面显示该分组对应的付款明细（可用行内展开或侧边抽屉，优先复用现有只读来源抽屉和表格样式）。明细显示付款日期、项目/单据号、部门/科室、收款方、分类、付款金额、付款编号/历史标识及来源状态；可继续打开原来源页面。下钻继承日期、来源、关键词和其他维度筛选，用户可清除当前分组返回完整汇总。

移动端避免新增固定宽度造成页面整体横向溢出：分组表局部横向滚动或切换为信息卡片；筛选器换行并保持可触控、键盘可访问。空、加载、错误状态分别表达。

## 5. 金额、日期和去重口径

- 期间实付 = 选定上海自然日期范围内、具有已确认实际付款日期的付款记录金额之和。
- 无实际付款日期的历史推算金额不进入期间合计；不使用创建日期、业务日期、成本日期或任务完成日期补日期。按用户已确认的简化方向，不在支出总览重复显示待核实金额卡片；新汇总视图仅用简短口径说明标明“只统计有实际付款日期的记录”。
- 汇总与下钻明细必须使用相同来源权限、日期过滤和维度键；合计不得从当前页分页行相加。
- `expense:read` 沿用现有支出入口权限。外协源仅在当前所有必需外协权限齐全时参与汇总；无权限账号的项目数、金额、笔数和比例都不能通过聚合结果泄露外协数据。
- 潜在项目成本/外协重复仍按来源记录分别展示，不自动去重。摘要说明纳入来源范围，并可用现有来源筛选查看；只有经过明确人工审查并另行定义纳入政策后，才能改变统计口径。
- 不在此视图混入业务总额和待付余额。需要查看当前应付状态时回到支出台账，避免把当前快照误读成期间支出。

## 6. 接口与实现边界

建议新增只读汇总查询接口 `GET /expenses/summary`，参数包含：`group_by`（project/department/supplier/category）、分页、关键词、来源、付款日期范围，以及四个可选维度过滤值。汇总由数据库对完整匹配集合分组并分页，不可在前端只对已加载的 20 行分组。

- 维度汇总的四个高级筛选采用受长度限制的文本包含匹配：项目编号/名称、部门/科室、供应商/收款方、原分类或分类显示名；来源由独立来源筛选控制。分组身份仍使用项目单据 ID、供应商 ID 或自由文本收款方键、部门规范化文本和“来源类别 + 原分类”键，不以模糊匹配合并不同主体。
- 汇总响应包含本次查询全量的期间实际付款额、付款笔数、涉及业务数，以及当前页分组行和分页信息。
- 分组明细可复用付款记录查询接口；为支持精确下钻，补充部门过滤和明确的维度组键参数，或由汇总响应提供可直接复用的过滤键。
- 参数白名单、UUID、日期范围、最大页大小和访问权限均在服务端校验。
- 不增加主数据表或数据库迁移；如果现有投影无法稳定表达分组键，先在只读查询层形成明确键，不改变来源模型。

## 7. 风险与控制

| 风险 | 控制 |
|---|---|
| 将业务总额误读为期间支出 | 新视图仅按真实付款日期汇总；当前业务金额留在台账 |
| 聚合只基于当前页导致金额偏小 | 后端在分页前完成分组和全量摘要；测试跨页总额守恒 |
| 权限裁剪只应用在明细，没有应用在汇总 | 汇总查询和明细共用来源权限过滤；测试无外协权限时所有聚合值均不含外协 |
| 同名供应商、项目或类别被误合并 | 分组键使用主键/来源类别；自由文本只按原值，不推断实体等价 |
| 部门/科室历史缺失 | 显示“未填写”，不从员工部门推导或回填 |
| 项目成本与外协业务潜在重叠 | 不自动去重，保留来源筛选和透明口径 |
| 桌面宽表在手机溢出 | 局部横向滚动或卡片模式；检查键盘操作、焦点及触控区域 |
