# 员工建档自动开通账号实施计划

## 1. 范围与状态

- 类型：身份主数据与登录账号生命周期改造。
- 模式：`STRICT`。
- 当前状态：`implemented`，代码和本地验证已完成；生产备份、迁移干跑和发布后检查待执行。
- 目标：新建员工自动生成以工号为用户名的登录账号；用户管理不再提供普通新增用户入口；既有任务执行、权限和历史引用不回归。

## 2. 计划项

### P01：现状盘点与迁移干跑

工作内容：

- 统计员工、用户、已绑定账号、未绑定员工、遗留用户和工号/用户名冲突。
- 检查 `employees.user_id` 的一对一约束、软删除边界和当前迁移版本。
- 生成只读干跑报告，不修改数据。
- 明确 `admin` 和其他系统账号的保留清单。

主要验收：`A01`；迁移脚本已实现，生产报告待发布前执行。

### P02：账号开通服务与事务边界

工作内容：

- 建立内部账号开通服务，统一负责员工、用户、偏好和角色写入。
- 新建员工时使用最终工号作为 `users.username`，自动写入 `employees.user_id`。
- 增加初始密码策略和 `must_change_password` 强制改密。
- 对工号重复、角色无效、用户名冲突、数据库异常执行整事务回滚。
- 修复工号生成的并发冲突保护。

主要验收：`A02`；实现和后端全量测试已完成。

### P03：登录、停用和删除安全边界

工作内容：

- 登录页和登录提示使用“工号”。
- 认证与当前用户解析同时排除软删除账号。
- 员工离职、停职、停用或软删除后阻断登录和任务执行；让旧 token 失效。
- 恢复在职不自动恢复账号，保留管理员显式启用边界。
- 保留 `admin` 等系统账号的明确例外。

主要验收：`A03`；实现和相关回归测试已完成，线上登录/旧 token 检查待发布后执行。

### P04：关闭普通用户创建接口

工作内容：

- 删除 `UserManage.vue` 的“新增用户”按钮、创建对话框和前端创建调用。
- 后端撤销或阻断 `POST /api/v1/users/`，提示应从员工管理中新建。
- 将 `user:create` 视为过渡期兼容/废弃能力，不允许绕过员工流程产生新员工账号。
- 更新页面能力说明和接口契约文档。

主要验收：`A04`；页面和后端契约测试已完成。

### P05：员工管理与用户管理界面调整

工作内容：

- 员工新建页去除手工绑定已有账号的选择器。
- 增加角色、初始密码和自动开通结果展示；员工编辑页显示账号状态但不直接改角色。
- 用户管理改为展示“工号”，保留角色、启停、密码重置和查询。
- 桌面/移动个人中心把“用户名”改为“工号”。
- 搜索支持工号和员工姓名，系统账号显示为系统账号。

主要验收：`A05`；前端类型、测试、Lint 和构建已完成。

### P06：历史账号迁移与补建账号方案落地

工作内容：

- 先对已绑定账号执行冲突检查和备份。
- 在不更换用户 UUID 的前提下，把确定的一对一账号用户名改为员工工号。
- 对没有账号的在职员工生成待处理清单；经管理员确认后分批补建。
- 对无员工绑定的旧账号保留或停用，不根据姓名/部门自动猜测归属。
- 迁移脚本支持 dry-run，遇到冲突时整体阻断。

主要验收：`A06`；只读/冲突阻断迁移脚本已实现，生产干跑和授权执行待发布前完成。

### P07：后端、前端和业务回归验证

工作内容：

- 覆盖员工创建、账号创建、失败回滚、登录、首次改密、角色、停用、删除和恢复场景。
- 验证任务分配、任务执行、完成统计仍能通过原 user UUID 找到有效员工。
- 执行后端专项/全量测试、前端类型检查、Vitest、Lint 和生产构建。
- 检查敏感信息、接口绕过、旧 token、软删除账号和权限越界。

主要验收：`A07`；本地全量验证已完成。

### P08：发布、备份、回滚和上线后检查

工作内容：

- 发布前备份数据库和上传目录元数据，记录当前 Alembic head 与应用提交。
- 先发布兼容代码，再执行经确认的数据迁移；不把大批量补建账号隐藏在启动脚本中。
- 上线后检查登录、首登改密、员工/用户列表、任务分配和管理员系统账号。
- 失败时优先回退应用版本；数据迁移须有单独恢复方案，不用危险 SQL 盲目反向覆盖。

主要验收：`A08`；待生产主机连通、备份和发布后回读。

## 3. 建议改动范围

预计涉及：

- 后端：`employee_service`、`user_service`/内部 provisioning service、`auth_service`、认证依赖、员工/用户 schema 和 API、迁移/干跑脚本、相关测试。
- 前端：员工管理、用户管理、登录页、桌面/移动个人中心、用户/员工 API 类型和页面能力描述。
- 文档：本目录的设计、计划、验收和依赖关系文件，以及上线迁移记录。

不应在本任务中修改订单、任务状态机、工资、考勤、报价、财务或历史业务表的语义。

## 4. 发布顺序

1. P01 只读盘点和冲突报告。
2. P02-P05 完成兼容代码和自动化测试。
3. 在隔离数据库做迁移 dry-run、升级/回滚演练。
4. 备份生产数据库后发布代码。
5. P06 只执行已确认的历史迁移批次。
6. 执行 P07/P08 的线上健康检查并记录剩余遗留账号。

任何冲突、缺少初始密码分发方案或用户要求改工号的情况，都应在 P01/P06 阶段停下来人工确认，不自动猜测。
