# 员工建档自动开通账号验收标准

本文件对应 `PLAN.md` 的 P01-P10。代码实现和本地自动化验证已完成；涉及生产数据、备份和线上行为的项目必须在发布窗口继续验收。

## A01：现状盘点和迁移门禁

- [ ] 生成员工/用户/绑定/未绑定/遗留账号/工号冲突的只读报告。
- [ ] 报告明确列出 `admin` 等系统账号，不把系统账号自动当成员工账号。
- [ ] 发现工号与现有用户名冲突时，迁移 dry-run 明确失败且不改数据。
- [ ] 生产迁移前完成数据库备份，并记录备份可恢复性检查结果。

## A02：新建员工自动生成用户

- [ ] 新建在职员工后，在同一事务内生成一个用户并写入 `employees.user_id`。
- [ ] 新用户的技术用户名值等于员工工号，用户列表可显示该工号。
- [ ] 员工、用户、用户偏好或角色写入任一步失败时，员工和用户都不落库。
- [ ] 工号重复、用户名冲突和并发生成冲突均返回可理解的中文错误，不覆盖已有账号。
- [ ] 新账号默认 `must_change_password = true`，明文初始密码不写库、不进日志、不进入操作审计快照。
- [ ] 新建停职/离职/停用档案时账号存在但不可登录。

## A03：登录和账号生命周期

- [ ] 登录页显示“工号”，员工可使用工号和初始密码登录。
- [ ] 首次登录或管理员重置密码后必须先完成改密，改密前不能访问业务接口。
- [ ] 软删除用户、停用用户、软删除员工、停职/离职员工不能新建会话。
- [ ] 员工状态变化后旧 token 不能继续访问受保护业务；历史任务和审计数据保留。
- [ ] 员工恢复在职后账号不会未经管理员确认自动恢复启用。
- [ ] `admin` 等明确系统账号仍能按既有规则登录和管理系统。

## A04：用户管理不再创建普通账号

- [ ] 用户管理页面没有“新增用户”按钮、创建用户对话框和普通创建表单。
- [ ] 直接调用 `POST /api/v1/users/` 不能创建新账号，并返回“请在员工管理中新建员工”等明确提示。
- [ ] 用户管理仍可查看账号、编辑角色、启停账号和重置密码。
- [ ] `user:create` 权限不会成为绕过员工建档流程的后门。

## A05：页面和接口契约

- [ ] 用户管理列表将“用户名”显示为“工号”；关联员工账号显示员工工号，系统账号有明确标识。
- [ ] 员工新建页不再允许选择已有用户手工绑定；保存成功后能看到自动创建的账号结果。
- [ ] 角色选择与密码策略在员工新建流程中有清晰文案和校验。
- [ ] 桌面个人中心、移动个人中心和登录页的用户可见文案统一使用“工号”。
- [ ] 用户/员工列表支持按工号、姓名搜索，且不泄露密码或不必要的权限细节。

## A06：历史账号迁移

- [ ] 已绑定员工的用户 UUID、角色、密码哈希、任务/订单/日志引用保持不变。
- [ ] 已绑定但用户名不等于工号的记录，只有在无冲突时才改成工号。
- [ ] 无账号在职员工、无员工遗留账号和冲突记录分别形成清单，不自动猜测和覆盖。
- [ ] 补建历史账号前明确初始密码分发和强制改密策略，且支持分批执行。
- [ ] 迁移脚本提供 dry-run，升级/失败/恢复路径经过隔离数据库演练。

## A07：业务和安全回归

- [ ] 绑定员工的设计、制作、安装任务执行和完成统计仍按原 user UUID 正常工作。
- [ ] 任务分配列表不出现未绑定、停用、离职或删除员工。
- [ ] 旧用户名、工号重复、空工号、无效角色、账号停用和越权创建均有测试覆盖。
- [x] 后端全量测试、前端类型检查、Vitest、Lint 和生产构建通过；发布后仍需做线上关键接口回读。
- [ ] 安全检查确认没有明文密码、敏感信息日志、接口绕过或删除重建账号行为。

## A08：发布和上线后验证

- [ ] 发布前记录代码提交、数据库版本、备份文件和迁移 dry-run 结果。
- [ ] 线上只执行已确认的数据迁移批次，不在启动脚本中隐式批量开通账号。
- [ ] 上线后验证员工自动创建账号、工号登录、首次改密、角色权限、停用和管理员账号。
- [ ] 上线后检查员工列表、用户列表、任务分配和完成统计的关键接口。
- [ ] 发布失败时能回退应用版本；数据迁移恢复方案已单独确认，不依赖不可逆的盲改 SQL。

## A09：异步序列化与实时连接安全

- [ ] 单据更新、订单联系人更新、部门/工资/请假/考勤规则更新和高空车/人员软删除在 `flush()` 后序列化不触发 `MissingGreenlet`。
- [ ] 以上回归路径均有自动化测试，测试覆盖对象刷新或安全重载，而不是依赖隐式懒加载。
- [ ] 通知和聊天 WebSocket 使用受控子协议承载令牌，连接 URL 不再携带 JWT；旧客户端查询参数兼容期不写入 Nginx 访问日志。
- [ ] WebSocket 建连同时校验用户启用、员工状态、删除状态和 `token_version`，失效账号不能继续建立实时连接。
- [ ] 鉴权失败不记录令牌或完整连接 URL，且不改变现有消息/通知业务数据。

## A10：修复发布后关键路径复验

- [ ] 发布前记录当前线上提交、配置备份、服务状态和无迁移声明，并保留应用版本回滚点。
- [ ] 上线后健康检查、登录鉴权、成本保存/凭证上传、通知 WebSocket 和聊天 WebSocket 关键路径通过。
- [ ] 上线后检查服务日志无新增 `MissingGreenlet`、未处理 WebSocket 鉴权异常或凭证上传 500。
- [ ] 发现发布异常时按上一已知提交和 Nginx 配置备份回退，不删除历史日志或业务数据。
