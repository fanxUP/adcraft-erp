# EUB-P01 员工档案与登录账号绑定实施计划

## 1. 范围与风险

- 类型：身份映射、后台管理和数据库完整性约束。
- 模式：STRICT。
- 风险：中高。绑定错误会影响任务可见性、任务执行归属和个人完成统计；索引迁移需要确认现有数据无重复。
- 当前状态：代码、隔离迁移演练、线上备份、迁移和健康检查全部完成。

## 2. 实施分解

### P01：现状与数据约束

- 保留 `employees.user_id -> users.id` 外键。
- 新增未删除员工范围内的部分唯一索引。
- 迁移前检查重复绑定并在发现重复时阻断迁移，不自动选择或覆盖员工。

### P02：后端绑定服务与接口

- 增加可绑定用户选项查询。
- 增加绑定/解除绑定服务和接口。
- 校验账号启用状态、员工在职状态、重复绑定和软删除边界。
- 补充员工列表和用户列表的轻量关联展示字段。

### P03：管理页面

- 员工管理增加账号列和绑定选择器。
- 用户管理增加关联员工列。
- 保持原有权限：员工管理绑定操作仅管理员可执行，用户自身不能绑定其他身份。

### P04：回归验证

- 先写重复绑定、未绑定、解除绑定、无效账号和列表展示测试。
- 执行后端专项/全量测试、前端类型检查、Vitest、Lint、构建。
- 做静态差异、秘密扫描和迁移 SQL 检查。

### P05：发布准备（已完成）

- 发布前备份数据库，检查现有 `employees.user_id` 重复和索引状态。
- 在测试副本执行 upgrade/downgrade 演练。
- 线上先执行迁移，再发布应用；失败时按部署基线回滚应用，索引回滚前先确认没有依赖新约束的数据。

## 3. 文件范围

只修改 `.vibe` 约束、员工/用户关联所需的后端模型、接口、服务、前端管理页、回归测试和本目录文档；不修改业务数据和无关模块。
