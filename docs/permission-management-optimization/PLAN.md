# 权限管理优化

## 目标与边界

用户要求优化项目权限功能。本轮属于安全敏感维护，使用 STRICT 方式，围绕现有权限目录和校验器改善角色授权、用户分配和边界一致性。保留现有权限码、权限包、数据范围、敏感字段与冲突策略，不重置角色或业务数据，无依赖及数据库迁移。

预算：最多 15 个修改文件、4 个新文件，1 项兼容 API 扩展（角色列表增加内置角色标记），新增测试失败、类型错误、Lint 错误均为 0。

## 已确认问题

- 取消前置权限后，旧界面立即补回，无法一次撤销依赖权限。
- 异步保存使用可变的当前角色，等待响应时切换角色可能错写本地状态。
- 切换角色、离开页面没有未保存保护；目录和权限包加载失败被静默忽略。
- 页面全选包含超级管理员能力，掩盖普通角色的权限冲突；技术权限码和过时模块名影响配置效率。
- 前端只隐藏管理员和经理的删除按钮，但后端禁止删除所有内置角色。
- 用户管理在角色选项加载失败或尚未完成时，编辑会把原角色映射为空数组并允许提交。
- 角色调整仅检查启用用户；停用用户重新启用而不传角色时，没有再次检查已有权限组合。

## 实施

1. 按模块分组、支持关键词与已选/敏感筛选，显示中文前置权限。模块内批量勾选排除系统超级管理能力；该能力须单独勾选并明确提示。窄屏用角色下拉选择代替长列表，宽屏保留并排角色列表。
2. 勾选自动补齐目录依赖，取消前置能力同步取消其依赖项；已停用能力只能保留或移除，不能新增。
3. 保存前调用现有服务端预览，显示新增、移除、冲突和影响用户数，确认后按固定角色及权限快照保存；增加加载失败重试及未保存保护。
4. 用服务端内置角色标记统一编辑/删除提示；用户编辑必须完整加载并解析原有角色，失败阻止提交。
5. 角色预览与保存复用校验、一次读取关联用户，并包括停用账号；重新启用账号时验证现有或本次提交的最终权限组合。

## 验收与结果

已覆盖传递依赖加入/移除、停用权限、模块批量操作、预览失败不写入、保存失败保留草稿、异步请求角色隔离、目录失败保护、停用用户组合与启用校验。

- 前端全量测试：42 个文件、303 项通过。
- 后端权限、角色、用户及认证专项：213 项通过。命令：`python3 -m pytest -q tests/test_*permissions.py tests/test_role_permission_guards.py tests/test_auth_service.py tests/test_user_service.py tests/test_manager_role.py`。
- 前端 `npm run lint`、`npm run build`（含类型检查与包大小检查）通过；首屏 gzip 为 158.08 KiB，限额 200 KiB。
- 用本地隔离的模拟 API、内置角色与真实权限目录检查了角色选择、模块搜索和窄屏布局；预览不连接生产数据。预览服务与临时配置已清理。
- 手工检查安全边界、`git diff --check` 和范围检查通过：12 个源码/文档文件，其中 4 个新增；另外维护本地忽略的 2 个 `.vibe` 范围/预算记录。
- 使用现有权限目录与服务端校验器；未增加依赖、数据库迁移或批量授权操作。

验证范围为本地自动化及模拟数据页面检查；尚未进行生产多账号业务验收。

本轮完成代码优化及验证；提交、推送、部署以用户后续指令为准。
