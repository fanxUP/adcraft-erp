# TAV-P01 订单任务可见范围与任务详情权限实施计划

## 1. 范围与风险

- 类型：RBAC、订单级行可见性和任务操作归属改造
- 风险：高。错误的查询条件可能造成订单任务越权，错误的角色基线可能让执行人员看到任务列表。
- 实施模式：STRICT
- 当前状态：代码实现和本地自动化验证完成，待数据库迁移、浏览器验收和发布；本轮不部署服务器、不修改业务数据。

## 2. 实施分解

### P01：数据模型和迁移

- 新增 `order_task_assignees` 表、唯一约束和索引。
- 将模型加入 Alembic metadata。
- 不回填既有订单；没有关联行即保持全员可见。

### P02：权限基线

- 新增 `task_queue:read`、三类任务 `*:list` 和 `*:assign`、`order:task_assign`。
- 设计、制作、安装角色保留工作台与本阶段详情/状态能力，不获得任务列表和分配能力。
- 销售/管理员拥有维护订单任务可见范围和阶段任务负责人的显式权限。

### P03：后端可见性

- 任务仓储列表和详情统一追加订单员工可见性条件。
- 工作台、订单明细选项、任务附件上传/删除使用同一可见性判定。
- 只使用在职、启用、未删除且绑定当前登录账号的员工记录放行。

### P04：订单任务分配

- 增加员工选项接口、订单当前可见员工查询接口和多选保存接口。
- 空数组清除限制；重复、无效、停用或未绑定账号的员工拒绝保存。
- 维护接口不授予订单价格或订单编辑权限。

### P05：任务详情负责人和状态归属

- 增加三类任务的专用负责人接口，避免“拥有分配权限但没有编辑权限”的用户被通用编辑接口挡住。
- 普通员工状态变更时忽略不了的负责人伪造请求由后端拒绝，并强制解析当前登录在职员工。
- 继续保留订单明细勾选范围和外协阻断等现有业务规则。

### P06：前端入口与交互

- 任务列表导航/路由改为显式 `*:list` 权限。
- 任务详情按分配权限显示可编辑负责人；普通员工只显示只读归属提示。
- 订单详情增加多选员工卡片。
- 按用户拥有的阶段列表权限逐个请求订单任务，避免一个缺失权限的阶段导致其他阶段也加载失败。

### P07：验证与代码审查

- 后端：TAV 专项测试、任务服务回归、附件回归、全量 pytest。
- 前端：权限/导航专项测试、全量 Vitest、类型检查、Lint、生产构建。
- 静态检查：差异空白、迁移头、未授权路由、敏感字段和越权附件通道。
- 浏览器验收重点：管理员/销售、设计、制作、安装和无员工绑定账号各一组。

### P08：发布准备（本轮不执行）

- 发布前备份数据库并记录 Alembic 当前版本、代码提交和服务状态。
- 先迁移再发布后端，再发布前端，最后按角色做工作台、详情和外协可见性冒烟。
- 本轮不执行服务器迁移、重启、Git 推送或部署。

## 3. 不在本轮范围内

- 不改变设计、制作、安装的状态机和进度汇总。
- 不删除历史任务、订单、订单明细或外协记录。
- 不新增短信、邮件、飞书通知。
- 不实现复杂的部门、客户、区域层级权限。
