# UI/UX 全栈一致性实施计划

本计划只描述实施顺序和边界；本轮不执行代码修改。

## 1. 计划项

### UIX-P01：基线盘点与视觉/交互规范冻结

目标：建立页面、组件、状态、权限、接口和截图基线。

工作内容：

- 生成路由-页面-角色-主动作矩阵。
- 盘点页面骨架、表格、弹窗、表单、加载/空态/错误态。
- 采集桌面端 1440/1024 和手机端 390 宽度的核心流程截图。
- 固定状态语义、颜色语义、金额/日期/数字格式和文案风格。
- 标记允许保留的业务特例，不把所有差异都当成不一致。

### UIX-P02：设计 Token 与通用页面原语

目标：把现有主题能力变成可执行的语义 token 和页面级组件。

工作内容：

- 新增语义 token 层，保留旧变量兼容映射。
- 统一按钮、标签、表格、分页、卡片、弹窗、抽屉和表单密度。
- 建立 `AppPage`、`PageHeader`、`PageToolbar`、`DataTableShell`、`StatusTag`、`ProgressBar`、状态反馈组件。
- 提供一个仅用于开发验证的组件样例页或测试入口，不新增生产导航。

### UIX-P03：应用壳层、导航与权限可见性统一

目标：桌面端、移动端和不同角色看到的导航、页面标题、返回行为、按钮能力一致。

工作内容：

- 统一默认布局的标题区、内容区、侧栏收缩、移动端顶部和面包屑/返回。
- 建立资源-动作-角色-对象状态能力矩阵。
- 将路由角色判断、导航过滤和页面按钮能力分层；后端权限为最终事实。
- 统一无权限、未登录、强制改密、过期登录和 403 的交互反馈。

### UIX-P04：后端 API、状态视图与错误契约收口

目标：让 UI 所需的状态、进度、可操作性和失败原因由稳定的数据契约提供。

工作内容：

- 收口列表、详情、错误和分页响应模型。
- 统一状态 view model：`code / label / tone / terminal`。
- 统一动作能力：`allowed / disabled_reason / requires_confirmation`。
- 统一时间、金额、ID、字段错误、并发冲突和 request id。
- 优先覆盖订单、订单明细、设计/制作/安装任务、外协和项目成本接口。
- 保留旧接口兼容适配器，禁止在本阶段大规模破坏性改 URL。

### UIX-P05：核心链路试点迁移

目标：用一个真实业务闭环验证全栈一致性。

范围：工作台、项目看板、订单列表/详情、设计/制作/安装任务、项目成本列表/详情。

验收场景：

- 一个订单的不同明细可同时位于设计中、制作中、安装中。
- 任务处理只对勾选的订单明细生效。
- 不属于当前任务阶段、已完成或外协进行中的明细不可选，并显示原因标签。
- 任务进度是本任务关联明细的聚合进度；达到 100% 或终态后从看板隐藏。
- 工作台与项目看板显示同一个任务进度。
- 成本登记支持明细列表、多选、关联成本和整单/明细互斥校验。

### UIX-P06：销售与财务模块波次迁移

目标：把经过试点验证的模式迁移到客户、报价、合同、应收、支出、对账和外协付款。

重点：表格筛选与分页、金额格式、批量操作、表单校验、导出、权限和财务敏感数据。

### UIX-P07：资源、AI、人事与系统模块迁移

目标：完成车辆、高空作业车、AI、人事和系统管理页面的壳层、反馈、状态和权限统一。

允许保留：车辆/高空作业车的日历、照片、移动操作等业务专用布局；但不能绕过统一的错误、权限、按钮和状态语义。

### UIX-P08：跨端 QA、清理与发布

目标：确认一致性没有造成业务回归，清除已替换的死代码和重复样式。

工作内容：

- 桌面端、平板宽度、手机端核心流程回归。
- 键盘焦点、对比度、禁用原因、屏幕阅读器名称和错误反馈检查。
- 删除已被公共组件替换的重复状态映射和局部样式。
- 执行前端构建、类型检查、Lint、单元测试、后端全量测试和 API 契约测试。
- 记录变更范围、回滚点和上线后的观察指标。

## 2. 推荐执行顺序

```text
P01
├── P02 ── P03 ──┐
└── P04 ─────────┼── P05 ── P06 ── P07 ── P08
                 └───────────────
```

P02 和 P04 可以在 P01 完成后并行；P05 必须同时依赖 UI 原语、权限呈现和后端契约。

## 3. 优化项落位

下面的优化不新增独立大阶段，而是作为对应波次的必交付项；P0 未完成时不得把核心波次标记为完成。

| 编号 | 优化主题 | 优先级 | 责任计划项 | 完成判据 |
|---|---|---:|---|---|
| OPT-01 | 状态、进度、动作能力单一事实来源 | P0 | P01、P04、P05 | 试点页面不再各自维护同一业务状态映射；接口和 UI 语义一致 |
| OPT-02 | 批量选择与写操作安全 | P0 | P04、P05、P08 | 只更新当前勾选集合；后端校验阶段/终态/外协/权限；重复提交和 409 有测试 |
| OPT-03 | 加载、空态、错误、权限、冲突和成功反馈 | P1 | P02、P03、P05 | 核心页面六类状态均有统一表现，不重复弹错 |
| OPT-04 | 响应式与可访问性 | P1 | P03、P05、P08 | 1440/1024/390 及键盘、焦点、对比度、触控目标通过 |
| OPT-05 | 样式与组件维护成本 | P1 | P02、P05、P06、P07、P08 | 核心波次使用 token/原语；替换后的重复样式和映射有删除清单 |
| OPT-06 | 请求、分页、缓存和列表性能 | P1 | P04、P05、P08 | 无明显重复请求/N+1；变更后按服务端事实刷新；大列表有分页边界 |
| OPT-07 | 文案、金额、日期和数量格式 | P1 | P01、P02、P05、P06 | 词典和格式化规则在列表/详情/看板/移动端复用 |
| OPT-08 | 安全和敏感信息治理 | P0 | P03、P04、P08 | 无敏感日志；后端最终授权；上传/导出/外链仍经权限校验 |

## 4. 变更控制

- 每个计划项只对应一组可审查的文件/模块，不跨波次顺手重构。
- 每个页面迁移必须有迁移前后截图或明确的不可截图原因。
- 每次合并只做一个业务波次，避免 token、接口和页面同时大范围变动而无法定位回归。
- 新增公共组件前先确认至少有三个页面共享同一结构；单页特例留在页面内。
- 任何状态规则改变必须同步后端服务、Pydantic schema、前端类型、组件和测试。
- 优化项必须绑定到具体计划项和验收证据；发现不属于当前波次的改进，登记到 backlog，不在当前分支顺手扩 scope。

## 6. 执行状态

UIX-P01 至 UIX-P08 已在当前复合工作树完成实施与验证。各阶段证据分别记录在 `P01_EVIDENCE.md` 至 `P08_EVIDENCE.md`；P08 另提供 `RELEASE_CHECKLIST.md`，包含正式发布前的备份、健康检查、观察指标和回滚步骤。

本轮完成的是发布前质量收口，不等同于已经上线：当前工作树仍有未提交变更，实际 commit、产物摘要、备份位置和部署窗口必须在用户授权发布时补录并执行。
