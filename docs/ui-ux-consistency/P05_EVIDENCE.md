# UIX-P05 实施证据：订单、任务与成本核心链路迁移

## 1. 结论

UIX-P05 已完成核心链路的第一轮迁移：工作台、项目看板、订单列表/详情、设计/制作/安装任务列表与详情、任务处理明细、外协展示和项目成本页面，开始统一消费服务端提供的 `status_view`、`progress_pct`、`capabilities` 与明细阻塞原因。

本阶段保持 API URL、数据库结构、任务阶段规则、成本金额事实和授权边界不变。前端的状态映射只保留为旧接口兼容回退；服务端返回的状态、终态和动作能力优先级更高。

## 2. 本阶段交付

### 2.1 订单状态语义

- `backend/app/domain/presentation.py` 增加订单状态的统一 `StatusView`，覆盖草稿、待确认、已确认、设计中、制作中、安装中、已完成和已取消。
- `business_document_service` 在订单列表和详情响应中输出 `status_view`；原始 `status` 保留，兼容旧调用方。
- 订单列表、订单详情、项目概览以及项目成本列表/详情优先使用服务端状态标签和色调，金额、回款、成本和毛利事实未改变。

### 2.2 工作台与项目看板

- 工作台和项目看板均使用任务队列的 `taskProgress`，不再分别读取设计/制作/安装的独立进度字段。
- `isTaskVisible` 优先使用服务端 `status_view.terminal` 判断终态隐藏，再以进度 100% 作为兼容回退；因此已完成或已取消任务不会继续出现在未完成看板中。
- 任务卡片统一使用 `StatusTag` 和 `ProgressBar`，工作台与独立项目看板显示相同的任务进度语义。

### 2.3 设计、制作、安装任务

- 三类任务的列表和详情页统一使用服务端 `status_view`，统一使用共享 `StatusTag` 和 `ProgressBar`。
- 删除了三个任务列表页各自维护的状态颜色、状态文字和进度裁剪函数，避免页面之间出现同一状态不同文案或色调。
- 任务详情继续把 `task.capabilities` 传给任务处理卡片；服务端能力只用于展示对象当前是否可操作，不替代后端授权和业务校验。

### 2.4 订单明细多选与阶段阻塞

- `TaskOrderItemLinkCard` 的勾选状态优先使用 `item.capabilities.select.allowed`，兼容旧字段 `item.can_select`。
- 不可选明细展示服务端 `disabled_reason`，并同时展示当前阶段标签、当前任务状态标签和任务进度。
- 制作、安装任务遇到进行中的外协明细时，继续显示外协阻塞标签；完成操作只允许作用于已勾选明细，外协完成前不能推进该明细进入下一阶段。
- 任务状态变更优先使用 `task.capabilities.change_status` 和 `disabled_reason`，历史终态仍保持只读。

### 2.5 外协和项目成本

- 外协任务当前状态列表使用服务端 `status_view`；取消、撤回等能力字段继续由服务端提供。
- 项目成本页面使用成本记录的 `status_view` 和结算能力；整单成本、订单明细成本的金额归属与互斥事实规则没有在本阶段改动。

## 4. 范围与审查

### 4.1 范围

- 当前复合工作树统计：41 个已跟踪文件发生变更 / 上限 70；30 个新增文件 / 上限 32。
- P05 新增的页面范围仅包含工作台、项目看板、订单、设计/制作/安装任务、外协、项目成本及其契约测试和证据文档。

### 4.2 架构审查

- 服务端 `status_view` 是展示语义的首选来源；前端默认映射仅用于兼容旧响应，不参与任务完成、阶段推进或权限判定。
- 任务队列进度、明细状态、外协阻塞原因和成本结算能力继续由服务端事实计算；页面只负责展示和提交用户选择。
- 任务明细的批量完成入口保留勾选集合，未勾选明细不会被加入状态变更请求。
- `capabilities` 明确是 UI 可操作性提示，最终授权仍由路由依赖、服务校验和数据库事实负责。
