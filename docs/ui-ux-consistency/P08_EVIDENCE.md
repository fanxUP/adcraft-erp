## 2. 浏览器与可访问性复核

### 2.1 真实浏览器记录

测试页面：`http://127.0.0.1:4173/login`，使用 Codex In-app Browser 现场复核。登录凭证没有在浏览器中提交；受保护业务路由使用源码契约、组件测试和 API 契约测试覆盖，避免为了视觉验收传输未经授权的凭证。

| 视口 | 结果 | 现场记录 |
| --- | --- | --- |
| 1440 × 900 | PASS | `scrollWidth=1440`、`scrollHeight=900`，登录卡片和主要操作可见 |
| 1024 × 768 | PASS | `scrollWidth=1024`、`scrollHeight=768`，无页面溢出 |
| 390 × 844 | PASS | `scrollWidth=390`、`scrollHeight=844`，无横向/纵向溢出；用户名、密码和登录按钮可见 |

移动端交互目标复核：输入外层 `.el-input__wrapper` 为 268 × 40px，登录按钮为 268 × 40px，达到本阶段 40px 触控目标基线。键盘顺序已现场复核为“用户名 → 密码 → 登录”，焦点不会跳过主要操作。浏览器 `error`/`warning` 日志为空。

本次修复的实际问题是 `BlankLayout` 的 `min-height: 100vh` 与内边距叠加造成的纵向溢出，以及移动登录容器重复设置 `min-height: 100vh` 造成的窄屏溢出。修复分别落在 `BlankLayout.vue` 的盒模型和 `LoginView.vue` 的移动样式中。

### 2.2 静态可访问性契约

- `tokens.scss` 和 `MobileLayout.vue` 保留明确的 `:focus-visible` 样式。
- `StatePanel` 使用 `aria-live` 提示加载、空态和错误变化。
- `ProgressBar` 暴露 `aria-valuenow`，`StatusTag` 暴露可读的 `aria-label`。
- 统一 UI 质量测试固定 1440/1024/390 三个视口、40px 触控目标和 WCAG 对比度计算。
- 禁用、错误和敏感写操作继续由页面状态、后端能力契约和确认交互共同表达；前端标签不替代后端授权。

## 3. 死代码与重复样式清理

清理范围均有页面引用和路由证据，没有删除业务专用布局：

- 删除已经迁移到公共页面原语后的 `.page-header`、`.search-bar` 和旧页面外层样式，覆盖 AI、AI 模型中心、高空作业车、系统、外协、车辆、客户、报价、支出和债务页面。

- 保留矩阵、报表、移动安装、照片、AI 卡片和报价编辑器等有明确业务密度或设备特征的专用布局，仅统一外层标题、反馈、权限和操作位置。
