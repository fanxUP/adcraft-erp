# UIX-P03 实施证据：应用壳层、导航与权限可见性

## 1. 结论

UIX-P03 已完成。本阶段只处理前端应用壳层、导航过滤、路由级访问兜底、移动端底栏语义和无权限反馈，没有修改后端授权、API、数据库、业务状态规则或部署配置。

本阶段的权限边界明确为：

```text
前端访问矩阵 = 页面可见性和导航体验的兜底
后端权限与对象状态校验 = 最终授权事实
```

前端角色矩阵不能替代后端授权；P04 仍需接入服务端返回的资源/动作能力和统一 403 错误契约。

## 2. 已完成内容

### 2.1 单一的页面访问矩阵

- 新增 `frontend/src/config/access.ts`。
- 导航项和路由守卫共用 `AccessKey -> 角色集合`，不再分别维护 `navigation.ts` 的 `roles` 和路由守卫的临时判断。
- 页面可读角色与导航/执行入口角色可以不同：例如销售/财务可读取订单，销售/设计可读取部分任务，但导航入口仍只对负责执行该模块的角色显示。
- 路由名、页面标题、智能工具入口和角色可见性均集中登记。
- 保留旧 `route.meta.roles` 作为额外兜底条件，避免管理路由的历史配置失效。
- 未登记的路由不会因为前端矩阵缺失而被错误拦截；后端仍负责最终拒绝。

### 2.2 导航与直接 URL 访问一致

- `frontend/src/config/navigation.ts` 改为使用 `accessKey`。
- 桌面侧栏、智能工具下拉入口和路由守卫使用同一套页面访问规则。
- 用户直接访问无权页面时，路由跳转至 `/forbidden`，不再静默跳回工作台。
- 新增 `frontend/src/views/ForbiddenView.vue`，使用 P02 的 `StatePanel` 展示原因和明确的返回动作。

### 2.3 桌面壳层统一

- `DefaultLayout` 增加当前页面标题，侧栏切换按钮补充可访问名称。
- 侧栏、顶部栏、弹出菜单、内容区和品牌标记改用 P02 语义 token。
- 智能工具按角色过滤，避免看到入口后再落到无权限页。
- 仍保留通知、聊天和 AI 助手的现有业务行为；未把前端角色矩阵扩展成按钮写权限。

### 2.4 移动壳层统一

- `MobileLayout` 的底部导航改为语义化 `nav + button`。
- 当前页增加 `aria-current="page"`，支持键盘 Enter/Space 默认按钮行为和可见焦点。
- 底部导航存在时才预留安全区空间，子页面不会额外留下固定底部空白。
- 移动壳层背景、文字、边框、激活色和焦点样式使用语义 token。

## 3. TDD 证据

先添加 `frontend/src/config/access.test.ts`，确认访问矩阵不存在时测试失败；随后实现最小访问矩阵并接入导航/路由。

覆盖行为：

- 登录后的通用页面可访问。
- 制作角色可访问制作页面，销售角色不可访问制作页面，管理员可访问制作页面。
- 路由守卫和导航共享同一访问键体系；读取权限和执行入口权限可以分层，不把只读用户误当成执行用户。
- 历史 `meta.roles` 作为额外限制仍然生效。
- 页面标题未知时有稳定的应用壳层回退文案。
- 无权角色不会看到智能工具入口。
