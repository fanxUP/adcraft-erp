# UIX-P06 实施证据：销售与财务模块波次迁移

## 1. 结论

UIX-P06 已完成。客户、报价、合同、应收、支出、对账、成本欠款和外协付款页面已迁移到 P05 验证过的统一页面壳层、状态展示、金额格式和反馈模式；销售与财务对象由服务端优先提供 `status_view`，旧 `status` 仅作为兼容回退。

本阶段没有修改 API URL、数据库模型、迁移、存储、通知、部署脚本或依赖清单，也没有改变既有金额事实规则、收款/结清校验和后端最终授权。

## 2. 本阶段交付

### 2.1 页面壳层与反馈

- 客户列表、报价列表、合同列表、支出列表、对账单列表、成本欠款列表和外协付款列表统一使用 `AppPage`、`PageHeader`、`PageToolbar`、`DataTableShell` 和错误重试反馈。
- 客户详情、合同详情、对账单详情统一使用 `AppPage`、`PageHeader`，主数据加载失败时显示可重试的 `StatePanel`。
- 应收管理统一使用页面标题、筛选工具栏和两组数据表状态壳层：客户欠款与收款记录分别覆盖加载、空态、错误和重试；收款记录分页放入共享表格页脚。
- 表单提交继续保留原有 loading、成功提示和成功后刷新；已有 API 错误拦截器仍负责最终错误提示。

### 2.2 状态语义

- `backend/app/domain/presentation.py` 增加报价、合同、收款、对账单的 canonical `status_view` 构造器。
- 报价、合同、收款、对账单 schema 增加向后兼容的 `status_view`；对账单和成本欠款增加动作 `capabilities`。
- 成本欠款列表直接消费服务端 `status_view` 和 `capabilities.settle`，不可结清时展示服务端原因；前端没有把隐藏按钮当作授权。
- 应收内的订单、报价、合同、收款嵌套列表优先使用 `status_view`，旧字段只作回退。

### 2.3 金额与筛选

- 新增 `frontend/src/utils/format.ts` 的 `formatMoney`、`formatNumber` 和 `formatPercent`，统一人民币前缀、负数、空值、两位小数和百分比边界。
- 销售与财务页面的金额、合计、付款记录、欠款、合同/报价选项均使用 `formatMoney`；面积等非金额计算仍保留业务所需的小数格式。
- 修复应收管理筛选项加载后客户选项未写入响应式列表的问题，订单和客户筛选可以正常同步使用。
