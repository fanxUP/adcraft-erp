## R01：统一报价转换与订单金额

**影响范围：** 常规报价转单、订单编辑预览/保存、合同项目金额、验收、应收、成本利润及打印。隔离用例已证实 900 元订单被预览为 1,000 元、差额 0。

**建议方案：**

1. 明确订单继续保留报价的优惠和税费。转单复制小计、优惠、税率、税额等财务字段，使用一套 Decimal 计算函数。
2. 订单编辑中承载这些字段；预览“修改前”从实际存储金额和有效收款读取，“修改后”使用统一公式计算。校验总额、余额、优惠和税额之间的关系。
3. 将金额变化纳入现有关联预览、签名和变更批次；合同、验收和报表使用同一结果。已经确认的财务/交付事实按原有复核规则保留。
4. 扫描所有历史来源报价和订单的差异，输出待核对清单。只在有明确来源证据的情况下回填，保留旧值与操作日志。

**验收：** 普通、优惠、含税、优惠加税、已收款、有关联合同/验收等组合均验证。相同内容保存不改变金额；900→1,000 的真实变更必须明确显示 +100。

## R02：统一经营报表日期和欠款定义

**影响范围：** 工作台、日报、月报、财务中心、应收、客户欠款排行和导出。

**建议方案：**

1. 实际收款统一按 `paid_at`；登记时间保留用于审计和“本期登记”查询。缺日期记录明确单列，不用登记时间推测付款时间。
2. 统一业务时区及历史无时区列的解释；金额流量区间全部使用 `[start, next_start)`，订单 Date 列采用对应的日期半开区间。
3. 将“本月新增订单金额”“本月实际收款”“这些订单当前未收”“全部合同未收”分别定义。欠款从合同/分配或订单余额计算，消除跨期收款的错误相减。
4. 与财务中心共享查询/聚合函数，统一页面名称、打印和导出口径；用当前 3 笔补录收款作为只读对账样本。

**验收：** 补录、跨日、跨月、跨年、作废、合同级未分配收款及零点边界下，各页面同一指标一致。10 月不包含 11 月 1 日，历史日期修正后可追溯。

## R04：统一附件上传和访问控制

**证据：** Nginx 当前对 `/uploads/` 直接公开提供文件；应用的静态挂载也没有对象授权。本地未登录请求 HTML 附件返回 200、`text/html`，未附加隔离 CSP。AI 图片、验收和 CDR 等上传仍有整文件读取路径。

**建议方案：**

1. 建立附件资源 ID→业务对象→权限检查的下载入口。Nginx 改为 internal 文件区，由授权后的 `X-Accel-Redirect` 返回；打印、预览需要的临时分享用短期、有范围的签名链接。
2. 对旧路径建立兼容映射，检查订单、任务、财务、人事等所属对象权限；迁移期间保护现有附件和打印链接。
3. 汇总上传策略：按业务允许类型，检查扩展名、MIME/签名，限制文件和请求大小，流式写入，失败清理临时文件。
4. HTML、SVG 等主动内容按业务需要禁用内联或在隔离来源/受限预览中展示；普通下载设置合适的 `Content-Disposition` 和响应头。

**验收：** 未登录或无对象权限的请求被拒绝；合法预览、打印和下载正常；超限上传返回 413 且无残留；旧附件可授权访问。

方案参考 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)，实际策略需要结合设计图、现场照片和财务凭证的业务格式。

## R05：补齐聊天的会话和业务对象权限

**证据：** [推荐接口](/Users/estefan-macworkstation/Downloads/ERP/backend/app/api/conversations.py:660) 直接通过消息仓库读取指定会话，之前没有成员校验；搜索和卡片路径没有统一复用订单/任务可见范围。

**建议方案：**

1. 提取共用会话成员检查，覆盖消息推荐、详情、分享、输入状态、已读等 HTTP/WebSocket 入口。
2. 业务检索、卡片生成与重新读取均复用现有 `AuthorizationPolicy`，检查资源权限、任务可见范围、单据类型和软删除状态。
3. 保留现有价格脱敏；资料可见权限与价格权限分别检查。对越权返回统一的 403/404，不在提示中泄露私有会话信息。
4. 为已存储旧卡片建立读取时授权和脱敏规则；避免历史消息成为绕过业务权限的出口。

**验收：** 两个不共享会话的用户不能相互读取/影响会话；设计、制作、安装、销售、财务及管理员的搜索与卡片结果符合业务可见范围；越权负面用例覆盖 HTTP 和 WebSocket。

## R06：统一业务编号分配

**证据：** [编号生成器](/Users/estefan-macworkstation/Downloads/ERP/backend/app/services/number_generator.py:9) 多数前缀采用 max+1；隔离库两个独立事务得到同一个订单号。EMP 分支已使用事务锁，可参考其保护方式。

**建议方案：**

1. 统一按单据类型和编号日期分配计数，采用事务锁/计数表或数据库序列；保留现有历史编号及唯一约束。
2. 明确编号日期的时区，处理高位流水号和旧前缀兼容。不要依靠字符串倒序推断任意位数流水号。
3. 在完整事务内处理冲突和重试；创建动作增加幂等键，避免用户重试导致重复单据。

**验收：** 多连接并发创建订单、收款、付款、外协和成本无重号、无丢单；回滚和跨日不破坏编号唯一性；历史编号继续可查。

## R07：统一事务与通知时点

**影响：** [转单](/Users/estefan-macworkstation/Downloads/ERP/backend/app/services/business_document_service.py:1318)、[通知服务](/Users/estefan-macworkstation/Downloads/ERP/backend/app/services/notification_service.py:68) 等内部 `commit()` 会提前结束调用方事务；后续错误可能令用户看到失败而部分业务已落库。

**建议方案：**

1. 为一次业务操作确定一个提交责任方，底层服务以 flush 返回结果。
2. 将通知和 WebSocket 推送安排在事务提交成功后；需要可靠重试时采用轻量 outbox。
3. 使订单、任务、财务、审计和变更批次原子完成；保持现有幂等、防超付和并发版本校验。

**验收：** 在转单、任务分配、付款、审计写入和序列化前后注入故障，验证完整回滚或可确认的成功状态；失败操作不提前发送成功通知。

## R14：统一密码长度与哈希兼容策略

**证据：** [密码策略](/Users/estefan-macworkstation/Downloads/ERP/backend/app/core/password_policy.py:4) 接受最多 128 个字符，[哈希函数](/Users/estefan-macworkstation/Downloads/ERP/backend/app/utils/security.py:9) 直接调用 bcrypt。当前 bcrypt 5 对 73 字节 ASCII、25 个中文字符（75 字节）的合成输入均抛出 `ValueError`，这些输入却能通过前置策略。见 [复现](/Users/estefan-macworkstation/Downloads/ERP/docs/project-audit-2026-10-26/evidence/password-policy.json)。

**建议方案：**

1. 短期让创建、改密和登录的限制与算法一致，按 UTF-8 字节长度做清晰提示，覆盖中文及组合字符。避免静默截断密码。
2. 如需继续支持完整的 128 字符，采用支持该范围的版本化密码哈希方案；评估 Argon2id 等实现、依赖及资源参数。
3. 旧 bcrypt 哈希继续按明确的兼容规则验证，在成功登录或重置时升级；为历史长密码用户设计可控恢复方式，保留 token 失效机制。

**验收：** ASCII/中文/组合字符边界一致；合法的新密码可以创建和登录；旧账号兼容验证通过；不记录明文密码，也不因后端依赖升级改变密码含义。
