# 订单业务下单日期验收标准

每项验收对应 `PLAN.md` 中一个主计划项。

## A-OBD-01：规范、权限与数据模型

- [ ] 订单模型有 `order_date: date | None`，报价模型复用表字段但报价业务值为空。
- [ ] 订单详情/列表/引用返回 `order_date`，同时保留 `created_at`。
- [ ] 存在 `order:change_date` 权限；权限依赖包含 `order:read`，默认仅管理员/销售角色获得。
- [ ] 创建订单和两条转订单链路初始化北京时间业务日，订单号不由后续日期修改重算。

## A-OBD-02：迁移与历史数据回填

- [ ] 迁移只新增 `business_documents.order_date`、索引和订单非空约束，并包含可逆 downgrade。
- [ ] 回填只作用于 `doc_type='order'`，报价不被填入订单日期。
- [ ] 回填表达式和时区假设可审查；未执行生产迁移前不修改线上数据。
- [ ] 迁移源码测试、离线 SQL 生成和现有迁移链检查通过。

## A-OBD-03：预检、确认、并发与审计

- [ ] 没有 `order:change_date` 权限不能访问写接口。
- [ ] 原因为空、日期未变化、未来日期、订单不存在或版本过期时后端拒绝。
- [ ] 已完成/已取消订单没有超级管理员权限时拒绝；有收款/成本/已确认对账单命中时预检标记高风险且正式提交必须确认。
- [ ] 正式提交重新锁订单、重算预检上下文、校验签名和版本；旧预检/篡改目标日期不能提交。
- [ ] 重复提交同一 `preview_id` 幂等，不重复生成版本或操作日志。
- [ ] 审计记录包含前后日期、不可变 `created_at`、操作者、原因、影响目录和 `change_type=order_date_change`。
- [ ] 任务、付款、成本、验收和附件字段不因日期变更而被写入或重算。

## A-OBD-04：业务消费者切换

- [ ] 订单列表和日报/月报按 `order_date` 统计和排序，而不是 `created_at`。
- [ ] 客户账期计算和已确认对账单覆盖判断使用订单业务日期。
- [ ] 验收单订单日期显示 `order_date`；系统创建时间仍可单独追溯。
- [ ] 任务/付款/成本/附件的事件时间查询保持原字段。

## A-OBD-05：前端入口与影响提示

- [ ] 订单列表展示“下单日期”和“系统创建时间”两个不同字段。
- [ ] 有权限用户能在订单详情编辑下单日期、填写原因、查看变更前后和风险提示。
- [ ] 高风险变更显示明确确认项；无权限或锁定状态不显示可用编辑入口。
- [ ] 保存成功后刷新订单详情，错误提示不会误导用户认为 `created_at` 被修改。

## A-OBD-06：测试、门禁和交付

- [ ] 后端重点/全量测试通过，前端测试、类型检查和构建通过。
- [ ] `git diff --check`、范围检查、敏感信息扫描和质量门禁有新鲜执行证据。
- [ ] 迁移发布前有副本 dry-run、备份、锁风险、回滚和上线后查询核对方案；本次实现阶段不执行生产部署。

验收限制：页面截图只能证明显示；日期语义、审计不可变性、并发保护和关联事实不变必须由后端测试/数据库证据证明。
