# 订单业务下单日期实施计划

任务模式：STRICT。目标是让订单业务日期可受控修正，同时保持系统创建时间和关联事实不可篡改。

## P-OBD-01：规范、权限与数据模型

- 增加 `order_date` 字段、业务日期初始化函数和独立 `order:change_date` 权限。
- 更新订单列表/详情/引用类型，不改变既有 `created_at` 字段语义。

验收：A-OBD-01。

## P-OBD-02：迁移与历史数据回填

- 增加 1 个 Alembic 加法迁移。
- 历史订单从 `created_at` 回填业务日；报价保持空值。
- 建立订单日期索引和订单非空约束，提供可逆 downgrade。

验收：A-OBD-02。

## P-OBD-03：预检、确认、并发与审计

- 增加订单日期预检和正式修改服务/API。
- 实施原因、权限、未来日期、状态锁、高风险确认、乐观锁、行锁、签名凭证和幂等重放。
- 保存版本快照和操作日志；不修改订单号、任务、付款、成本或附件事实。

验收：A-OBD-03。

## P-OBD-04：业务消费者切换

- 订单列表按 `order_date` 排序。
- 经营报表、客户账期逾期、已确认对账单覆盖判断、验收订单日期改用业务日期。
- 保留系统创建时间和各业务事件时间的原有语义。

验收：A-OBD-04。

## P-OBD-05：前端入口与影响提示

- 订单列表同时显示“下单日期”和“系统创建时间”。
- 订单详情增加日期编辑入口、原因填写、影响预检确认和高风险提示。
- 前端只做显示/交互判断，后端权限和状态校验保持最终权威。

验收：A-OBD-05。

## P-OBD-06：测试、门禁和交付

- 先写失败用例，再完成最小实现并重跑回归。
- 覆盖模型/迁移源码、服务权限与状态、并发/签名/幂等、报表、验收、前端类型和组件行为。
- 执行后端全量测试、前端测试、类型检查、构建、diff/敏感信息/范围检查；迁移只做本地离线 SQL 检查，不触碰生产数据库。

验收：A-OBD-06。

## 非目标与后续项

- 不允许直接修改 `created_at`，不提供 SQL 直改入口。
- 不允许通过订单日期回写订单号日期段。
- 不改变付款、成本、任务、验收和附件的真实发生时间。
- 后续如需批量历史日期校正，另立带审批和数据核对的批处理任务。
