# 任务按状态批量选择验收标准

每个计划项对应一个主验收项，验收重点是“分类选择便利”不能破坏“只处理已勾选明细”。

## A-STAGE-SEL-01 对应 STAGE-SEL-P01：分组规则准确

- [ ] 设计任务将 `pending/designing` 显示为“待分配/设计中”。
- [ ] 制作任务将 `pending/in_progress` 显示为“待制作/制作中”。
- [ ] 安装任务将 `pending/assigned/in_progress` 显示为“待分配/已分配/安装中”。
- [ ] 未关联且处于当前任务阶段、后端允许选择的明细进入当前任务的待处理分类。
- [ ] 设计 `pending_review/revision`、制作 `rework`、安装 `pending_acceptance`、已完成、已取消、不可关联和无效阶段明细不进入快速选择组。

证据：分组辅助函数测试、状态矩阵测试、组件源代码检查。

## A-STAGE-SEL-02 对应 STAGE-SEL-P02：全选控件清晰可用

- [ ] 三类任务的订单明细列表上方出现各自状态分类全选框。
- [ ] 每个全选框显示当前分组可选明细数量。
- [ ] 全部选中显示选中状态，部分选中显示半选状态，未选中显示空状态。
- [ ] 分组没有可选明细时对应控件禁用，不能选择已完成或不可选明细。
- [ ] 任务处理中、历史只读和窄屏场景下控件状态与布局正确。
- [ ] 现有平铺明细列表、行字段、状态标签和排序不发生无关变化。

证据：组件测试、桌面/窄屏截图或浏览器操作记录、`npm run typecheck`。

## A-STAGE-SEL-03 对应 STAGE-SEL-P03：选择范围安全

- [ ] 点击某组全选只增加该组可选明细，不清除另一组已选明细。
- [ ] 取消某组全选只移除该组明细，不影响另一组选择。
- [ ] 手工勾选/取消后，全部全选框和“已选数量”即时同步。
- [ ] 全选动作不调用保存关联接口、不直接提交状态、不自动完成任务。
- [ ] 状态变更事件只传递当前 `selectedItemIds`，未选明细不会进入请求。
- [ ] 同时选择两组时仍由现有混合状态工作流限制可执行目标，不绕过后端规则。

证据：选择集合单元测试、事件参数测试、任务状态流转回归测试。

## A-STAGE-SEL-04 对应 STAGE-SEL-P04：边界与既有规则不回归

- [ ] 外协任务进行中的明细仍显示外协标签，快速选择不绕过其 `can_select` 结果。
- [ ] 已完成、已取消明细仍不可选，且不会被分组全选选中。
- [ ] 刷新明细后旧选择被清理，新的分组数量和三态按最新数据重新计算。
- [ ] 任务状态变更成功后重新加载明细，选择集合不会残留旧 ID。
- [ ] 现有逐条勾选、变更状态、回退和外协完成限制测试全部通过。

证据：前端全量测试、任务处理回归测试、API 请求参数断言。

## A-STAGE-SEL-05 对应 STAGE-SEL-P05：质量门禁通过

- [ ] `npm test` 通过。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run lint` 通过。
- [ ] `npm run build` 通过，首屏包体不超过既定预算。
- [ ] `git diff --check` 通过，未出现无关文件修改或死代码。
- [ ] 变更未包含数据库迁移、生产数据修改或未经授权的部署操作。

证据：命令输出、Git 差异、提交记录和交付说明。

## 验收限制

截图可以证明控件显示、数量、三态和布局，但不能单独证明后端最终只更新选中明细；提交范围必须通过前端事件/API 参数测试和后端既有校验共同证明。
