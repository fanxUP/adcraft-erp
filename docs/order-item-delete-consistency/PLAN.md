# 订单明细删除与三阶段任务一致性实施计划

## 1. 实施模式和边界

- 模式：STRICT。
- 风险：高。
- 目标：将订单明细删除收敛为一个可预检、可确认、可回滚、可审计的事务，统一处理设计、制作、安装三类任务关联和进度；订单没有有效明细时自动进入回收站。
- 本计划只覆盖订单明细删除及其联动，不改变订单级人工取消的业务含义。
- 默认只做逻辑删除/逻辑解除关联；财务事实、任务审计、订单阶段附件和已完成事实保留。
- 每个计划项对应一个主验收项，详见 `ACCEPTANCE.md`。

## 2. 稳定业务决策

1. 删除最后一条有效订单明细不再被 `LAST_ITEM` 阻止；在已收款金额约束通过时，订单自动进入回收站。
2. 某个阶段任务为空，不等于订单为空；只有订单所有有效明细为 0 才回收订单。
3. 任务当前关联在业务上删除，底层 link 保留 `removed` 快照；不物理删除任务历史。
4. 被删除的明细不参与任何设计/制作/安装任务进度、完成判定、工作台项目队列和当前完成统计。
5. 同一任务内未删除明细的状态、进度、执行人和附件/外协状态不被重置。
6. 订单阶段附件是订单级源头资料，删除一条明细时不按文件名猜测，也不删除整组附件。
7. 已付款、已验收、已结算、外协进行中的事实默认阻断或保留复核，不用普通“确认删除”静默抹除。
8. 三类任务使用一个共享删除/重算服务，通过 `task_type` 配置状态差异；不在三个 API 中复制三套逻辑。

## 3. 实施项

### OID-P01：现状契约、数据盘点和失败用例冻结

工作内容：

- 固化现有订单明细删除、预检、确认、订单回收站和任务聚合调用链；
- 盘点 `BusinessDocumentItem`、三类任务、`TaskOrderItemLink`、旧 `order_item_id`、`TaskItemStatusLog`、外协、验收、成本和订单阶段附件的真实关联；
- 记录现有 `LAST_ITEM` 阻断和“软删除但任务 link 仍可能参与聚合”的问题；
- 建立删除单条、删除任务内部分明细、删除全部明细、跨批次删空订单四类基准场景；
- 明确不改变订单级人工取消和报价硬删除。

对应验收：A-OID-01。

### OID-P02：任务关联生命周期和任务范围模型

工作内容：

- 给 `TaskOrderItemLink` 增加 `link_status`、`removed_at`、`removed_by`、`removed_reason` 及索引；
- 给设计、制作、安装任务增加 `scope_status`、`scope_closed_at`、`scope_closed_reason`；
- 编写 Alembic 迁移，已有 link 默认 `active`，不批量改写业务状态；
- 增加统一的 `active_task_item_link` 查询条件，过滤 removed link 和 voided order item；
- 处理现有 `_sync_task_order_item_links` 的重建逻辑，不能因为正常任务重新同步而把 removed 历史行物理抹掉；
- 保持旧 `task.order_item_id` 字段兼容，先定义清理/回填策略，不在本轮删列。

对应验收：A-OID-02。

### OID-P03：删除影响预检和确认契约

工作内容：

- 扩展现有订单明细删除预检，按明细精确返回三个阶段任务 link、旧直接引用、外协、验收和成本记录；
- 返回每条关联的处理动作：移除当前关联、软取消计划、解除草稿引用、保留事实、阻断；
- 返回删除后有效明细数、订单金额、已收/未收金额、是否自动回收；
- 继续使用订单版本、`preview_id`、`plan_hash`、过期时间和高风险确认，服务端重新签名关联目录；
- 预检不修改任何数据，目录变化或订单版本变化必须重新预检。

对应验收：A-OID-03。

### OID-P04：实现统一订单明细删除事务

工作内容：

- 在订单服务中增加统一的 `delete_order_item_with_task_relations` 编排服务；
- 锁定订单和目标明细，重新校验权限、预检凭证、订单版本、目标明细仍为 active 和阻断条件；
- 将订单明细标记 `voided`，清除旧任务直接 `order_item_id`，将三类任务 link 标记 `removed` 并保存删除快照；
- 只处理当前目标明细，禁止把同订单其他明细隐式加入删除集合；
- 处理未开始外协、草稿验收、成本明细归属等可自动处理项；
- 已付款、已验收、已结算或外协进行中的关联按预检规则阻断或保留待复核；
- 写订单变更版本和操作日志；任何一步失败时整个事务回滚；
- 同一预检批次重复提交保持幂等。

对应验收：A-OID-04。

### OID-P05：三阶段任务和订单聚合重算

工作内容：

- 实现统一 `recalculate_task_scope_and_progress`，设计/制作/安装只传阶段配置；
- 有效任务明细仅包括 active link + active order item，并排除当前阶段取消/回退状态；
- 删除部分明细时保留其他明细原状态、进度、执行人，按剩余明细重算任务状态和平均进度；
- 删除任务全部明细时设置任务范围为空、进度为 0、从未完成看板隐藏，不把空集合判定为完成；
- 重新计算订单明细合计、订单已收/未收、成本和毛利；
- 有效明细仍存在时，确保订单不会因删除历史而错误完成；必要时按现有阶段解析器修正剩余明细的订单阶段；
- 有效明细为 0 时设置订单 `cancelled + deleted_at`，写状态日志并移入回收站；
- 看板、任务列表、任务详情、完成统计和自动流转全部复用重算后的有效范围。

对应验收：A-OID-05。

### OID-P06：回收站恢复和关联数据安全适配

工作内容：

- 自动回收时保存导致回收的订单明细和三阶段任务 link 快照；
- 回收站对该类订单显示“恢复订单并恢复删除明细”；
- 恢复时只恢复快照中未被后续处理覆盖的明细/link，并再次重算任务和订单；
- 明确订单阶段附件、成本金额、付款、合同、库存和已完成事实的保留规则；
- 对成本多明细归属只解除被删除明细的 link，不做金额分摊；单明细成本必要时转为订单级解释；
- 增加孤儿引用扫描：任务旧直接引用、任务 link、外协 item、验收 item、成本 item link 都必须能解释；
- 现有人工取消订单的恢复流程保持原语义，不误恢复明细删除快照。

对应验收：A-OID-06。

### OID-P07：订单详情删除确认和三阶段显示

工作内容：

- 订单详情删除按钮接入预检结果，不再只显示简单“确定删除”；
- 按设计/制作/安装、外协、验收、成本、保留事实、阻断原因分组展示；
- 删除后无有效明细时，按钮改为“确认删除并移入回收站”，成功后跳回订单列表；
- 三类任务详情和列表默认隐藏 removed link、voided item 和 empty scope；历史查看显示明确的“订单明细已删除”标签但不可操作；
- 任务进度、完成状态、明细数量和执行人显示使用统一响应字段；
- 不在前端猜测关联，不通过产品名称、文件名或排序位置判断是否属于目标明细。

对应验收：A-OID-07。

### OID-P08：测试、迁移门禁和发布准备

工作内容：

- 为三阶段删除和任务聚合补充单元、服务、API、迁移和前端交互测试；
- 先在测试数据库执行迁移 dry-run 和回滚演练，核对现有 link/task/item 计数；
- 发布前备份数据库、上传目录元数据和当前代码版本；
- 执行后端测试、前端测试、类型检查、Lint、构建、契约检查、孤儿数据扫描和 `git diff --check`；
- 通过浏览器验证管理员、订单编辑人员、设计/制作/安装员工及无权用户的显示和操作边界；
- 记录部署后健康检查和回滚步骤；Git 提交与服务器部署另行执行，不在方案阶段操作。

对应验收：A-OID-08。

## 4. 文件范围预算

预计涉及：

- 后端模型：`business_document.py`、`task_order_item_link.py`、三类任务模型；
- 后端服务：`business_document_service.py`、`task_service.py`、任务队列/完成统计、外协/验收/成本适配；
- 后端接口与 schema：订单明细预检/确认、订单恢复、任务响应字段；
- 前端：订单详情、订单回收站、任务明细共享组件、三类任务详情和 API 类型；
- 数据库：1 个新增结构迁移，必要时 1 个只读修复/核查脚本；
- 测试和本目录规划文档。

不新增第三方依赖，不删除上传文件，不做不可逆业务数据物理删除。

## 5. 发布前数据门禁

必须按以下顺序执行：

1. 读取当前 Alembic head、数据库版本和目标服务器运行版本；
2. 统计三类任务、任务 link、voided item、外协/验收/成本引用数量；
3. 备份数据库并验证备份文件可读；
4. 在测试副本执行迁移、删除演练、回滚演练和孤儿检查；
5. 检查迁移 SQL、索引和 FK 锁风险；
6. 本地测试全通过后才允许线上发布；
7. 发布后验证“删一条保留其他、删空任务、删空订单进回收站、回收恢复”四条主路径。
