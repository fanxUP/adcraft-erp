# 订单明细删除与三阶段任务一致性验收标准

每项验收标准只对应 `PLAN.md` 中一个主计划项。

## A-OID-01：现状契约和边界明确

对应：OID-P01

- [ ] 能从订单明细删除接口追踪到订单明细软删除、三阶段任务关联、任务聚合、订单回收站和恢复接口。
- [ ] 明确区分订单明细 `voided`、任务 link `removed`、任务范围为空和订单级 `cancelled`。
- [ ] 明确“某个任务为空但订单还有其他有效明细”不回收订单。
- [ ] 明确“订单有效明细为 0”才自动进入回收站。
- [ ] 订单级人工取消、报价删除和订单阶段附件不被误纳入本次规则。

证据：现状调用链、模型关系图、基准数据盘点和四类失败用例说明。

## A-OID-02：关联生命周期和迁移安全

对应：OID-P02

- [ ] `TaskOrderItemLink` 存在独立的 `link_status`、移除时间、移除人和移除原因字段。
- [ ] 三张任务表存在任务范围状态字段，能区分正常工作范围和“订单明细删除后为空”。
- [ ] 已有 link 迁移后默认为 active，迁移不批量改写任务状态、订单状态、明细状态或进度。
- [ ] 有效任务明细查询同时排除 removed link 和 `BusinessDocumentItem.lifecycle_status != active` 的明细。
- [ ] 任务关联重建逻辑不会为了刷新当前集合而物理抹掉 removed 历史行。
- [ ] 旧任务 `order_item_id` 兼容字段不会形成可见的孤儿引用。

证据：迁移 SQL、升级/回滚 dry-run、字段/索引检查和迁移前后计数对比。

## A-OID-03：删除预检和确认契约

对应：OID-P03

- [ ] 删除前能按明细 ID列出设计、制作、安装三类任务的任务编号、原状态、进度和执行人。
- [ ] 预检能列出外协、验收、成本关联，并为每条关联返回自动处理、保留、待复核或阻断动作。
- [ ] 预检返回删除后的有效明细数、订单金额、已收/未收金额和是否自动回收。
- [ ] 预检不修改数据库；订单版本或关联目录变化后旧凭证不能提交。
- [ ] 已收款导致删除后订单总额低于已收金额时，服务端拒绝提交并返回大白话提示。
- [ ] 预检结果中的关联只依据稳定 ID/FK，不依据名称、文件名或页面排序猜测。

证据：预检 API 响应、未修改数据库的快照、过期凭证测试和高风险阻断测试。

## A-OID-04：统一删除事务

对应：OID-P04

- [ ] 删除一条订单明细后，该明细在设计、制作、安装三类任务的当前有效关联中均不可见、不可选、不可操作。
- [ ] 删除只影响请求中的明细 ID；同订单其他明细的状态、进度、执行人和关联不改变。
- [ ] 旧任务直接 `order_item_id` 引用被清理或转换，不留下任务摘要悬空引用。
- [ ] 未开始且未付款的外协计划按规则软取消；外协进行中、已付款、已结算等高风险记录不会被静默物理删除。
- [ ] 草稿验收行可解除明细引用；已验收事实保留并提示待复核。
- [ ] 项目成本金额保留，单条/多条明细成本归属按规则解除，不发生未经授权的金额分摊。
- [ ] 任务 link 的原状态、进度、执行人、位置和删除原因可在审计快照中追溯。
- [ ] 中途任一步失败时，订单明细、任务 link、外协/验收/成本和审计结果整体回滚。
- [ ] 同一确认批次重复提交不会重复删除、重复回收或重复写入关联处理结果。

证据：服务层事务测试、数据库前后快照、失败回滚测试、幂等测试和审计日志。

## A-OID-05：任务进度、状态和回收计算

对应：OID-P05

- [ ] 一个任务包含 3 条明细，删除其中 1 条后，任务只按剩余 2 条明细重新计算进度。
- [ ] 删除 1 条已完成明细不会把剩余未完成明细当成已完成，也不会把任务进度直接置为 100%。
- [ ] 一个任务内所有明细被删除后，任务范围为 `empty_after_item_delete`、进度为 0，并从未完成看板隐藏。
- [ ] 某阶段任务为空但订单仍有其他有效明细时，订单不进入回收站，其他阶段任务正常显示。
- [ ] 一次删除或多次删除后订单有效明细数变为 0 时，订单写入 `cancelled + deleted_at` 并出现在订单回收站。
- [ ] 订单回收原因明确为“订单明细全部删除，系统自动移入回收站”，不被标记为已完成。
- [ ] 删除后订单金额、已收、未收、成本和毛利与剩余有效明细及现有公式一致。
- [ ] 被删除明细不参与工作台项目队列、任务列表、完成统计和下游阶段自动生成。

证据：三阶段混合进度测试、任务/订单聚合前后对比、项目看板查询和完成统计查询。

## A-OID-06：回收站恢复和数据保留

对应：OID-P06

- [ ] 因明细全部删除自动回收的订单保存了删除前明细和三阶段 link 快照。
- [ ] 回收站显示“恢复订单并恢复删除明细”，恢复后至少有一条有效明细才离开回收站。
- [ ] 恢复只恢复快照中未被后续处理覆盖的内容，不覆盖新的人工变更。
- [ ] 恢复后三阶段任务、任务进度、订单金额和订单阶段重新计算，不能恢复成 100% 的空任务。
- [ ] 订单阶段附件、付款、成本金额、合同、库存和已完成历史没有被删除动作物理抹掉。
- [ ] 孤儿扫描对任务 link、旧直接引用、外协、验收和成本归属返回 0 个无法解释的引用。
- [ ] 订单级人工取消恢复仍按原有逻辑，不误恢复明细删除批次。

证据：回收/恢复集成测试、恢复前后快照、附件/财务记录对比和孤儿扫描报告。

## A-OID-07：前端交互和三类任务显示

对应：OID-P07

- [ ] 订单详情删除明细前显示实际影响的任务、状态、执行人、外协、验收和成本处理结果。
- [ ] 删除后无有效明细时，确认按钮明确写“确认删除并移入回收站”。
- [ ] 三类任务详情默认不显示 removed link、voided item 和空任务的可操作按钮。
- [ ] 历史页面显示“订单明细已删除”、删除时间和原因，但不能继续变更状态、分配或领取。
- [ ] 删除一条明细后刷新订单、任务、看板和成本列表，页面数据与服务端重算结果一致。
- [ ] 不同角色的价格、外协和订单可见范围权限未因删除预检而扩大。
- [ ] 无订单编辑权限的设计/制作/安装员工不能调用删除订单明细接口。

证据：桌面/窄屏浏览器记录、前端组件测试、API 权限测试和响应字段检查。

## A-OID-08：测试、数据门禁和发布准备

对应：OID-P08

- [ ] 后端重点测试、后端全量测试、前端单元测试、类型检查、Lint 和构建通过。
- [ ] Alembic 迁移在测试副本升级、删除演练和回滚演练通过；线上 SQL 已人工检查。
- [ ] 发布前有数据库备份和上传目录元数据备份，并验证备份可读。
- [ ] 发布前完成三类任务、任务 link、voided item、外协/验收/成本引用盘点。
- [ ] `git diff --check`、敏感信息扫描、依赖变更检查和范围检查通过。
- [ ] 浏览器验证管理员、订单编辑人员、设计/制作/安装员工和无权限用户的边界。
- [ ] 部署后验证删部分明细、删空任务、删空订单进回收站和恢复四条主路径。
- [ ] 有明确的代码回滚和业务数据恢复步骤；未通过门禁不得执行线上部署。

证据：命令输出、迁移报告、备份校验、测试报告、浏览器验证记录和发布检查单。

## 验收限制

截图只能证明页面显示和提示；“删除只影响目标明细”“任务进度不虚高”“空订单进入回收站”“事务失败整体回滚”“历史事实未被物理删除”必须通过后端测试、数据库快照和 API 验证共同证明。
