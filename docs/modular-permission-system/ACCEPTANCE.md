# 模块化权限验收标准

## A-MP-01：现状清单和契约冻结

对应计划：P-MP-01。

- [ ] 形成完整权限目录、内置角色、自定义角色、后端路由、前端导航/路由/按钮清单。
- [ ] 所有直接按 `admin` 角色、角色名或本地权限 Set 判断的代码都有迁移项或明确兼容理由。
- [ ] 已明确任务、外协、资源中心、订单价格、明细价格和财务字段的授权矩阵。
- [ ] 已冻结旧权限码兼容映射，未直接删除或重命名历史权限。
- [ ] 方案评审确认“功能权限可组合，安全冲突需校验或显式例外”的原则。

## A-MP-02：权限目录、依赖和冲突规则

对应计划：P-MP-02。

- [ ] 每个权限码只有一个目录定义，包含模块、资源、动作、类型、敏感级别和状态。
- [ ] 依赖关系不存在未知权限、依赖环或自引用；冲突关系不存在自冲突。
- [ ] 权限目录可被后端 seed 幂等导入，重复执行不会删除业务数据或自定义角色。
- [ ] 前端角色页面不再维护独立的敏感权限集合和分组事实来源。
- [ ] 废弃权限不能新分配，但历史关联和审计仍可读取。

## A-MP-03：统一后端授权

对应计划：P-MP-03。

- [ ] 所有业务路由通过统一权限评估器授权；除兼容/启动入口外，不再直接依赖 `admin` 角色名。
- [ ] 父级/子级权限、依赖、对象范围和字段权限使用同一套授权上下文。
- [ ] 缺权限、缺依赖、冲突、对象无权和字段隐藏都有稳定错误码或脱敏行为。
- [ ] 统一评估器与 AI 工具权限检查不再各自维护重复的授权逻辑。
- [ ] 权限评估不信任客户端提交的角色、权限或字段标志。

## A-MP-04：角色、权限包和用户组合

对应计划：P-MP-04。

- [ ] 角色可以组合任意非冲突模块；设计、制作、安装、外协只读、资源中心等组合不依赖角色名称。
- [ ] 选择子权限时能看到并补齐前置权限；缺依赖时服务端整批拒绝保存。
- [ ] 冲突组合返回具体权限、风险和处理建议，不允许静默保存半套配置。
- [ ] 角色更新会校验已绑定用户的有效权限；会造成冲突时不保存。
- [ ] 内置角色默认配置版本化；重复 seed 不覆盖管理员已配置的自定义角色和例外。
- [ ] 角色、权限包、用户角色变更均记录操作人、时间、前后差异和理由。

## A-MP-05：前端权限优先

对应计划：P-MP-05。

- [ ] 导航、路由、页面按钮和字段显示使用服务端权限能力，不再依赖固定角色名作为主判断。
- [ ] 自定义角色拥有某权限时，页面入口、直访路由和 API 行为一致。
- [ ] 无权限直访 URL 进入统一无权页面，不能只依赖导航隐藏。
- [ ] 角色权限页面按模块和动作展示，能显示依赖、冲突、影响用户和保存预览。
- [ ] 保存失败时角色页面不修改本地已选权限，刷新后与服务端一致。

## A-MP-06：敏感业务边界

对应计划：P-MP-06。

- [ ] 设计、制作、安装人员在任务、工作台、看板、订单明细处理、聊天、导出、下载和 AI 通道中都拿不到价格字段。
- [ ] 无 `outsource_task:read` 的用户看不到外协卡片、标签、供应商、编号、状态和阻断来源。
- [ ] 外协查看权限不能绕过设计/制作/安装任务权限；外协付款权限不自动获得外协任务写权限。
- [ ] 订单任务员工范围在列表、详情、明细选项、附件和状态变更接口统一生效。
- [ ] 资源中心父级和车辆/高空车子权限均按依赖校验，不因进入父级而获得全部子模块能力。
- [ ] 缺字段权限时字段直接省略，不返回 `0`、`null`、掩码或可推导的金额占位。

## A-MP-07：自动化质量门禁

对应计划：P-MP-07。

- [ ] 后端全量测试、权限组合矩阵、字段脱敏测试和路由契约测试全部通过。
- [ ] 前端单元测试、类型检查、Lint、生产构建和权限导航契约检查全部通过。
- [ ] 静态检查能阻止新增未登记权限码、未知依赖、直接角色名授权和未声明权限的业务路由。
- [ ] 已验证停用用户、过期 JWT、未绑定员工、删除角色、空权限、重复权限和并发保存。
- [ ] 安全检查没有新增秘密、注入、路径穿越、危险下载、日志泄露或未审批依赖。
- [ ] 回归预算为 0；发现既有业务边界回归时必须停止发布。

## A-MP-08：发布和回滚

对应计划：P-MP-08。

- [ ] 发布前已备份权限目录、角色、角色权限、用户角色和审计数据。
- [ ] 已验证迁移、seed、后端健康、前端静态资源和 `/auth/me` 权限摘要。
- [ ] 已用隔离账号验证管理员、销售、财务、设计、制作、安装、资源管理员、外协管理员和至少一个自定义组合角色。
- [ ] 已验证新版本失败时可恢复到旧版本，且不会删除订单、明细、任务、成本和收款数据。
- [ ] 已记录版本、迁移头、服务状态、验证结果、异常和回滚决策。
- [ ] 线上权限异常未通过手工直接改数据库解决，所有修复均可追溯到目录/seed/管理操作。
