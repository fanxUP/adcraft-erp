## 2. 已落地能力

### 2.1 权限目录和安全组合

- 新增统一权限目录：`backend/app/core/permission_catalog.py`。
- 每个权限统一记录模块、资源、动作、权限类型、敏感级别、状态、排序和前置权限。
- 统一定义依赖关系：阶段任务读权限、订单任务分配、订单价格字段、资源中心子权限、外协子权限等。
- 统一定义冲突关系：设计/制作/安装任务执行能力不能与价格、成本、利润、财务及 AI 财务能力组合。
- 新增权限包：设计任务处理、制作任务处理、安装任务处理、外协只读、资源车辆管理、财务查看。
- 显式 `system:super_admin` 取代业务代码中的 `admin` 角色名授权；角色名称不再决定安全边界。

### 2.2 后端统一授权

- 新增 `backend/app/core/authorization.py`，统一处理单权限、全部权限、任一权限、依赖缺失、组合冲突、字段权限和权限解释。
- 路由、AI 工具和任务权限校验收敛到同一评估器；保留旧 `require_role` 仅作迁移兼容入口，业务路由不再使用。
- 无权限字段直接省略，不返回 `0`、`null`、掩码或可推导金额。
- 订单、订单明细、任务、工作台/看板、聊天、AI 上下文、报表和业务文档均继续执行价格/财务字段裁剪。
- 无外协权限时不返回外协卡片、供应商、编号、状态和阻断来源。
- 修复客户路由遗漏的精细权限依赖，客户列表、创建、修改、删除分别使用对应权限。

### 2.3 角色管理和权限组合

- 角色保存先做依赖、冲突、停用权限和已绑定在职用户影响预览，校验失败整批拒绝。
- 角色权限变更记录变更前后权限差异。
- 角色删除前检查在职用户绑定，避免删除角色后留下不可解释的有效授权。
- `permission_seed_version` 使内置角色默认权限版本化；重复 seed 不再无条件覆盖管理员已经调整的角色组合，自定义角色也不会被重置。
- 新增权限元数据迁移：`backend/alembic/versions/b1c2d3e4f5a6_add_permission_metadata.py`。

### 2.4 前端权限契约

- 导航、路由和角色管理页改用服务端权限能力；设计、制作、安装均可进入共享项目看板，但数据仍由后端按字段策略裁剪。
- AI 报价、知识库、异常、报表、现场照片和付款 OCR 页面使用与后端一致的精确权限契约。
- 角色管理页支持权限包、前置权限自动补齐、敏感标识和保存前预览；前端不再维护独立的敏感权限集合。
