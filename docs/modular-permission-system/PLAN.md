# 模块化权限实施计划

## 1. 任务属性

- 类型：安全敏感的权限架构改造。
- 模式：STRICT。
- 目标：让权限按模块和原子能力自由组合，同时由统一依赖、冲突、数据范围和字段策略阻止越权。
- 本轮：P-MP-01～P-MP-07 已实施并通过自动化验证；P-MP-08 已完成受控生产发布、线上迁移和基础健康验收。隔离业务账号的完整角色冒烟与故障回滚演练仍待维护窗口补充。

## 2. 实施预算与边界

建议实施预算（开始开发前冻结）：

```yaml
max_changed_files: 115
max_new_files: 45
max_dependency_additions: 0
max_migration_files: 3
max_public_api_changes: 18
max_regression_budget: 0
```

允许范围：

- `backend/app/core/**`、权限/认证相关 service、模型、schema、repository、路由和测试；
- `backend/alembic/versions/**` 最多 3 个迁移；
- `backend/scripts/seed_permissions.py` 或迁移后的权限目录 seed；
- `frontend/src/config/**`、auth store/composable、router/navigation、角色管理页面和权限相关测试；
- `docs/modular-permission-system/**`。

明确禁止：

- 修改订单、明细、任务进度、成本、收款等业务事实数据；
- 新增第三方权限依赖；
- 直接删除历史权限码或旧角色关联；
- 通过前端隐藏替代后端鉴权；
- 未经单独审批的全库恢复、批量改角色或批量改业务数据。

## 3. 计划项

### P-MP-01：权限现状清单与授权契约冻结

目标：形成唯一的权限、路由、字段、对象范围和敏感数据清单。

工作内容：

- 盘点当前 135 个权限码、内置角色、自定义角色、后端路由、前端导航/路由/按钮。
- 标记所有 `require_role("admin")`、角色名判断、重复权限集合和手工父级校验。
- 建立模块—资源—动作—字段—范围矩阵。
- 明确任务、外协、资源中心、订单价格和财务字段的依赖关系。
- 冻结兼容映射：旧权限码继续有效，后续不直接重命名。

对应验收：A-MP-01。

### P-MP-02：建立权限目录、依赖和冲突规则

目标：消除后端 seed、前端页面和角色页的多份权限事实来源。

工作内容：

- 扩展 `permissions` 元数据或建立等价目录模型。
- 新增权限依赖、冲突、敏感等级和废弃状态的结构化定义。
- 编写目录启动校验：重复、未知依赖、环、冲突自引用和非法动作均拒绝。
- 为现有权限码补齐模块、资源、动作、敏感级别和中文说明。
- 生成/提供前端所需的只读权限目录，禁止前端重复维护敏感集合。

对应验收：A-MP-02。

### P-MP-03：统一后端授权评估器与错误契约

目标：让路由、service、字段脱敏和对象范围使用同一授权入口。

工作内容：

- 实现 `AuthorizationEvaluator` 和统一 `AuthorizationContext`。
- 收敛 `require_permission`、`require_any/all`、任务内私有 helper、AI `PermissionGuard` 的重复逻辑。
- 为权限缺失、依赖缺失、组合冲突、对象范围不允许、字段隐藏定义稳定错误码和大白话消息。
- 设计 `explain()` 仅供管理页/测试使用，普通业务响应不泄露权限内部结构。
- 让 `super_admin` 能力成为显式系统权限；业务路由不再直接判断 `admin` 角色名。

对应验收：A-MP-03。

### P-MP-04：角色、权限包和用户组合事务化

目标：支持自由组合，同时避免半保存、隐式扩权和组合后用户进入非法状态。

工作内容：

- 保留 `role_permissions` 作为展开后的明确权限；新增权限包快捷配置。
- 角色保存前执行依赖补齐、冲突检测和有效权限预览。
- 用户多角色分配按有效权限并集校验；角色更新时模拟所有绑定用户，发现冲突整批拒绝。
- 将现有“执行角色/敏感角色”硬编码迁移为配置化能力冲突策略。
- 将 seed 改为权限目录幂等 upsert；内置角色默认值版本化，不再每次部署无条件覆盖已配置关联。
- 所有角色/权限/用户授权变化写入操作日志和变更前后差异。

对应验收：A-MP-04。

### P-MP-05：前端权限优先和模块化管理界面

目标：让自定义组合角色与内置角色拥有同样的导航、路由和按钮行为。

工作内容：

- `router` 使用 `permission`、`allOf`、`anyOf` 元数据，不再把角色名作为主判断。
- 导航、智能工具、操作按钮和页面字段统一调用 `authStore.can()`/composable。
- 角色页面改为模块、权限包、动作和字段权限视图，显示依赖/冲突/影响用户。
- 增加 dry-run 预览和整批保存；失败时不更新前端本地角色状态。
- 角色页面只消费服务端权限目录，不再维护本地敏感权限 Set。

对应验收：A-MP-05。

### P-MP-06：任务、外协、订单价格和对象范围接入统一策略

目标：保证本项目目前最敏感的权限边界在组合角色下不回归。

工作内容：

- 设计/制作/安装任务统一校验工作台、阶段详情、列表、状态变更、负责人维护和附件权限。
- 保留订单任务员工可见范围；将对象范围判断接入统一 evaluator。
- 外协中心父级与商户/任务/付款子权限统一处理；无外协查看权限时统一脱敏。
- 订单总额、明细单价/小计、成本、利润、目录价格和财务字段统一由字段策略裁剪。
- 覆盖聊天卡片、工作台、看板、报表、导出、下载和 AI 上下文等替代通道。

对应验收：A-MP-06。

### P-MP-07：组合矩阵、静态契约和安全回归

目标：用自动化检查防止以后新增模块再次回到散落硬编码模式。

工作内容：

- 后端正反向矩阵：单角色、多角色、自定义权限包、冲突组合、依赖缺失和临时例外。
- 字段不存在测试：无价格/外协权限时所有替代接口均不返回敏感字段。
- 代码静态规则：新业务路由不得直接 `require_role("admin")`，新页面不得新增角色名判断。
- 目录契约：所有引用权限码必须存在；所有依赖和冲突必须可解析。
- 前端单测、类型检查、Lint、生产构建和后端全量测试。
- 安全检查覆盖日志、下载、路径、注入、JWT、停用用户和权限缓存/刷新。

对应验收：A-MP-07。

### P-MP-08：分批发布、线上验证和回滚演练

目标：在不改业务数据的前提下上线新权限内核。

工作内容：

- 发布前备份权限目录、角色、关联表、用户角色和审计日志。
- 先上线兼容读和目录校验，再分批迁移路由和前端，最后开放新的角色组合 UI。
- 用隔离账号验证管理员、销售、财务、设计、制作、安装、资源管理员、外协管理员及自定义组合角色。
- 验证旧版本回滚后仍能读取旧权限码；验证新版本回滚不覆盖业务数据。
- 记录提交、迁移、seed、服务健康、账号烟囱和回滚点。

对应验收：A-MP-08。

## 4. 推荐依赖顺序

```text
P-MP-01 -> P-MP-02 -> P-MP-03 -> P-MP-04
                                      |       \
                                      v        v
                                  P-MP-05   P-MP-06
                                      \       /
                                       v     v
                                      P-MP-07 -> P-MP-08
```

P-MP-05 和 P-MP-06 可并行，但必须依赖 P-MP-03 的统一错误和能力契约。P-MP-08 只有在 P-MP-07 全部通过后才能执行。

- B-MP-02：临时授权申请与审批流程。
- B-MP-03：权限变更影响图和管理员风险评分。

## 6. 回滚策略

- 代码回滚：恢复到迁移前已验证提交，保留新增权限目录记录，旧代码继续使用兼容权限码。
- 数据回滚：只在迁移失败且完成权限关联备份核对后回退权限相关迁移；不得用全库恢复覆盖订单和财务业务表。
- 配置回滚：停用新权限包入口，保留旧角色权限快照和审计记录。
- 部分失败：禁止继续发布或手工补权限；先定位是目录、迁移、路由还是前端契约问题，再按批次恢复。
