# 任务分配与变更状态合并验收标准

每个计划项对应一个主验收项。验收重点是“必须有负责人才能变更状态”，同时证明分配与明细级状态更新的一致性。

## A-TASK-ASSIGNEE-01 对应 TASK-ASSIGNEE-P01：合并布局和业务语义明确

- [ ] 设计、制作、安装任务都在同一个“任务处理”卡片内显示任务分配和变更状态。
- [ ] 任务分配控件位于“变更状态”标题旁边/同一操作区，原独立分配卡片被移除。
- [ ] 当前任务已有负责人时，状态操作可以继续使用，除非任务自身不可变更。
- [ ] 当前任务没有负责人时，所有状态推进、回退和取消操作不可执行。
- [ ] 无负责人时页面提示为“请先选择分配人，再变更任务状态”。
- [ ] 没有勾选订单明细时，继续提示先勾选明细，不被负责人校验覆盖。
- [ ] 负责人仍是任务级字段，不出现明细级不同负责人假象。

证据：三类任务页面截图/操作记录、布局源代码检查、状态矩阵测试。

## A-TASK-ASSIGNEE-02 对应 TASK-ASSIGNEE-P02：后端强制校验和原子更新

- [ ] 三类状态变更接口支持携带负责人 ID。
- [ ] 请求未携带负责人但任务已有已保存负责人时，可以继续状态变更。
- [ ] 请求和任务都没有负责人时，后端拒绝状态变更并返回大白话提示。
- [ ] 无效、无权限或不可用的负责人不能被写入任务。
- [ ] 选择新负责人直接变更状态时，负责人和勾选明细状态在同一事务中提交。
- [ ] 状态校验、明细校验或外协校验失败时，负责人和明细状态都回滚。
- [ ] 任务分配通知继续按既有规则执行，不新增短信、邮件、飞书依赖。

证据：后端服务测试、API 请求/响应测试、事务回滚测试。

## A-TASK-ASSIGNEE-03 对应 TASK-ASSIGNEE-P03：三类任务界面一致

- [ ] 任务处理卡片内提供员工选择器和“保存分配”按钮。
- [ ] “保存分配”只修改任务负责人，不改变订单明细状态和进度。
- [ ] 用户选择新负责人后直接点击状态，系统能够提交负责人和状态变更。
- [ ] 设计、制作、安装任务的每条已关联明细显示“分配人：姓名”。
- [ ] 已关联但无负责人时显示“分配人：未分配”。
- [ ] 未关联明细不显示负责人。
- [ ] 重新派发后所有已关联明细显示新负责人。
- [ ] 数量、金额、小计、本任务进度顺序不变；窄屏下负责人控件和标签正常换行。

证据：共享组件源代码检查、三类任务桌面/窄屏截图、前端构建结果。

## A-TASK-ASSIGNEE-04 对应 TASK-ASSIGNEE-P04：明细状态范围不回归

- [ ] 变更状态请求仍只包含用户勾选的 `order_item_ids`。
- [ ] 未勾选明细的状态、进度和负责人显示不会因其他明细变更而改变。
- [ ] 全选、单选、回退、完成、外协阻塞和任务进度聚合保持既有规则。
- [ ] 已完成、已取消、历史只读和 legacy 任务行为符合既有规则。
- [ ] 改派负责人不会改变明细状态或进度。
- [ ] 新增关联明细后，按现有初始化规则处理，并显示当前任务负责人。
- [ ] 状态变更成功后刷新页面，负责人和每条明细的状态显示一致。

证据：前端事件/API 参数测试、后端状态流转回归测试、外协/历史任务测试。

## A-TASK-ASSIGNEE-05 对应 TASK-ASSIGNEE-P05：质量门禁通过

- [ ] 后端任务服务和 API 契约测试通过。
- [ ] `npm test` 通过。
- [ ] `npm run typecheck` 通过。
- [ ] `npm run lint` 通过。
- [ ] `npm run build` 通过，首屏包体不超过既定预算。
- [ ] `git diff --check` 通过。
- [ ] 没有新增数据库迁移、第三方依赖、无用接口或重复的任务分配入口。
- [ ] 本阶段没有未经授权执行服务器部署。

证据：命令输出、Git 差异、提交记录和交付说明。

## 验收限制

截图只能证明卡片布局、禁用状态和负责人标签。是否真正做到“无负责人不能改状态”和“状态失败时负责人不落库”，必须通过后端接口测试与事务回滚测试共同证明。
