# 任务分配与变更状态合并实施计划

## 1. 任务分类

- 类型：现有任务处理工作流的 UI、接口契约和业务校验增强。
- 风险：STANDARD。涉及状态变更前置条件和“负责人 + 状态”事务一致性，但不涉及数据库迁移。
- 变更预算：一个共享任务处理组件、三类任务状态接口的服务层适配、三个详情页入口收敛、相关测试和文档；不扩展到明细级派工。
- 核心约束：状态变更仍只作用于勾选的 `order_item_ids`；负责人仍是任务级字段。

## 2. 计划项

### TASK-ASSIGNEE-P01：冻结合并卡片与前置规则

目标：确认布局、负责人必填范围、仅保存分配和直接变更状态的交互语义。

工作内容：

- 将任务分配放到“变更状态”标题旁边的同一操作区；
- 设计、制作、安装所有可执行状态变更都要求负责人；
- 保留无负责人时的“请选择分配人，再变更任务状态”提示；
- 确认已关联明细才显示负责人，未关联明细不显示；
- 确认任务级负责人语义，不新增明细级分配字段。

对应验收：A-TASK-ASSIGNEE-01。

### TASK-ASSIGNEE-P02：扩展负责人和状态变更接口契约

目标：让状态变更可以安全携带新选择的负责人，并由后端强制执行负责人前置条件。

工作内容：

- 为状态变更请求增加负责人 ID 输入；
- 没有请求负责人时使用当前已保存负责人；两者都为空时拒绝；
- 校验负责人用户存在、权限和可用状态；
- 将保存负责人、校验并更新勾选明细状态放在同一事务；
- 保留现有任务分配通知，不增加短信、邮件和飞书；
- 更新 AI、移动端或其他状态接口调用方的契约和测试。

对应验收：A-TASK-ASSIGNEE-02。

### TASK-ASSIGNEE-P03：合并前端卡片和负责人逐行显示

目标：让用户在一个卡片内完成分配、查看负责人和变更明细状态。

工作内容：

- 在共享 `TaskOrderItemLinkCard` 的变更状态标题旁放置员工选择器和“保存分配”按钮；
- 删除设计、制作、安装详情页外置的独立任务分配卡片；
- 无负责人时禁用状态工作流；有待保存负责人时允许点击状态并一并提交；
- 任务处理列表的每一条已关联明细显示“分配人：姓名/未分配”；
- 保留现有单条勾选、按状态全选、回退、完成、外协和进度显示。

对应验收：A-TASK-ASSIGNEE-03。

### TASK-ASSIGNEE-P04：事务一致性和状态回归测试

目标：证明负责人前置规则有效，且不会扩大状态变更的明细范围。

工作内容：

- 覆盖三类任务无负责人、有负责人、改派和清除选择；
- 覆盖“仅保存分配”和“选择负责人后直接变更状态”；
- 覆盖状态校验失败时负责人和明细状态均回滚；
- 覆盖状态变更只提交勾选明细，未勾选明细不受影响；
- 覆盖历史/终态任务、legacy 关联、已完成明细和外协阻塞；
- 覆盖已有负责人变更后的逐行显示和刷新同步。

对应验收：A-TASK-ASSIGNEE-04。

### TASK-ASSIGNEE-P05：质量验证与交付准备

目标：确认三类页面一致、接口兼容、构建干净且没有引入明细级派工死代码。

工作内容：

- 执行后端任务服务和 API 契约测试；
- 执行前端任务界面契约测试、类型检查、Lint 和生产构建；
- 检查桌面端和窄屏下标题、选择器、状态节点和明细负责人标签；
- 检查 `git diff --check`、无数据库迁移、无新依赖、无重复分配入口；
- 记录提交版本和验收证据；部署另行授权。

对应验收：A-TASK-ASSIGNEE-05。

## 3. 推荐顺序

```text
TASK-ASSIGNEE-P01
          |
          v
TASK-ASSIGNEE-P02 -> TASK-ASSIGNEE-P03 -> TASK-ASSIGNEE-P04 -> TASK-ASSIGNEE-P05
```

## 4. 变更控制

- 不新增 `task_order_item_links.assigned_to`；
- 不把负责人写入订单明细本身；
- 不改变 `order_item_ids` 的勾选提交集合；
- 不允许前端通过置灰代替后端校验；
- 不在状态变更失败后保留新负责人；
- 不保留三个详情页重复的任务分配卡片；
- 若后续要求“不同明细分配不同人”或“负责人历史”，立即停止本计划的扩展，另立数据模型方案。

- B-TASK-ASSIGNEE-03：按负责人筛选任务处理明细；
- B-TASK-ASSIGNEE-04：接入短信、邮件或飞书通知。
