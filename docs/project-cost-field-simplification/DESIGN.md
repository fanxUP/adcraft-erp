# 项目成本字段精简设计

## 目标

将项目成本登记和项目成本详情列表收敛为财务可操作的九个字段：日期、供应商、支付金额、欠款金额、分类、付款方式、支出总额、说明、凭证。保留订单/报价与订单明细成本归属作为独立的关联上下文。

## 字段策略

- `支出总额`是只读计算值，等于`支付金额 + 欠款金额`。
- 现有数据库中的 `amount` 继续表示支出总额，`debt_amount` 继续表示登记时进入应付台账的欠款金额；支付金额通过两者相减得到。
- 供应商作为唯一新录入的对方主数据入口；`payee_company_name` 只保留给历史数据和兼容接口，不再出现在新表单和列表列中。
- 成本摘要、产品/材质/工艺、规格尺寸、数量、单位、单价、收款公司从新建/编辑页面和成本明细列表中移除，但首期不物理删除数据库列。
- 说明使用现有 `remark` 字段；旧 `description` 和 `summary` 继续由后端返回以兼容历史读取，但新页面不再编辑或展示。

## 页面结构

登记成本弹窗分为两块：

1. 关联信息：订单/报价、成本归属、可选分项。
2. 财务信息：日期、供应商、支付金额、欠款金额、分类、付款方式、支出总额、说明、凭证。

项目成本表格保留编号、成本归属和操作等定位列，业务列使用上述九个字段；凭证显示数量并沿用现有查看、下载和删除能力。

## 兼容边界

首期不执行数据库迁移。后端 schema 和导入解析器继续接受旧字段，新的前端不再发送冗余字段；新的 Excel 模板使用精简字段，旧模板在兼容窗口内可以导入，旧字段被忽略并返回提示。

## 约束

- 支付金额、欠款金额均不得为负数。
- 支出总额必须大于零，且欠款金额不得大于支出总额。
- 修改已有应付来源时继续执行已付款金额保护，不能将待付款金额调低到已付款流水以下。
- 供应商、应付台账、凭证和成本归属权限沿用现有权限模型。
