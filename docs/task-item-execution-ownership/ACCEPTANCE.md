# 订单明细执行归属验收标准

## A-TIO-01：D20260910-0015 失败用例被准确复现并定义

- [ ] 一个设计/制作/安装任务包含至少两条可操作订单明细。
- [ ] 只提交其中一条明细的状态变更时，预期只有该明细状态、进度和执行归属变化。
- [ ] 未勾选明细的状态、进度、执行人和操作权限不发生变化。
- [ ] 明确记录现有错误来自 `task.assigned_to` 被逐行复用，而不是把问题归因于复选框。

证据：复现请求/响应、数据库快照、服务层调用链和失败测试。

## A-TIO-02：明细执行人字段和迁移安全

- [ ] `task_order_item_links` 存在可空的明细执行人字段和必要索引。
- [ ] 旧任务级 `assigned_to` 不会被批量复制到该任务所有明细。
- [ ] 没有可靠逐条证据的历史明细显示“历史未记录”或未分配，不伪造员工姓名。
- [ ] 迁移 dry-run 可生成 SQL，升级/回滚范围只包含本次新增结构。
- [ ] 迁移前有备份记录，迁移后状态、进度、明细数量和任务数量保持一致。

证据：Alembic SQL、备份校验、迁移后计数对比和回滚演练记录。

## A-TIO-03：订单可见范围与阶段权限隔离

- [ ] 订单无可见员工记录时，所有拥有任务工作台权限且满足岗位读取权限的员工可见。
- [ ] 订单有一个或多个可见员工记录时，只有名单内在职员工可见；名单外员工不能通过列表、详情、明细选项或附件接口绕过。
- [ ] 设计、制作、安装岗位都能只读查看订单的三阶段流程。
- [ ] 设计岗位不能执行制作/安装状态；制作岗位不能执行设计/安装状态；安装岗位不能执行设计/制作状态。
- [ ] 阶段列表权限与阶段状态变更权限保持独立，岗位员工不能因为只读查看而获得任务列表或价格权限。
- [ ] 没有外协权限时不返回外协任务编号、外协状态或外协名称；价格字段继续按现有权限脱敏。

证据：权限矩阵测试、API 403/404 测试、工作台/详情浏览器验证和响应字段检查。

## A-TIO-04：明细领取、继续操作和改派规则

- [ ] 员工首次把未分配明细推进到本阶段工作状态时，只有该明细写入当前登录员工。
- [ ] 同一次请求勾选多条未分配明细时，每条都写入当前登录员工，但不写入任务表全局负责人。
- [ ] 同一订单内其他未分配明细仍可被其他可见员工领取。
- [ ] 已由员工甲领取的明细，员工乙可见但不能勾选、推进或回退；错误提示包含明细名称和当前负责人。
- [ ] 无负责人或未绑定在职员工的登录账号不能领取或变更状态。
- [ ] 回退到阶段等待状态释放负责人；返工保留负责人；完成/取消保留历史负责人但不可再操作。
- [ ] 混合勾选自己可操作与他人已领取明细时整批失败，不产生部分状态、进度或负责人变更。
- [ ] 明细改派接口必须显式提交明细 ID，只改负责人不改状态/进度，且必须具备阶段分配权限。
- [ ] 状态、负责人、事件日志、任务聚合更新失败时整体回滚。

证据：三阶段服务层测试、事务回滚测试、混合勾选测试、改派接口测试和审计日志。

## A-TIO-05：前端显示与操作边界

- [ ] 任务处理卡片不再显示整张任务的全局负责人选择器。
- [ ] 每条关联明细显示执行人姓名、待领取或历史未记录。
- [ ] 已由其他员工领取的明细显示只读状态和明确禁用原因。
- [ ] 未领取且属于当前岗位阶段的明细可选择；其他阶段、终态、外协阻塞明细不可选择。
- [ ] 其他阶段详情只显示流程状态、进度和执行人，不显示该阶段状态按钮或明细勾选操作。
- [ ] 设计、制作、安装三类页面使用同一套字段和禁用语义，桌面和窄屏布局均不出现重复分配入口。

证据：前端组件测试、类型检查、构建、1440/1024/390 宽度截图或浏览器记录。

## A-TIO-06：历史修复、统计和通知不再串归属

- [ ] D20260910-0015 修复前有备份和只读预览；修复只影响明确范围的明细负责人。
- [ ] 修复不改变订单状态、任务状态、明细进度、数量或金额。
- [ ] 经营驾驶舱完成数量按明细执行归属/完成事件统计，不因任务级旧负责人把所有明细记到一人名下。
- [ ] 超期通知和任务通知不再把整张任务的旧负责人当成所有明细负责人。
- [ ] 任务按负责人筛选时使用明细 link 数据，不能继续误用任务表单一 `assigned_to`。

证据：数据修复前后对比、驾驶舱统计回归、通知接收人测试和筛选 SQL/接口测试。

## A-TIO-07：发布门禁

- [ ] 后端重点测试、后端全量测试、前端单元测试、类型检查、Lint、构建和 API 契约检查通过。
- [ ] `git diff --check`、敏感信息扫描和范围检查通过。
- [ ] Alembic 新迁移升级/回滚 dry-run 通过，且全链路旧迁移失败项已单独记录，不被误报为本次迁移通过。
- [ ] 服务器发布前已完成数据库备份、当前版本记录、健康检查和回滚命令确认。
- [ ] 未经用户单独授权，不执行 Git 提交、线上迁移或服务器部署。

证据：命令输出、质量门禁记录、发布清单和浏览器多角色验证记录。

## 验收限制

截图只能证明显示、禁用和布局；“只更新勾选明细”“阶段权限不能越权”“失败原子回滚”和“旧任务负责人不再影响明细”必须由后端测试、数据库对比和 API 验证共同证明。
