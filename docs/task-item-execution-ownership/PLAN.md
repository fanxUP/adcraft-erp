# 订单明细执行归属实施计划

## 1. 任务分类与边界

- 类型：任务状态、明细数据模型和模块化权限的联合修复。
- 模式：STRICT。
- 目标：修复 D20260910-0015 的“单条明细操作导致全任务负责人覆盖”问题，并建立订单可见范围、明细执行人、阶段操作权限三层模型。
- 用户已授权开始实施。本阶段执行代码、测试和本地迁移预演；历史数据修复、Git 提交及服务器部署仍须分别完成门禁后再执行。
- 现有工作树中的经营驾驶舱、权限和附件等未提交变更属于既有工作，后续实施必须在同一工作树上保留并回归。

## 2. 稳定决策

1. `order_task_assignees` 只负责订单任务可见范围，支持多选；空集合表示所有符合岗位权限的员工可见。
2. `task_order_item_links.assignee_user_id` 负责某阶段某条订单明细的当前执行人。
3. 员工首次把未领取明细推进到本阶段工作状态时，当前登录员工领取该明细；状态请求不再把一个全局负责人写入整张任务。
4. 已被其他员工领取的明细只读展示，不能被普通员工再次选择；未领取明细仍可被同订单可见范围内的同岗位员工领取。
5. 设计、制作、安装只拥有自己阶段的 `change_status`，但通过任务队列和只读任务详情查看订单的所有阶段流程。
6. 管理员/阶段管理人员如需改派，使用明确的“明细改派”接口，必须提交明细 ID 集合，不允许隐式整单生效。
7. 旧 `task.assigned_to` 暂不删列，但冻结为兼容字段，不再参与新权限、状态和明细展示。

## 3. 实施项与验收映射

### TIO-P01：现状契约与失败用例冻结

工作内容：

- 固化 D20260910-0015 的复现模型：一个任务至少两条明细，提交一条状态变更后只能一条明细变化；
- 明确三层关系、角色矩阵、回退释放策略和历史数据处理原则；
- 为现有 task assignment/visibility、task completion metrics、price/outsource masking 建立依赖清单。

对应验收：A-TIO-01。

### TIO-P02：明细执行人数据模型与迁移

工作内容：

- 给 `task_order_item_links` 增加可空 `assignee_user_id` 和查询索引；
- 复用 `task_item_status_logs` 记录状态事件的执行归属和实际操作人；
- 迁移默认不复制旧 `task.assigned_to`；只对有可靠明细事件证据的数据回填；
- 定义升级、回滚、备份、dry-run、线上锁风险和迁移后校验脚本。

对应验收：A-TIO-02。

### TIO-P03：订单可见范围与阶段权限收敛

工作内容：

- 保持 `order_task_assignees` 的“有记录按员工过滤、无记录全员可见”逻辑；
- 确保工作台、三类任务详情、明细选项、附件接口全部复用订单可见性；
- 设计、制作、安装岗位补齐三阶段只读查看能力，但保留各自唯一阶段的状态变更权限；
- 移除任务列表入口对岗位员工的导航与接口权限，保留工作台/详情入口；
- 外协查看权限继续单独控制，价格字段继续按权限脱敏。

对应验收：A-TIO-03。

### TIO-P04：后端明细领取、状态校验与改派接口

工作内容：

- 状态变更只接受 `order_item_ids`，按当前登录账号逐条领取和校验；
- 已领取明细只允许执行人或阶段管理人员操作；
- 设计/制作/安装阶段权限在服务层再次校验，防止移动端、AI 或直接请求绕过前端；
- 回到等待状态释放执行人，返工保留执行人，完成/取消保留历史展示；
- 增加只对选中明细生效的改派/释放接口；
- 旧 task-level `assigned_to` 状态写入、逐行显示和错误通知逻辑停止使用；
- 同一事务内完成状态、负责人、事件日志和任务聚合更新，失败全部回滚。

对应验收：A-TIO-04。

### TIO-P05：前端任务处理和跨阶段只读视图

工作内容：

- 删除任务处理卡片中“整张任务负责人”的选择器和逐行复用逻辑；
- 每条明细显示“执行人：姓名/待领取/历史未记录”；
- 只让服务端返回 `can_select=true` 的明细出现可操作选择；
- 已由他人领取的明细显示禁用原因；
- 其他阶段详情可查看状态、进度、执行人，但不出现状态按钮和勾选操作；
- 阶段管理人员增加明确的明细改派入口，不恢复全局任务分配；
- 三类详情页、工作台、项目看板使用同一字段语义。

对应验收：A-TIO-05。

### TIO-P06：历史数据核查、D20260910-0015 修复和统计通知适配

工作内容：

- 备份后以只读查询确认 D20260910-0015 的明细、状态事件和错误批量负责人范围；
- 只清理无法证明的明细负责人，保留状态和进度；
- 有业务依据的明细按行恢复，不做整任务恢复；
- 经营驾驶舱完成统计改用明细执行人/完成事件；
- 超期通知、任务分配通知和筛选接口不再依赖旧任务级负责人。

对应验收：A-TIO-06。

### TIO-P07：全链路验证与发布门禁

工作内容：

- 后端、前端、权限契约、迁移 dry-run、浏览器多角色验证；
- 覆盖设计/制作/安装岗位、订单可见员工、未分配员工、无员工绑定账号、管理员/阶段管理人员；
- 验证 401/403/404/409/422、混合勾选原子性、外协隐藏、价格隐藏、历史任务和回退；
- 完成备份、回滚点、发布顺序和服务器部署前审批清单；
- 本计划完成后另行授权 Git 提交与服务器部署。

对应验收：A-TIO-07。

## 4. 文件范围预算

预计只涉及以下类型文件：

- 后端：任务 link 模型、任务服务、任务队列、任务接口、订单可见性服务、权限种子/目录、超期通知、统计服务、迁移和测试；
- 前端：任务明细共享卡片、三个任务详情页、任务 API/类型、权限入口和测试；
- 文档：本目录下的设计、计划、验收和 DAG；
- 不新增第三方依赖；预计 1 个结构迁移文件；不修改成本、订单金额和状态聚合公式。

## 5. 风险控制

- 数据库迁移必须先备份、后 dry-run，再在事务中执行；不能直接线上批量 UPDATE。
- 旧 `task.assigned_to` 不得作为明细归属回填来源，除非有逐条事件证据。
