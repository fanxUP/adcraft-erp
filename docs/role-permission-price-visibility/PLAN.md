# 角色权限与订单价格可见性实施计划

## 1. 任务属性

- 类型：安全敏感的 RBAC、字段级数据可见性和前后端权限一致性改造
- 风险：高
- 实施模式：STRICT
- 当前状态：P01-P07 已在本地实现并完成代码级验证；P08 未执行（未备份、未发布、未线上验收）；未修改业务数据
- 目标：设计、制作、安装角色不能从页面、API、工作台、聊天业务卡片、导出或附件下载中获取订单及明细价格参数

## 2. 变更预算与边界

### 预计修改范围

- 后端：权限常量/访问策略、认证 profile、角色 seed、角色管理服务、订单/任务/目录/报表相关序列化和接口、专项测试
- 前端：权限 store/composable、路由/导航、任务列表与详情、项目看板、工作台、产品目录价格列、订单/财务入口、专项测试
- 文档：权限矩阵、价格字段清单、验收记录和发布回滚说明

### 明确不修改

- 不改订单、订单明细、任务进度和任务状态数据库事实
- 不删除历史价格或历史日志
- 不新增审核角色或审核流程
- 不改短信、邮件、飞书配置
- 不通过前端置灰替代后端权限
- 不做按部门/客户/负责人进行的复杂行级数据权限

### 默认安全决策

- `admin`、`sales`、`finance` 可以按显式权限查看相应价格。
- `designer`、`production`、`installer` 默认没有订单价格、明细价格、目录价格和财务权限。
- 同一账号不允许执行角色与销售/财务敏感角色并存，管理员例外；如业务需要兼职授权，另立临时授权方案。

## 3. 计划项

### P01：建立现状清单与字段分类

目标：形成可执行的权限和敏感字段基线，防止只修三个任务页面而遗漏工作台、产品和聊天入口。

工作内容：

- 盘点基线中的 115 个权限码，并新增 5 个显式敏感权限（当前权限字典共 120 个）；同时核对六个预置角色及自定义角色行为。
- 逐个清点订单、明细、产品、材质、工艺、成本、收款、报表、聊天卡片、导出和附件接口。
- 建立价格字段 allowlist/blocklist，明确任务人员可见的基础字段。
- 标记只校验登录、只按角色名、未接入统一权限的路由，形成修复清单。

对应验收：A01。

### P02：落地敏感权限和访问策略

目标：在权限系统中建立订单价格、明细价格、目录价格和财务字段的显式能力。

工作内容：

- 增加 `order:view_price`、`order_item:view_price`、`catalog:view_price`、`finance:view_cost`、`report:view_financial` 等权限常量和 seed 定义。
- 建立统一访问上下文，提供权限判断函数，不让业务服务散落硬编码角色判断。
- 设计基础订单/明细 DTO 与财务价格 DTO 的边界。
- 明确敏感权限缺失时字段完全省略，禁止返回 0、null 或掩码值。

对应验收：A02。

### P03：收敛预置角色和角色管理

目标：让角色矩阵可重复初始化、不可被意外覆盖，并阻止执行角色获得敏感权限。

工作内容：

- 只同步六个内置角色的默认权限，修复初始化脚本清空自定义角色权限的问题。
- 角色管理接口校验权限 ID 完整存在，保护内置角色名称和核心权限。
- 后端拒绝向设计、制作、安装角色授予敏感权限。
- 用户角色分配时拒绝执行角色与销售/财务敏感角色冲突，管理员例外。
- 为角色变更和敏感权限变更保留操作日志。

对应验收：A03。

### P04：后端接入安全响应和模块动作权限

目标：从 API 层真正阻断订单及明细价格泄露和越权写入。

工作内容：

- 任务列表、详情、统一队列、订单明细选项改用安全 DTO/访问策略。
- 三类任务响应去除订单总额和明细价格；销售/财务/管理员按显式权限保留必要字段。
- 订单、订单明细、产品、材质、工艺、报表、客户财务、成本、付款、导出和附件接口接入正确的模块/动作权限。
- 产品目录对执行角色仅开放基础只读；价格编辑和定价规则只开放给管理角色。
- 任务创建/编辑输入拒绝无关金额字段；价格变更和财务写入保持销售/财务边界。

对应验收：A04。

### P05：覆盖替代数据通道

目标：防止用户通过页面之外的接口得到价格。

工作内容：

- 工作台 dashboard 对任务人员只返回任务工作数据，不返回金额、收款、欠款排名等财务字段。
- 经营报表、客户欠款、合同项目金额、外协/成本摘要按财务权限处理。
- 聊天搜索、订单/报价分享卡片、通知、最近业务对象和 AI 上下文按查看者裁剪价格字段。
- 报价 PDF、订单报价附件、含价格导出和下载接口必须有价格/财务权限。
- 对每条发现的替代通道补充 API 级权限测试。

对应验收：A05。

### P06：前端权限能力和 UI 收敛

目标：前端展示和后端实际响应保持一致，任务人员看不到金额控件和金额占位。

工作内容：

- `/auth/me` 返回权限码和能力摘要，Pinia 提供 `hasPermission`/`canViewPrice`。
- 路由、导航和操作按钮逐步从硬编码角色切换为权限能力判断。
- 移除设计、制作、安装任务列表金额列、看板金额区、任务处理卡片单价/小计。
- 工作台按权限隐藏财务统计和欠款区；产品/材质/工艺页面隐藏价格列和价格编辑控件。
- 类型定义把可能被省略的财务字段改为可选，不用 `|| 0` 伪造金额。

对应验收：A06。

### P07：跨角色安全回归和代码纯净度检查

目标：证明权限边界不是只在一个页面有效，并确保没有留下旧的价格渲染和死权限代码。

工作内容：

- 为 admin、sales、finance、designer、production、installer 建立正向/反向 API 测试矩阵。
- 对任务列表、任务详情、选项列表、订单详情、目录、dashboard、聊天、导出和下载做“字段不存在”断言。
- 测试直访 URL、伪造请求、缺权限 token、停用用户、多角色冲突、自定义角色和权限重启持久性。
- 前端执行单元测试、类型检查、Lint、生产构建；静态搜索金额渲染残留和未使用权限常量。
- 执行秘密、注入、路径、下载、日志和依赖安全检查。

对应验收：A07。

### P08：备份、发布、线上烟囱与回滚准备

目标：在不改业务数据的前提下安全发布权限和序列化改造。

工作内容：

- 发布前记录当前提交、数据库版本、服务状态和回滚点。
- 备份数据库和权限关联表；新增权限 seed 采用幂等操作。
- 发布后验证服务健康、迁移状态、登录、角色权限、三类任务接口和前端静态资源。
- 用隔离测试账号验证六个角色：执行角色响应无金额，销售/财务/管理员按权限可见。
- 发布失败时优先回滚代码和前端资源；不执行未经批准的业务数据删除或批量改写。

对应验收：A08。

## 4. 推荐实施顺序

```text
P01
 |
 v
P02 -> P03 -> P04 -> P05 -> P06 -> P07 -> P08
```

P04 和 P05 共享 P02/P03 的策略和角色基线；P06 必须等后端响应契约确定后实施，避免前端依赖尚未稳定的字段。

## 5. 回滚策略

- 若只新增权限记录：回滚应用代码后保留权限记录，不影响历史业务数据；恢复旧代码前确认旧代码忽略新增权限码。
- 若发现响应字段误删：优先恢复到发布前提交，重新构建前端，不直接修改订单数据。
- 若角色 seed 异常：从备份恢复权限关联前先核对内置角色与自定义角色清单；不使用全库恢复覆盖业务表。
- 若服务启动失败：停止继续发布，保留发布前备份和提交，恢复上一个已验证的应用版本。

## 6. 发布前必须获得的确认

1. 是否按“执行角色与销售/财务角色不能同账号并存”的强规则执行。
2. 销售角色是否需要查看产品/材质/工艺的目录价格；默认按“只读必要价格”处理。
3. 任务人员是否需要查看订单附件中的报价 PDF；默认一律不允许下载含价格文件。

若用户未另行指定，实施阶段按以上三个默认值执行。
