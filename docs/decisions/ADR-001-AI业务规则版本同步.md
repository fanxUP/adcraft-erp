# ADR-001：AI 业务规则版本同步

## 状态

已采纳

## 日期

2026-07-29

## 背景

AI 助手同时依赖业务状态机、操作规则和页面上下文。若业务流程调整后只修改业务代码，历史 AI 规则可能继续提供已经失效的操作建议。

## 决策

采用“源码为唯一事实来源、数据库保存发布版本”的双层结构：

1. `app.domain.workflows` 维护业务状态机，AI 规则目录直接从该模块生成。
2. 每条规则使用稳定 `rule_key` 和 SHA-256 内容指纹识别变更。
3. 服务启动时同步规则：
   - 新规则创建版本 1；
   - 内容变化时旧版本标记为 `superseded`，新版本号加 1；
   - 源码中删除的规则标记为 `retired`，不物理删除历史；
   - 未变化的规则不创建重复版本。
4. 生产环境同步失败时阻止服务启动，避免带着旧规则继续提供 AI 引导。
5. AI 对话读取数据库当前 `active` 版本。运行时发现数据库与源码不一致时，立即使用当前源码规则，不读取旧数据库规则。
6. 每次同步写入追加式审计日志，管理员可通过状态接口检查漂移并手动同步。
7. `app.ai_assistant.contracts.page_capabilities.json` 维护 AI 可定位的前端路由、业务类型和 `data-ai-target` 控件标记：
   - 后端生成引导时校验 `target_key` 与 `target_path`，未登记或路径不匹配时拒绝返回错误引导；
   - 前端 CI 运行 `npm run check:ai-contract`，路由、页面文件或控件标记缺失时阻止合并；
   - 完整页面能力清单以 `contract.page_capabilities` 规则进入版本库，能力变更会触发数据库新版本。
8. 页面能力契约同时登记页面用途和每个操作的业务语义：
   - 操作用途、前置条件、完成标志和阻塞条件；
   - `read/write` 影响分类；
   - 按路由登记的 RBAC 权限码；
   - 所有写操作必须声明 `requires_confirmation=true`。
9. AI 只把当前页面和当前业务类型相关的操作语义加入提示词，避免无关页面规则占用上下文。
10. 管理员通过“系统管理 → AI 业务知识健康”查看契约版本、语义覆盖、权限异常、待新增/停用控件和最近同步历史。

## 开发约束

后续新增、调整或删除业务状态时，必须先修改 `app.domain.workflows`。非状态机类操作规则必须登记到 `business_rules/catalog.py`，不得只修改提示词中的自然语言描述。

后续新增、移动或删除 AI 引导按钮时，必须同步修改页面能力契约：

1. 在 Vue 页面保留稳定的 `data-ai-target` 或 `data-ai-targets`；
2. 在 `page_capabilities.json` 登记对应路由名、路径和控件文件；
3. 为控件登记完整操作语义及每个路由所需的现有 RBAC 权限码；
4. 写操作必须要求人工确认，只读预览必须明确标记为 `read`；
5. 后端指导动作只能返回契约中存在的 `target_key`；
6. 本地先运行 `npm run check:ai-contract`，再执行前后端完整测试。

发布顺序固定为：

1. 执行 Alembic 数据库迁移；
2. 启动后端，由启动钩子同步规则；
3. 检查 `/api/v1/ai-assistant/business-rules/status` 返回 `in_sync=true`；
4. 再开放 AI 助手流量。

## 后果

- AI 规则变动可审计、可追溯、可识别删除。
- 业务状态机变化会自动生成新的数据库版本。
- 页面路由或控件变化也会进入规则版本摘要，并由 CI 阻止失效引导上线。
- 页面说明、权限码、操作语义和确认策略发生漂移时，CI 会阻止上线。
- 管理员无需查看数据库即可判断 AI 业务知识是否与代码同步。
- 历史规则仍可用于排查，但不会进入当前 AI 提示词。
- 新增 AI 可定位控件需要显式登记契约，增加少量维护成本，但避免隐式字符串长期漂移。
